# Cache Eviction Policy · Minimize Miss Rate on Synthetic Traces

## Problem Background

You implement a **fixed-capacity cache** that must serve `get(key) -> value | None`
operations under a synthetic workload trace. When a `put(key, value)` brings the
cache over capacity, you must **evict** some existing entry to make room. The
goal is to **minimize miss rate** (fraction of `get` ops that return `None`).

Three policies are in scope:
- **FIFO**: evict the oldest-inserted entry.
- **LRU**: evict the least-recently-used entry (read or write counts as use).
- **TinyLFU / SLRU / ARC (reference)**: more sophisticated adaptive policies
  that resist scan patterns and adapt to workload phase changes.

Your goal: produce an eviction policy that **minimizes total misses** on the
bundled synthetic traces (mix of LRU-friendly + scan-heavy + looping).

## What You Must Implement

Edit `baseline/init.py`. It must keep exposing exactly this interface:

```python
def run_cache(instance: dict) -> dict:
    """
    instance = {
      "name": str,
      "capacity": int,
      "ops": [("get", key) | ("put", key, value), ...]   # in order
    }
    returns = {
      "misses": int,                # total get() ops that returned None
      "miss_rate": float,           # misses / total_gets
    }
    """
```

The current implementation is **FIFO**. Improve it (LRU, TinyLFU, ARC, adaptive
sliding window, scan-resistant Bloom-filter admission — your choice).

## Hard Constraints (violations ⇒ score = 0)

- Pure **Python 3 standard library only** — no third-party imports in `baseline/init.py`.
- Deterministic output: same trace ⇒ same misses.
- Preserve the `run_cache` signature and return-dict fields exactly.
- Per-instance time budget: **30 seconds** on the evaluation machine.
- Do not read, modify, or monkey-patch anything under `verification/`, `data/`,

## How Your Score Is Computed

```
score_i = min(100.0, 100.0 * (1 - miss_rate_you / miss_rate_FIFO))
combined_score = mean(score_i)
```

Higher is better. The FIFO baseline typically scores 0 (it IS FIFO).
The ARC reference typically scores ~80-95 (huge miss-rate reduction).
GPT5.5 N=3 should land Medium-Hard if it implements proper LRU or ARC.

## Notes

The traces are synthetic, deterministic, generated by a fixed seed.
They include a mix of:
  - Looping access patterns (LRU-friendly)
  - Scan patterns (resist LRU; TinyLFU/ARC win)
  - Phase shifts (ARC adapts faster than LRU)
