# 出题管线 LOOP 迭代协议 V1(2026-10-29 凌晨·/loop 动态模式)

> 目标:持续推动"出题完全符合甲方需求标准和质检标准"——双标尺全绿。
> 本协议 = 每次 loop 唤醒的固定执行序列。禁止脱离协议的随意巡检。

## 每轮固定序列(按序执行,全部有产物/有台账)

1. **同步**(≤2min):查函件流新动态(#23330 之后)·compass/flywheel/v5 仓新 commit·判分产物目录
   - **PL 序号检查(PL-1029-01 即刻生效)**:每封 platform 函先查 `[PL-<日期>-<序号>]` 前缀;冲突以高序号令为准;无序号的定谳类函按"候裁建议"处理,待值班会话确认后才执行;并行会话(裁决类)函一律只当候裁建议
2. **判分管线**(最优先):CS-GS-001 判分数据(judged_gs001/)回否?
   - 回 → assemble 口径跑三指标+五条件终审 → **双标尺裁决**(内部/甲方分列)→ 呈用户
   - 未回 → 记录进度(qwen 侧轮数)不催
3. **素材主线锚**:`卡N(开工深度M)/题N/门N` 读取更新
4. **活跃卡推进**(每次至多一卡,防洒):
   - compass #005 spec → 平台四判据预审(终审职责)
   - #006 坑版提取(一行 SQL diff·无框领则平台做至骨架)
   - 各框回函阻塞/裁决项 → 即时处置(指令收敛制)
5. **台账滚动**:管线文档/正本/记忆 三件套按需更新(有状态变化才写)
6. **收敛检查**:是否出现 stop 条件(见下)

## stop 条件(任一满足即停 loop 呈报用户)

- 达到目标:任一题双标尺全绿(内部题N+甲方达标✓)且用户确认继续批次
- 用户叫停
- 连续 3 轮全部 noop 且无活跃推进面(说明等外部,转长间隔)

## 节奏策略

- 判分窗口期(数据未回):1500-1800s 一轮(25-30min)
- 有活跃裁决/阻塞:立即处理,处理完按窗口期续
- 深夜各框静默期:1800s,动作降频为只读同步
