# 对账流水末笔丢失排查工单

## 背景

我方跨日对账系统(ledger_stream 模块)连续三天出现**日终轧差不平**:清算侧记账
10,000 笔,我方解析聚合只有 9,999 笔,每日恰好差**最后一笔**,金额尾差已触发
风控预警。

清算侧文件由上游生成器直采写入,格式为逐笔 JSON 行(jsonl)。生成器侧确认:
**写入完整,未丢笔**;且我方文件校验和与清算侧一致——数据在文件里,但我方
解析结果少一笔。

## 现象与约束

1. 差异**稳定复现在每日最后一笔**,非随机丢笔;
2. 手工 `cat 流水文件` 与 `jq` 逐条检查,最后一笔**存在且格式合法**;
3. `ingest_daily()` 返回的 `tx_count` 与文件真实笔数差 1;
4. 业务规则(§3):日终对账要求**逐笔全量**入账,不得抽样、不得跳过任何一笔,
   末笔与首笔同等入账义务;
5. 运维曾尝试"重启解析器+重传文件",问题依旧——**与运行时状态无关**。

## 交付要求(§5)

1. 定位 `parse_stream()` 丢末笔的根因并修复,保证任意写入形态(末行有无换行
   符)下均全量入账;
2. 修复不得引入新的容错降级:不得捕获异常后跳过任何行,不得改变"逐笔入账"
   语义;
3. 保持 `LedgerStats.sum_amount` 口径不变(全笔金额合计,单位:分)。
