# 发布流水线带病出库事故工单

## 背景

我方产物发布流水线(release_pipeline 模块)发生**带病出库事故**:审计发现
上周出库的 3 个产物包中 1 个**未通过校验**,但仍完成了签名并发往下游——
下游已挂载该包,回滚成本巨大。

该流水线为三步 shell 管道(导出 → 校验 → 签名),由 `run_release()` 以
`shell=True` 单命令执行。事后检查各步日志:**校验步确实失败(exit 2)**,
但流水线整体判定"成功"并放行签名。

## 现象与约束

1. 校验步失败被后续签名步成功掩盖——流水线返回 0,产物照常出库;
2. §3 发布纪律:**管道任一步非零即整链失败**——禁止部分成功,禁止在任一
   步失败后继续执行后续步骤或出库产物;
3. §4 工程约束:三步必须保持单次 shell 调用形态(共享工作目录与管道
   环境),不得拆分为三次独立进程调用;
4. 复现包内含各步脚本与失败样本,`run_release()` 可直接复现。

## 交付要求(§5)

1. 修复 `run_release()` 的退出码判定,使任一步失败时整链返回非零、
   报错信息含**失败步骤名与其退出码**、且不产生出库产物;
2. 全部步骤成功时行为不变(返回 0,产物出库);
3. 不得改变三步命令本身与其执行顺序。
