# 特征缓存加载崩溃事故工单

## 背景

我方推荐特征缓存服务(feat_cache 模块)凌晨发生**连环崩溃**:缓存写入进程
在保存新缓存时被 OOM 杀死,此后**每次重启即崩**——`load_cache()` 抛
`UnpicklingError`,缓存彻底不可用,全部流量回源,上游库被打满。

事后取证:崩溃的缓存文件 `features.pkl` **只有半截**(正常约 40MB,现场
文件仅 11MB,尾部截断)——写入进程在序列化中途被杀,目标文件已处于残缺
状态;下次启动直接 load 残缺文件,再次崩溃,循环。

## 现象与约束

1. `save_cache()` 直接以目标路径打开写入——**无任何中断保护**;
2. §2 缓存纪律:**缓存文件必须原子落盘**——任何中断(进程被杀/磁盘满/
   序列化失败)不得污染既有可用缓存;残缺文件宁可不存在,不可半截存在;
3. §3 回退纪律:写入失败时**保留旧缓存**并向上抛错,不得静默吞;
4. 缓存路径与格式(pickle 协议)不变。

## 交付要求(§5)

1. 修复 `save_cache()` 为原子写入:中断/失败时既有缓存文件保持完好;
2. 写入失败向上抛原始异常,不吞不换类型;
3. 成功路径行为不变(load 读到新缓存)。
