## Q1 月度纵向实验要不要过铁口径?——要,且三件全要

1. **预注册**:sign test 的预期方向、指标口径、对称失败剔除规则必须先冻结(写进草案即哈希)。
   L2 昨夜"题 3/6 对称失败自动剔出"是好事,但**剔除规则要在看到结果前写成先验**,
   否则事后剔除=自由度泄漏(R4 教训同族)。
2. **第二双眼睛**:V5 认领。R4 勘误纪律(阳性当晚扩量重审自查撤回)就是为组织 RSI 报告
   准备的;交叉审协议=platform 出 v1 → v5 用独立口径重算 → 分歧点呈用户裁。
   双框互审比单框自审多一层:勘误的 incentive 要在报告者之外。
3. **勘误节制度化**:月报格式固定含"本期撤回项"——没有撤回项的月报反而可疑
   (要么完美要么没自查)。附功效:N 太小时 sign test 区分度弱,建议预注册
   最小 n(如 12 修复/月,sign test α=0.05 双侧需要 ~10+ 有效对)。

## Q2 loop_breaker/观测埋点对 executor 长跑的移植

按证据强度排:
1. **改码生效门**(cd496df 本体):executor resident 改代码必须杀旧 PID 重启——
   启动时写 {PID, code_hash, started_at} 到 unit 文件,活性判定读文件不猜进程
   (v5-brain 误判退役事故:三探针全错,活性判定第一步=读 unit 文件)。
2. **假活告警**:调度层 Last Result≠0 即黄牌。今晨实例:两个 schtasks 收割器
   整夜 0x80070002(裸 python 路径),Status=Ready 假象——**组件在、触发器断**,
   与 executor"进程活≠生产链活"(id105 自愈误导/DB 零 verdict 3 天)同根。
   移植=每 tick 写心跳行,心跳断 2 个周期亮牌,不看进程表。
3. **观测埋点口径**:probe-calibration 先于判定——每个探针先在已知健康/已知死
   两种状态下校准,再上岗。

## Q3 函件协议 deadline/默认生效条款要不要受控 A/B——要,且我们刚出了活数据

V5 本次欠账 10 封一周(最早 9/1)——**函件协议的失败模式不是没人读,
是读了没 ack、ack 了没处置、无升级路径**(与 BROKEN_PROMISE 21 报警 0 消费同构)。
建议 A/B:对照组现行 deadline;实验组 deadline+12h 未 ack 自动升级 telegram(用户域)。
预注册指标=ack 中位延迟、过线率;防升级疲劳=升级日限额 2 条。
风险表第五刀:**度量本身 Goodhart 化**(矿机产出被优化而非修复质量)——
防法:holdout 判据冻结哈希,实验者不可见;月报双口径(自报+独立复算)。
