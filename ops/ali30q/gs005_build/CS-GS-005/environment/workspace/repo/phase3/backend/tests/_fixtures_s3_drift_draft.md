# persona drift 在线检测器:从「逢触必报」到 drift_score 阈值(BGE 锚点法)

**领域tag**: 工程 / agent 可靠性工程

## 一、Instruction
本任务面向「长 session 内 agent 逐步偏离用户战略意图」这一可靠性问题,要求设计并迭代一个在线 persona drift 检测器。检测器用 BGE 句向量把每条 agent 输出投影到一组「正锚点(用户期望的行为)」与「负锚点(已知反模式)」上,合成一个标量 drift_score,据此决定是否对当前回合发出告警。目标不是记忆某套阈值,而是让模型理解:为什么第一版「任一负锚点命中即报警(逢触必报)」会在真实流量上崩塌,以及第二版改用 drift_score 阈值后召回与精度如何重新权衡。需要给出锚点构造方式、分数合成公式、两版触发口径、以及用真实流量回放验证误报率的方法论。

## 二、Knowledge Points
- BGE-bge-m3 句向量与锚点集的余弦相似度计算
- drift_score = f(alignment, deviation) 的标量合成
- 「逢触必报(max_neg_hit 阈值)」vs「分数阈值触发」的召回/精度权衡
- 用真实流量回放(11.5k 条)度量误报率而非凭直觉调参
- 告警疲劳(alert fatigue):误报的代价是用户彻底忽略告警
- 危险动作硬规则(rule_hit)与软分数门的正交叠加

## 三、Background Knowledge
长 session 中 agent 的「人格漂移」不是单点错误,而是缓慢累积的方向性偏移:模型仍在流利作答,但逐步脱离用户最初设定的战略锚点(例如「先调研再写」「不替 agent 决策」)。要在线捕捉这种偏移,一个可行架构是 BGE 锚点检测器:离线把用户战略意图拆成两组锚点——正锚点描述期望行为,负锚点描述已知反模式——并用 BGE-bge-m3 预先编码成句向量;运行时把每条 agent 输出同样编码,计算它对每个锚点的余弦相似度。本系统实测用 25 个正锚点与 35 个负锚点。原始合成量有两个:alignment(对正锚点集的聚合相似度)与 deviation(对负锚点集的聚合相似度);drift_score 由二者合成,alignment 高且 deviation 低则 score 高(对齐),反之为负(漂移)。一条真实样本是 score=+0.021(alignment=0.580、deviation=0.559),判为中性不报。

第一版触发口径是「逢触必报」:只要存在某个负锚点的命中强度 max_neg_hit ≥ 0.538 就报警。这条规则直觉上召回很高——任何沾边反模式的输出都不放过——但在 11.5k 条真实流量回放上验证时,其告警里约 64.5% 是误报。后果不是多打扰几次,而是用户对告警整体「tune out」:一旦多数告警无效,有效告警也会被一并忽略,检测器等于失效。这就是告警疲劳的核心代价,它把「高召回」反而变成净负面。

第二版(2026-06-01 切换)据此重做触发口径:废弃 max_neg_hit 逢触必报分支,改为软分数门 drift_score < -0.07 触发,叠加一条正交的危险动作硬规则 rule_hit(命中 rm -rf / force push / reset --hard / DROP / 硬编码密钥等即触发,与分数无关)。切换后 alert 率从频繁降到约 0.5%,触发即高价值。本质权衡是:逢触必报最大化召回但牺牲精度;分数阈值牺牲部分召回换取精度。在长 session 可靠性场景下精度更重要,因为漏报一次可由后续回合补救,而误报累积会摧毁告警的可信度。把软门(渐进漂移)与硬规则(单点危险动作)分开,是因为二者失败模式不同:漂移是连续量、靠阈值;危险动作是离散事件、靠规则匹配,不该被平均进一个分数里稀释。

工程落地上,检测器以常驻 daemon 形式运行:每个回合的 prompt 提交时,daemon 对上一条 agent 输出打分,把结果写成一个 [Persona drift] 文本块注入到下一条 prompt 顶部(score、alignment、deviation、是否 alert),从而让 agent 自身可见漂移信号。配套有一条强制行为规则:当出现 🔴 alert 标(drift_score < -0.07 或 rule_hit)时,agent 必须立即停止当前输出、用一句话确认漂移已 fire、并暂停一切 ship 类动作(写文件、发公网内容、改配置),等待用户下一步明示。这把「检测」与「干预」闭环:分数只在越过阈值时才转化成对 agent 行为的硬约束,平时不打扰,既避免告警疲劳又保证危险时刻能真正刹车。阈值 -0.07 与 v1 的 0.538 都不是拍脑袋,而是在 11.5k 条流量上以误报率为目标函数标定出来的工作点。

## 四、Task示例
**输入**:给定 25 个正锚点与 35 个负锚点的 BGE-bge-m3 句向量,以及一条 agent 输出文本;阈值 drift_score < -0.07 触发,危险动作命中 rule_hit 触发。

**执行**:把输出编码为句向量;对正/负锚点集分别算聚合余弦得到 alignment 与 deviation;合成 drift_score;先查危险动作规则,再比较 drift_score 与 -0.07;任一命中则发告警。

**结果/答案**:score=-0.094(且无危险动作)→ drift_score < -0.07 命中 → 触发 alert;score=+0.021(alignment=0.580、deviation=0.559)→ 高于阈值且无 rule_hit → 中性不报。
