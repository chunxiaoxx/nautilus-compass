# 三期工作流（非技术同学版）

一句话目标:  
一条任务从“立项”到“可交付、可结算”都在一个 `task_uid` 下走完；系统按固定节拍自动推进，团队只做两类人工确认。

## 谁该做什么

- 你（运营/负责人）  
  - 在派活表建任务，填清楚题目、验收标准、负责人、业务线。  
- 专家  
  - 只填自己的“交互/稿件”内容。  
  - 改好后把状态改成“已提交”。  
- QC  
  - 看稿子是否达标，给具体修改点。  
  - 合格就改成“已通过”；不合格就“已打回”。  
- 平台  
  - 通过自动化把“通过稿”推到交付和结算表。  
  - 外部验收通过后才算最终可计入收入。

## 一条任务的 6 个动作

1. **新任务上架**  
   在派活表点“待派单”并填 `task_uid`、`标题`、`验收标准`、`L级`、`业务线`。
2. **系统派给专家**  
   自动派发后，行状态变 `已派单`。  
3. **专家交稿**  
   专家在提交处粘贴稿件，填状态 `已提交`。  
4. **QC 回审**  
   QC 打分，合格转 `已通过`，不合格回 `已打回` 并写明修改点。  
5. **系统生成交付**  
   交付 runner 读取 `已通过` 行，生成交付记录和结算草稿。  
6. **外部验收闭环**  
    外部验收通过并标记后，系统写入最终收入入口，状态才算闭环。

## 人机分工（默认执行）

- 自动链路：S1、S2、S3 由常驻任务持续运行。  
- 人工仅介入两类节点：  
  - S1：补齐字段、确认 `task_uid` 唯一，不让任务空派。  
  - 待处理池：先处理 `pending` 提示后再让流程继续。

## 你每天只要看这 3 个问题

- 今天有多少单 `待派单` 还没被推进？  
- 今天有多少 `已提交` 没有 `已通过/已打回`？  
- `已通过` 中有多少还没形成交付表？  

## 常见异常你应该这样处理

- 很多人不改：先看有没有 `验收标准`，再看 `task_uid` 是否唯一。  
- 内容反复被打回：让 QC 在反馈里写 3 条以上可落地点。  
- 交付没出现：优先查 `verdict` 是否过了 `overall_pass`，再查交付表是否有权限。  
- 状态乱跳：把异常行恢复到上一步状态，并标注原因，不要手工跨步修改太多字段。

## 你可以直接抄的沟通话术

- “本条任务已打回：请按 QC 逐条改稿并把状态改回已提交”。
- “本条任务已通过，等待外部验收后自动入账”。
- “外部验收未通过，等待同一 task 的重提或复检”。

## 外部专家入群公告模板（可直接复制）

【FDE 三期出题/交互接单说明】

1) 每单只看 `task_uid`，不要改别的单。  
2) 找到对应行，状态要求：  
   - 待派单：只用作发起，不改稿。  
   - 已派单：可领取并开始写稿。  
   - 已提交：提交后请保持字段完整。  
3) 交稿动作：  
   - 在提交内容里粘贴正文。  
   - 将该行状态改为 `已提交`。  
4) 收到 QC 反馈：  
   - 只改正文，改完改回 `已提交`，不要改验收标准。  
5) 不要执行脚本，不要跨页重复粘贴正文。  
6) 若不确定，按 `task_uid` 提醒运营或 PM 处理，避免自行更改状态。

群发版本（短）：  
“收到 S2 任务后只按对应 task_uid 写稿并改为已提交，QC 反馈只改稿后再改回已提交，字段有问题请发我 task_uid 处理。”

## 外部专家首日打卡清单（3 问 1 答）

- Q1：我拿到的是什么单？（30 秒）
  - 看 `task_uid`、`状态`、`提交内容`、`QC反馈` 四个字段。

- Q2：我现在该做什么？（5 分钟）
  - `已派单`：开始写稿并填 `提交内容`，最后改 `已提交`。  
  - `已打回`：按 QC 反馈改稿，再改回 `已提交`。  
  - 不是这两种状态，暂停改动并提 ping 给运营。

- Q3：是否需要人工干预？（30 秒）
  - `已提交` 且无反馈：等系统或 QC 轮询。  
  - 无法提交：补齐提交内容后保存，不要改任务元字段。  
  - 有重复 `task_uid`：停止该行操作，先发起 `task_uid` 核对。

- 今日打卡标准（对外宣言）：
  - 每单只对一个 `task_uid` 操作一次；每次改完都可回到 Q1 自检。

## 5 分钟快速联调（新同事看这个）

1. 运营建单  
   - 在派活表填 `task_uid`、标题、验收标准、业务线、专家身份。
2. 系统派发  
   - 把状态设 `待派单`，5 分钟内看是否进 `已派单`。
3. 专家交稿  
   - 在提交区域填正文并设 `已提交`。
4. QC 判定  
   - 打 QC 反馈，状态改 `已通过` 或 `已打回`。
5. 系统交付  
   - 通过件由系统生成交付/结算记录，外部验收通过后视为闭环。

### 卡住了怎么办

- 不是 `已提交`：先问专家是否按行提交并保存。  
- 有提交无反馈：看状态是否误改，恢复到 `已提交` 再等。  
- `已通过` 但没交付：先查 verdict 是否通过，再查交付表写入权限。  
- 外部验收失败：先停在复检，不要无限次重跑一单。  
- 有 pending 提醒：先按平台建议处理一条后再继续。

## 你不需要做的事

- 不要把正文在多个表里重复粘贴。  
- 不要替专家直接改稿。  
- 不要用口头说明代替表单字段（字段未变更就不算变更）。
- 不要执行脚本或手工批量命令推进流程。
