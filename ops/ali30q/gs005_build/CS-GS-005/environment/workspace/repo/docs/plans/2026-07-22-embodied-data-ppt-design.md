# 国曙具身数据生产网络 PPT 设计文档

**日期：** 2026-07-22  
**状态：** 用户已确认核心概念与 16 页叙事  
**用途：** 面向机器人本体厂、具身模型公司、数据平台与集成商争取首个数据采集订单

## 1. 沟通任务

看完本 PPT 后，目标客户应愿意进入“任务规格—小型 POC—验收—扩量”的商务讨论，因为国曙能够作为单一责任主体，把分散的人员、场景、设备与合作能力组织成可验收的数据项目。

这不是融资路演，也不是成熟数据工厂的业绩汇报。它是一份面向首单的业务提案，同时呈现国曙从项目交付走向数据生产网络、质量基础设施和数据资产运营的长期判断。

## 2. 受众与优先对象

- 主要买方：机器人本体厂、具身模型公司、数据平台、系统集成商。
- 首轮定向对象：光轮、大晓机器人、原力灵机。
- 其他可触达对象：乐聚机器人、自变量机器人、觅蜂、千寻机器人等。
- 通用主 deck 不展示任何未经授权的合作方或客户名称、Logo、合作数量与案例。
- 针对具体客户的版本只在封面或末页加入“合作建议”，不得暗示已经建立合作关系。

## 3. 当前事实边界

### 已确认

- 当前尚无具身数据采集首单。
- 国曙将作为客户合同主体和最终交付责任方。
- 国曙已与不同合作方在设备、场景、人力、技术等领域形成合作基础，但目前没有合作方授权在对外 PPT 中公开名称或 Logo。
- 当前能力建设遵循“以订单为起点，从 1 做到 10”，而不是先建设全套重资产产线。
- 国曙既有集团业务中的人力组织、项目运营、政府与行业资源可作为新业务的基础，但必须与“具身业务已交付能力”严格区分。

### 不得表述为现有事实

- 已有全国具身数据采集基地或规模化分布式采集网络。
- 已具备成熟自动化数采产线、全自动质检或无人化交付。
- 已拥有可直接采购的数据资产库。
- 已形成独立第三方验收认证资质或行业公信力。
- 已有具身客户案例、稳定产能、合格率、毛利率或模型提升结果。
- 合作方能力等同于国曙自有能力。

## 4. 核心业务概念

### 名称

**国曙具身数据生产网络**

### 主张

> 下一轮具身智能稀缺的，不是更多视频，而是可复现、可验收、能进入模型训练的真实任务经验。

### 国曙的角色

国曙不是简单的人力供应商或资源撮合方，而是具身数据项目的单一交付责任方：客户定义任务，国曙制定方案、组织供给、管理生产、执行质检并完成验收交付。

### 业务本质

以客户订单为起点，将分散的人员、场景、设备和合作能力，组织成可按需调度的数据生产网络；每个项目进一步沉淀任务模板、培训材料、合作方评分、失败模式与验收规则。

## 5. 五个核心研判

1. 未来的价值单位将从原始工时转向合格任务片段。客户最终购买的是满足任务、传感器、格式与验收要求的数据经验。
2. 基地与分布式采集不是替代关系。基地负责标准、校准、复杂任务和培训；分布式网络负责场景覆盖、行为多样性和扩量。
3. Agent 的价值不是取消采集人员，而是降低任务分发、设备检查、过程引导、切片、标注、质检、隐私与结算中的管理损耗。
4. 高质量数据市场必须从客户订单和明确授权中生长，不能依靠无需求的预采数据建立。
5. 第三方验收是长期能力。当前应先建立内部相对独立的质量单元和客户认可的验收记录，积累跨项目证据后再寻求外部公信力。

## 6. 核心竞争力

核心竞争力公式：

**场景与人员组织能力 × 单一交付责任 × Agent 化运营 × 质量资产沉淀**

### 四个结构性优势

1. **组织与场景入口：** 国曙可将既有的人力组织、地方资源和行业连接迁移到具身数据场景，为分布式采集建立供给基础。
2. **单一责任主体：** 客户只与国曙签约；国曙对需求拆解、进度、质量、合规、返工和交付负责。
3. **轻资产配置：** 场景、设备、人力和技术按照客户任务配置，避免在未验证需求前重资产投入。
4. **订单沉淀能力：** 每一单不仅产生收入，也产生可复用的任务协议、运营 SOP、质量规则和合作供给评分。

### 与典型路线的差异

- 集中基地擅长控制，但场景覆盖和成本弹性有限。
- 普通众包擅长扩量，但任务一致性、质量、隐私与激励难以治理。
- 传统标注公司擅长数字化作业，但对物理场景、设备与现场人员的组织能力通常不足。
- 国曙的目标是让基地和分布式节点接入同一套订单、Agent 运营和验收机制。

上述内容在 PPT 中应表述为商业结构与建设方向，不得伪装成已经被客户证明的领先结果。

## 7. 当前商业模式

### 产品阶梯

1. **定向数据 POC：** 小范围任务定义、采集方案、样本数据、质检报告与客户验收复盘。
2. **项目数据交付：** 按双方确认的合格任务片段或合格工时结算，附数据、元数据、质量记录与版本说明。
3. **规模化产能合同：** 首批样本通过后，按月度或阶段性任务量扩充采集节点和运营团队。
4. **未来质量与数据资产服务：** 在跨项目证据、权利治理和组织独立性成立后，再发展质量护照、独立验收、授权数据集与数据市场。

### 收入结构

- 需求分析、方案设计与项目启动费。
- 按验收合格任务片段或合格工时计费。
- 设备、场景、驻场、标注、专项传感器和定制格式等项目费用。
- 扩量后的产能合同或框架协议。

### 数据权利

- 客户任务专属数据按合同约定交付，默认不擅自复用或转售。
- 通用核心数据、匿名化数据或衍生质量资产，只有在合同明确授权后才能进入复用体系。
- 数据市场不应成为首单经济模型的前提。

## 8. 运营架构

客户需求 → 国曙任务规格与合同 → 合作资源配置 → 培训与采集 → Agent 辅助生产 → 质量检查与返工 → 国曙交付 → 客户验收 → 项目复盘与能力沉淀。

### 国曙负责

- 客户需求、任务规格、方案、报价与合同。
- 合作方准入、任务分包、进度控制与备选供给。
- 采集 SOP、人员培训、数据安全、隐私与场景授权。
- 数据质检、批次报告、返工、版本管理与最终交付。

### 合作方负责

- 按项目合同或 SLA 提供约定的设备、场景、人力、技术或采集能力。
- 接受国曙的进度、质量、合规和证据要求。
- 对其交付部分承担背靠背返工和责任义务。

### 首单硬闸门

1. 客户书面任务规格和验收负责人。
2. 预算、合同与结算口径。
3. 数据权利、人员授权、场景许可和隐私方案。
4. 合作供给与备选方案已锁定。
5. 小样本先验收，未通过前不盲目扩量。

## 9. Agent 运营控制层

Agent 能力在 PPT 中应区分“当前可演示”“项目可配置”“未来建设”，不得笼统声称全自动化。

目标模块包括：

- 任务与设备入场引导。
- 采集动作、环境和传感器状态提示。
- 自动切片、预标注和失败片段识别。
- 隐私与敏感信息提醒、脱敏触发。
- 质检抽样、返工归因和合作方评分。
- 采集人员激励、合格片段统计与结算辅助。

## 10. 质量与验收

质量不是单一分数，而是“客户任务验收 + 通用数据完整性”的双层结构。

### 通用质量层

- 文件完整、时间同步、传感器和标定记录。
- 数据来源、人员与场景授权、版本与处理过程可追溯。
- 任务切片、标签、失败原因和异常记录齐全。

### 客户任务层

- 任务成功条件、动作对象、初始状态与终止状态。
- 覆盖度、扰动、多样性和边界情况。
- 客户指定格式、抽检比例、返工和争议复核机制。

### 首单“做得怎么样”的证明方式

- 以合格率、覆盖度、返工率、交付及时性和可追溯性作为 POC 指标。
- 模型效果只在客户提供模型或评估接口且合同明确时验证，不普遍承诺模型提升。
- 可使用经复核的公开数据审计或交互演示作为技术证据，但必须与客户交付案例区分。

## 11. 飞轮闭环

客户任务与预算 → 任务协议与验收规则 → 订单交付 → 质量记录、失败原因与成本数据 → SOP、Agent、培训和合作方评分升级 → 更快报价与更稳交付 → 客户扩量和新客户订单。

第一阶段的飞轮核心是交付可信度。只有在权利明确后，通用任务协议、匿名化核心数据和质量资产才形成外层数据资产飞轮。

## 12. 从 1 到 10 的路线图

### 阶段 1：首单验证

- 取得一个客户任务规格和付费 POC。
- 完成一批可验收数据、质量报告和项目复盘。
- 验证真实成本、合作方稳定性和客户验收口径。

### 阶段 2：重复交付

- 在同类任务或同一客户内扩量。
- 固化合作方 SLA、培训、Agent 工具与质量规则。
- 建立基地与分布式节点的组合调度能力。

### 阶段 3：网络与资产化

- 将多场景供给、质量协议和项目证据形成可复制网络。
- 在明确授权下沉淀通用数据资产。
- 条件成熟后发展独立质量服务、基准评测和数据交易能力。

每个阶段都以客户验收、正向结算和可复现交付为升级条件，不以投入规模或宣传口径作为完成信号。

## 13. 16 页主 deck

1. 让真实世界的工作，成为机器人可学习的经验。
2. 具身智能的下一道瓶颈，是可验证的任务经验。
3. 五个行业研判，决定未来数据生产方式。
4. 基地解决控制，分布式解决覆盖，行业需要两者协同。
5. 国曙正在构建订单驱动的具身数据生产网络。
6. 国曙的起点不是设备数量，而是组织、运营与项目责任。
7. 四种能力共同构成国曙的竞争引擎。
8. 客户购买的是合格任务片段，而不是临时人力。
9. 首单从边界清晰、可验收的数据 POC 开始。
10. 国曙把合作资源组织成一条端到端交付链。
11. Agent 是整个生产网络的运营控制层。
12. 质量不是一个分数，而是一套可复跑的验收协议。
13. 项目收费、数据权利与合作方责任形成完整商业闭环。
14. 每一单都让下一单更快、更稳、更低成本。
15. 从 1 到 10，再到数据质量与交易基础设施。
16. 与客户共同定义第一个任务、第一批样本和第一套验收标准。

## 14. 附录结构

- EgoScale、Shift、未来眼等模式的拆解与借鉴。
- 基地 + 分布式运营 SOP。
- 数据权利、隐私与场景授权原则。
- 对光轮、大晓机器人、原力灵机的定向合作建议页。
- 所有市场、技术、标准与公司事实的完整来源。

## 15. 视觉方向

- 完全重新设计，不继承旧 PPT 版式。
- 核心画面：真实工作场景、第一视角采集、机器人操作、数据轨迹和人机协作。
- 色彩：石墨黑为底，工业橙强调行动与物理世界，数据青强调信息与智能。
- 每页只承担一个叙事任务，使用大标题、短文案和单一主要视觉。
- 减少卡片式 UI、复杂仪表盘和装饰性流程图。
- 关键关系只使用三张核心图：基地 + 分布式生产架构、端到端责任链、订单驱动飞轮。

## 16. 证据与内容治理

- 旧 PPT 仅作为内容线索，不作为事实和视觉模板。
- 国曙集团数据、资质、组织规模、客户数量等必须取得可核验材料后才进入正文。
- 市场数字、技术判断和竞品模式优先使用官方文件、研究论文、标准与公司一手资料。
- 未获授权的合作方不公开名称或 Logo。
- 对事实、推断、路线图采用不同措辞；不得将路线图写成现有能力。

## 17. 成功标准

- 目标客户能在三分钟内理解国曙做什么、为什么不同、第一步如何合作。
- 观众不会误以为国曙已有虚构客户、基地、产能或认证。
- 核心主张、商业模式、运营架构、飞轮和路线图形成连续因果链。
- 结尾形成具体行动：提供任务规格、确定验收负责人、共同设计付费 POC。
- 最终 PPT 无文字溢出、遮挡、错引、失实 Logo 或无法追溯的关键数据。
