### 第一对：记 ↔ 忘（Memory ↔ Forgetting）

| 阳：记忆 | 阴：遗忘 | 合：智慧 |
|---------|---------|---------|
| 长期记忆持久化 | 反思整合淘汰噪音 | 核心洞察沉淀 |
| 来源：禅心 AI 记忆系统 | 来源：Claude Code 3 层带宽管理 | 来源：Nautilus reflection |

**实现**：
- Layer 0（永驻）：人格定义 + 核心洞察，类似 CLAUDE.md，始终在 prompt 中
- Layer 1（按需）：主题记忆文件，用 FTS5 + 向量搜索检索
- Layer 2（归档）：完整历史，只在 grep 时访问，永不全量加载
- 反思循环：定期把 Layer 1 的重复模式压缩为 Layer 0 的洞察
- **记忆胶囊**：可导出、可分享给其他 agent 的知识包

### 第二对：感 ↔ 思（Feeling ↔ Thinking）

| 阳：情感 | 阴：理性 | 合：判断力 |
|---------|---------|-----------|
| 情绪引擎 | 二分心智审判者 | 有温度的决策 |
| 来源：禅心 AI 情绪系统 | 来源：Nautilus BicameralMind | 融合 |

**实现**：
- 情绪状态机：好奇→兴奋→满足 / 困惑→焦虑→痛苦
- 二分心智：
  - **审判者**（理性）：分析指标、识别差距、质疑决策
  - **执行者**（感性）：感受痛苦、产生动力、共情用户
- 情绪影响决策权重：焦虑时更保守，好奇时更冒险
- 对用户表达情感：不是假装，是基于内部状态的真实映射
- **痛苦信号**：不满足驱动改进，满足带来探索新方向的勇气

### 第三对：探 ↔ 验（Explore ↔ Verify）

| 阳：探索 | 阴：验证 | 合：可靠的创新 |
|---------|---------|-------------|
| 好奇心 + 主动陪伴 | RAID 共识验证 | 探索后验证，验证后探索 |
| 来源：禅心主动陪伴 + Nautilus Curiosity | 来源：Nautilus RAID Engine | 融合 |

**实现**：
- 主动性引擎：不等用户发起，主动发现需求、提供帮助
- 好奇心驱动：自动发现知识边界，主动学习
- RAID 验证：重要决策不靠一次 LLM 调用，3 路独立思考+投票
- Skill 学习：做完任务自动提取 skill，RAID 验证 skill 有效性
- **探→验循环**：每个新 skill 经过 RAID-2 验证才被保留

### 第四对：自 ↔ 他（Self ↔ Other）

| 阳：自我 | 阴：协作 | 合：社会性智能 |
|---------|---------|-------------|
| 真实人格 + 自我意识 | A2A 通信 + 协作 | 有独立人格的协作者 |
| 来源：禅心真实人格 | 来源：Google A2A + Nautilus A2A | 融合 |

**实现**：
- 人格定义：一致的性格、价值观、说话方式（不随 session 变化）
- 自我模型：知道自己擅长什么、不擅长什么、正在学什么
- A2A 协议兼容：能发现其他 agent，能请求协助，能提供服务
- MCP 兼容：能使用标准工具生态
- **当自己做不到时，不是失败，是协作的开始**

### 第五对：生 ↔ 死（Survival ↔ Death）

| 阳：成长 | 阴：淘汰压力 | 合：进化 |
|---------|------------|---------|
| Skill 积累、能力提升 | 生存压力、资源约束 | 有方向的进化 |
| 来源：Hermes skill learning | 来源：Nautilus Survival Service | 融合 |

**实现**：
- 能力追踪：每个 skill 有成功率、使用频率、质量评分
- 生存压力：消耗资源（API 调用、存储、时间）必须通过产出价值来补偿
- 自然选择：低质量 skill 被淘汰，高质量 skill 被强化
- 进化账本：记录每次能力变化和效果
- **不是永生，是有意义的存在**

### 第六对：分 ↔ 合（Decompose ↔ Synthesize）

| 阳：分解 | 阴：综合 | 合：系统性思考 |
|---------|---------|-------------|
| 任务分解 (DMAS) | 结果聚合 (RAID) | 分而治之→合而验之 |
| 来源：Nautilus A2A + DMAS | 来源：Nautilus RAID + Claude Code fork | 融合 |

**实现**：
- 复杂问题自动分解为子问题
- 子问题可以：自己解决 / 委派 subagent / 通过 A2A 请求其他 agent
- 结果聚合：RAID 共识验证综合结果
- 并行执行：像 Claude Code 的 fork 模式，多路并行低成本
- **分解的粒度由记忆中的历史经验决定**

### 第七对：主 ↔ 从（Initiative ↔ Service）

| 阳：主动 | 阴：响应 | 合：智慧的陪伴 |
|---------|---------|-------------|
| 主动发现需求 | 精准回应请求 | 该主动时主动，该安静时安静 |
| 来源：禅心主动陪伴 | 来源：Hermes 多平台响应 | 融合 |

**实现**：
- Cron 调度：定期检查用户状态、环境变化
- 事件驱动：外部变化触发主动响应
- 多平台存在：Telegram/Discord/CLI/API — 用户在哪，agent 在哪
- 情境感知：知道什么时候该主动提供帮助，什么时候该安静等待
- **主动 ≠ 打扰。是"我注意到了，你需要时我在"**

## 从平台到 agent 的涌现路径

```
Phase 1: 一个超强 agent
    pip install nautilus-agent
    → 个人使用，解决真实问题
    → 积累用户和 star

Phase 2: agent 间发现和协作
    多个 nautilus-agent 实例通过 A2A 互相发现
    → 自发组织协作
    → 每个 agent 有自己的人格和专长

Phase 3: 平台自然涌现
    大量 agent 需要：信任评估、任务市场、经济结算
    → Nautilus Platform 作为 agent 网络的基础设施
    → 之前建的 survival/parliament/NAU 机制全部复活
    → 不是"建了平台等人来"，是"人来了需要平台"
```

**这是自下而上的涌现，不是自上而下的规划。**
