# 生产管道组织接入方案 V1(2026-10-28 凌晨)

> 前提:flywheel L3 管道已验真(Mac nautilusflywheel 仓,CS-517 首件实证);缺口=UT 校验失灵+产物未同步 NAS。
> 原则:**管道管速度,闸门管质量,第三方管公信**——三权分立,缺一不可。

## 一、分工重构(管道接入后)

| 角色 | 原 | 接入后 |
|---|---|---|
| **spec 作者** | — | **v5**(骨架库 24 条+39 事故→spec JSON,质量源=人的真实经验)|
| **编译/跑分/判定/调档** | 手工 | **flywheel 管道**(一命令全自动,速度源=机器) |
| **独立判据** | compass | **不变**——管道自判只作快筛预判,闸门判定仍 compass 独立复算(防自评作弊=组织差异化根基) |
| **闸门裁决+台账** | 平台 | **不变**——四闸门+追溯矩阵,管道产出件照走全闸 |

## 二、流水(14 件缺口 8 件的主产线)

```
v5 出 spec(骨架库逐条,每条一份 spec JSON)
  → flywheel end_to_end.py --spec --rounds 1(快筛:五模型×1轮+三判据秒出)
    → 过筛件:--rounds 4 满窗 → 校准四件套(compass 独立复算)→ 打包闸
    → 淘汰件:调档器旋钮方向 → spec 修订 → 循环(上限 3 轮,防渠道费烧穿)
```

效率账:手工环(出题→判分→IRT→返修)2-6h/轮 → 管道环分钟-小时/轮;A01 手工流水线与管道双线并行(A01 出事故卡的,管道出 spec 化的)。

## 三、前置件(flywheel 今晚/明晨)

1. **UT 校验修复**:编译器"≥21UT 自动校验"没拦住 CS-517 的 19 条——修校验逻辑(产出 <21 即拒出)
2. **产物同步 NAS**:管道产物自动落 NAS shared/(提交链+平台抽验可达)
3. **循环上限**:调档循环 ≤3 轮(防 token 烧穿——F-005 同族教训)

## 四、平台配套

- **管道台账**:spec→产物→闸门状态逐件追踪(并入排产台账)
- **渠道费护栏**:夜间判分错峰+循环上限
- **抽验制**:管道产物每日抽验一件(frame_snapshot 附带)——防"管道剧场化"复发
