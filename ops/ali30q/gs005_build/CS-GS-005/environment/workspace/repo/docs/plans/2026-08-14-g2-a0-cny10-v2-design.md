# G2-A0 CNY 10 V2 Contract Design

**Date:** 2026-08-14
**Status:** Approved for bounded implementation
**Authority baseline:** `af4bf6572ae05fb7f49d3e2ff31e734205b8e976`

## Objective

Define and implement an additive, test-only G2-A0 V2 contract that permits one
DeepSeek `deepseek-v4-flash-0731` completion with an exact maximum cost of CNY
10. V2 must remain inert in this task: no provider request, network access, API
key read, paid probe, database, deployment, push, or merge is authorized.

V1 remains authoritative for its original CNY 5 contract and must not be
modified. V2 is a new versioned contract, not a mutable interpretation of V1.

## Decisions

### 1. Additive versioning

V2 introduces distinct version identifiers and an authorization marker:

- policy: `g2-a0-model-gate-policy-v2`
- request: `g2-a0-model-gate-request-v2`
- evidence: `g2-a0-model-gate-evidence-v2`
- paid-run marker: `authorize-g2-a0-one-call-max-cny-10-v2`

V1 bytes, constants, parsers, marker, tests, and behavior are frozen. V1 and V2
objects are not interchangeable at an execution boundary. A V1 marker cannot
authorize V2 and a V2 marker cannot authorize V1.

### 2. Fixed policy, not caller-selected budget

The V2 policy fixes `max_cost_micros_cny` to `10_000_000`. It is not a request
parameter and cannot be lowered or raised by a caller. All other approved G2-A0
constraints remain fixed:

- exact model `deepseek-v4-flash-0731`
- thinking enabled at the approved reasoning setting
- one provider call at most
- zero retries and no fallback
- streaming disabled
- fixed endpoint allowlist
- fixed synthetic fixture, prompt, schema, and verifier bindings

The parser rejects unknown or missing fields, duplicate JSON keys, booleans in
integer fields, malformed hashes, non-canonical values, and mixed V1/V2 data.

### 3. Three independent cost gates

The CNY 10 ceiling is enforced at three points:

1. before transport from the fixed V2 policy;
2. after the provider response from provider-reported cost;
3. after the request from the independently observed balance delta.

Missing, malformed, negative, or over-limit cost evidence is fail-closed. An
inconclusive or rejected result never authorizes a second call.

### 4. Reuse without weakening V1

V2 may reuse proven V1 canonical JSON, strict parsing, synthetic fixture,
transport, verifier, replay, and evidence helpers by composition or narrow
subclassing. The V2 entry point must nevertheless require V2 request and policy
types and emit V2 evidence. Reuse does not authorize edits to V1 source files.

The test-only runner continues to use injected HTTPX transports. Tests use only
`MockTransport` plus a socket-deny guard. Production credentials are neither
needed nor read. No new dependency is introduced.

### 5. Determinism and replay

An identical authenticated request returns the original terminal result and
does not increase provider-call count. A changed request under the same replay
identity conflicts before any balance lookup or transport call. Cross-version
replay is rejected.

Evidence contains only fixed protocol values, hashes, bounded numeric counters,
and fixed decisions/reasons. It excludes API keys, authorization headers, raw
prompts, raw responses, reasoning text, patch text, paths, balance values, and
free-form error text.

## File boundary

The implementation is limited to new files:

- `phase3/backend/platform_protocol/g2_a0_model_gate_v2.py`
- `phase3/backend/tests/platform_protocol/g2_a0_model_gate_v2_cli.py`
- `phase3/backend/tests/platform_protocol/test_g2_a0_model_gate_v2_contracts.py`
- `phase3/backend/tests/platform_protocol/test_g2_a0_model_gate_v2_cli.py`
- `phase3/backend/tests/platform_protocol/test_g2_a0_model_gate_v2_fail_closed.py`
- `phase3/backend/platform_protocol/.gitattributes` (narrow LF policy only)
- `phase3/backend/tests/platform_protocol/.gitattributes` (narrow LF policy only)
- this design and its implementation plan

No V1 source, test, evidence, or plan file may change. The two attribute files
may only fix the five inherited, source-bound V1 Python files to `text eol=lf`;
their Git blobs and Python behavior remain unchanged.

## Verification and stop condition

Implementation follows RED to GREEN. Completion requires:

- focused V2 tests;
- the complete existing G2-A0 V1 suite;
- Ruff check and format check;
- compileall;
- source allowlist, secret, network, and paid-call scans;
- Git diff/show checks and exact proof that V1 paths are unchanged;
- an independent read-only review with High=0 and Medium=0;
- a clean isolated worktree after separate commits.

The branch then stops. The paid probe remains a separately authorized future
action; this contract commit does not itself authorize or perform it.
