# 第三期飞书应用与自动化绑定 Runbook

> 本文是受控上线检查单，不包含应用凭证、Base 标识、表单链接、外部专家资料或客户材料。
> 飞书多维表格 read-back 是任务、审核、返修血缘和导出资格的唯一业务权威。任何一项
> 无法 read-back 时，保持对应自动化关闭；聊天截图和 Agent 自报均不能替代验证。

## 目标工作流

外部专家只面对两个公开入口和一个导师续办页：

1. 首次报名填写“第三期专家信息采集（正式）”。
2. 题目阶段填写“第三期题目预审（正式）”。
3. Nautilus 对题目执行自动 P0；只有 Bitable read-back 为 `eligible_for_interaction` 的记录，
   才由智涌导师向该专家会话发放一次性、受认证的交互续办入口。
4. 专家在导师续办页补交豆包办公任务的交互成果。页面只接收使用工具、轮次数、对话图片、
   轨迹链接、日志 ID 和本人确认；题目、专家、关系和状态均由服务端 read-back 后受控写入。
5. Nautilus 执行交互 P0，符合条件的记录才进入甲方同步、反馈、V5 v3 脱敏导出与 Compass
   独立回执链路。

这样保留“先出题、后交互”的质量门槛，同时避免专家在两个公开表单间手工匹配 UID 或题目。

## 五张权威表

| 表 | 作用 | 外部写入方式 |
| --- | --- | --- |
| `第三期专家` | 专家资料、培训和豆包开通状态 | 原生专家信息表单 |
| `第三期题目预审` | 题目、领域、附件、来源、交互思路及题目 P0 | 原生题目预审表单 |
| `第三期交互成果` | 豆包办公任务交互证据及交互 P0 | 仅导师受认证续办页 |
| `第三期审核与反馈` | 自动 P0、买方反馈、`verdict`、反馈类别 | Nautilus 受控写入 |
| `第三期导出与回执` | V5 v3 脱敏导出及 Compass 签名回执 | Nautilus/Compass 受控写入 |

不得再创建混合全流程的任务入口、离线结果表或聊天台账。返修只允许创建后继记录，并以
`revision_of` 连接前序记录；不得覆盖原记录或凭消息文本推断血缘。

## 上线顺序

1. 盘点 Base 元数据，确认默认“数据表”是否为空、未分享且未绑定自动化；仅在满足迁移
   守卫时删除，归档表保留，不作为新入口。
2. 在维护窗口创建或 read-back 五张权威表、字段选项、关系字段及两个原生表单；不要公开
   `第三期交互成果` 的原生表单。
3. 批准字段映射，注入 Nautilus Bitable 仓储、持久幂等存储、事件签名校验、导师会话认证、
   续办存储和任务句柄签发配置。密钥只从受控密钥来源注入。
4. 发布 Nautilus 与智涌导师应用版本，逐项回读权限、事件订阅、机器人、消息卡片和自动化
   扩展绑定。
5. 配置自动化扩展，只投递包含路由、记录版本和事件标识的元数据；先完成不创建业务记录的
   回调挑战测试。
6. 使用一条经授权的脱敏演练记录走通报名、题目 P0、导师续办、交互 P0 和受控回执，再决定
   是否开启 V5/Compass 后段。

未完成前一项，不进入后一项。两个原生表单可作为入口存在，但未完成应用 read-back 前，
不得宣称自动 P0、续办或同步已启用。

## 智涌 Nautilus

Nautilus 是表单初始写入后的唯一业务字段写入应用。上线前在飞书开发者后台逐项核验：

- 已发布版本包含服务端回调、机器人、消息卡片和 Bitable 自动化扩展能力。
- 具备且仅具备五张权威表所需的读写范围；写入字段受已批准字段映射限制。
- 服务端已注入事件签名校验、受控 Bitable 仓储、持久幂等存储、导师投影发布器、受认证
  续办工作流和任务句柄签发密钥；这些配置仅位于受控密钥来源。
- `POST /api/platform/fde/phase3/events` 的 URL 验证能够返回挑战值；未通过签名的请求
  返回认证失败，不解析业务事件。
- 运行日志只保留路由、受控状态、幂等结果和错误类别；不得记录表单正文、附件、个人联系
  方式、客户原文、导师续办凭据或密钥。

题目自动 P0 只能写入 `eligible_for_interaction`、`question_repair_required` 或 `blocked`；
交互自动 P0 才可写入 `buyer_ready`、`repair_required` 或 `blocked`。两者都不能替代买方
`verdict`，也不能依据聊天消息直接改表。

## 智涌导师

导师是外部专家的培训、咨询、状态查询和返修陪跑入口，不拥有 Base 的宽泛读取或写入权限。
上线前核验：

- 已发布机器人和消息卡片版本，能在外部专家所在会话中提供培训、状态和续办入口。
- 专家会话认证绑定一个不透明专家范围句柄；客户端、卡片和续办页面都不接收 Bitable
  record ID、题目关联、专家关联或内部状态字段。
- `GET /api/platform/fde/phase3/mentor/continuations/{opaque_ref}` 只返回交互页配置；过期、
  已使用、越权或不存在均返回同一不可用结果。
- `POST /api/platform/fde/phase3/mentor/continuations/{opaque_ref}/interaction` 只接收六个公开
  交互字段。服务端根据导师会话和 Bitable read-back 解析题目与专家关系，并生成幂等键。
- 导师知识包由已审核的脱敏规则构成，不加载原始客户意见、原始 QC 草稿、专家身份资料、
  附件、截图或对话全文。
- 返修消息只给出一次性续办引用；`revision_of` 血缘仍由 Nautilus 在 Bitable read-back 后
  受控写入。

## 多维表格自动化扩展

自动化扩展只负责触发，不负责判断或写入审核结果。配置为：

| 触发条件 | 发送内容 | Nautilus 动作 | 禁止动作 |
| --- | --- | --- | --- |
| 专家信息表单新建记录 | 路由、记录版本、事件标识 | read-back 后生成报名流程建议 | 自动通过、直接开通权益 |
| 题目预审表单新建记录 | 路由、记录版本、事件标识 | read-back 后初始化并执行题目 P0 | 在扩展内计算 P0 或客户结果 |
| 题目 P0 完成且可交互 | 路由、记录版本、事件标识 | read-back 后向导师发放受认证续办投影 | 用公开结果表或群消息匹配题目 |
| 导师续办交互已提交 | 路由、记录版本、事件标识 | read-back 后执行交互 P0 | 由导师直接写关系或审核字段 |
| 交互 P0、甲方反馈或 Compass 回执完成 | 路由、记录版本、事件标识 | read-back 后更新受控路由 | 根据未验证文本猜测通过或回执 |

扩展失败时，保存到 Nautilus 的受控技术日志并标为需要恢复；不得在聊天窗口补写业务状态。
上线前确认旧自动化均已禁用，且扩展不绑定归档表或默认空白表。

## 表单与权限验收

- 对外只保留“第三期专家信息采集（正式）”和“第三期题目预审（正式）”两个原生表单。
- 两张表单均允许持链接者提交，但不授予 Base 查看权限。
- 专家表字段与人员信息合同一致；学历、学校层次、工作年限和每日作业时长使用下拉选项。
- 题目表收集 UID、题目、领域一级/二级目录、相关附件、附件来源、后续交互思路、姓名和
  豆包 UID；领域不预设第三期行业限制。
- `第三期交互成果` 没有公开原生表单。交互字段仅在导师已认证、题目已通过预审的续办页
  显示，使用工具固定为“豆包办公任务”。
- 使用独立浏览器上下文核验可见问题、下拉项、提交按钮和“不授予 Base 查看权限”，不创建
  测试业务记录。

## 不创建业务记录的回调测试

1. 在飞书开发者后台发送 URL 验证或签名测试请求。
2. 核验 Nautilus 返回挑战响应，日志仅记录结果类别。
3. 发送无效签名和不支持路由，核验接口拒绝且不创建或修改任何 Bitable 记录。
4. 确认导师状态和续办接口在无会话、跨范围、过期凭据或内部标识输入时均拒绝。
5. 确认交互提交包含客户端关系字段时被拒绝，重复公开字段提交只返回幂等结果。
6. 以上通过后，才安排一条授权、脱敏的端到端演练。

## 当前阻断项

- 五表、两个原生表单和关系字段尚未完成线上 read-back；旧归档表不得作为运行入口。
- 生产 Bitable 仓储、持久幂等与续办存储、事件签名校验器、导师会话认证和状态解析器尚未
  注入并独立验证。
- Nautilus/导师发布版本、事件订阅、消息卡片权限、自动化扩展绑定和失败日志尚无独立
  read-back 证据。
- 甲方同步仅能消费已完成交互 P0 的符合条件记录；买方反馈必须落回 Bitable 后才更新
  `verdict` 与返修血缘。
- V5/Compass 仅可在签名契约、独立验证和一条授权演练完成后开启。
