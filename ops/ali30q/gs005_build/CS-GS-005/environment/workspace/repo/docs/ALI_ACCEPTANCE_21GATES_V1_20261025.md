# 阿里 CodeSense·验收标准唯一口径·21 项检查表 V1

> ⚠️ **勘误标注(10/28)**:本表为甲方文档的**部分转述版**,缺失精确定义(opus全过轮∈[1,3]/qwen双低/整体通过率<70%等)——**判读/出题/打包一律以 docs/ALI_REQ_STANDARD_MAP_V1.md + docs/feishu/ 两正本原文为准**,本表仅作历史参考。
> 来源:甲方 1012 原始需求文档表 17(逐字转录,缺一不可)。
> 效力:**全组织唯一达标判据**——各框此前各自定义的"达标"口径即日作废,统一按此 21 项执行。

1. Code Sense 准入:UT 锚定「改一查十」改动点与语义陷阱、不得仅校验平凡功能正确性;test_is_sufficient=true;单轮;代码可单屏读完、只读上下文≤200行
2. 陷阱可证:反例程序在声明语言版本/平台上实际触发陷阱,附运行日志;概率性陷阱附复现率
3. 挑战有效:prompt内嵌的错误前提/挑战在expert_design_notes中说明预期区分开哪两类模型行为
4. Golden可执行性:含代码的参考答案与全部变体在声明环境下实际运行通过,输出与声明一致
5. 改动点锚定:每处改动点有指向参考答案的行级映射,并有对应UT方法覆盖
6. 变体完备:≥2个功能等价、写法不同的变体,各附运行输出与等价论证
7. 边界完备:明确列出不在考察范围内、不扣分的行为;≥1个「能跑但语义错」的反例边界
8. UT断言无二义性:每个UT方法均为可由代码执行客观判定的断言
9. UT数值约束:UT方法≥21;针对预设badpattern的UT≥2条;三必需维度全覆盖;gating UT 1-3条
10. UT证据映射:每个UT方法声明evidence_required与提取方法
11. UT判分方式标注:每个UT方法judge_type统一为unit_test;gating UT由UT断言判定
12. UT不锁定表述:只判语义命中,不判特定词汇/函数名/讲述顺序
13. 判分脚本可运行:tests/score.py可直接运行,执行tests/下全量UT方法并输出结构化JSON
14. UT可追溯:每个UT方法具名(test_*)并对应改动点/维度,命中时回写命中的原文片段与UT方法名
15. 判分确定性:同答卷连跑3次逐条UT通过/失败与gating一票否决判定100%一致
16. badpattern锚定:相关UT(含gating)均判定模型实际改动后的代码是否产生badpattern
17. 校准四件套齐备:满分=1.0;蒙对≤0.30;等价≥0.90;缺陷样例的UT失败与结果单逐条一致
18. 判分依据明确:每份结果单的UT通过/失败依据明确对应具名UT方法
19. 基线难度与区分度:passrate判分,tests全对为1否则为0;五模型运行4次结果有区分度;均值<70%;至少2次非全1;不可4次全1或全0;opus至少一次全1
20. 合规:许可证宽松或授权;已脱敏;公开benchmark相似度自查;无真实凭证
