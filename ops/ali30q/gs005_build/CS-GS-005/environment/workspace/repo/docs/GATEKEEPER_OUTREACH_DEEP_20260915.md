# 深度版接触材料:与李宁团队的思想共振(2026-09-15)

> 一页纸(OUTREACH)之外的深度版,供深谈/合作设计用。视角仍是"对方的研究议程",
> 但升到命题层:不是"我们有数据/人手",而是**我们与他做的是同一命题的两半**。

## 一、核心命题共振:品味的习得 vs 品味的制度化

《Machines acquire scientific taste from institutional traces》回答的是——
**评价能力(品味)能否从历史痕迹中习得**。答案是能:四个微调模型,10,000+
编辑部决策,48 位编辑 holdout 对表。

我们这三个月回答的是**同一个命题的另一半**——**习得的品味如何被组织制度化**:

| 维度 | Gatekeeper(他们) | nautilus 组织(我们) |
|---|---|---|
| 品味的载体 | 微调模型 | 专职验证框(compass) |
| 品味的来源 | 历史编辑部决策(静态) | 组织实时运转中的判据目录与复算(动态) |
| 校准的实现 | 把过度自信的模型**踢出概率集成**(模型级) | 把自报的生产者**踢出验证写入权**(权限级) |
| 防自报机制 | holdout 对表人类专家 | 独立复算对表执行者(非实现者复算) |
| 痕迹的形态 | 出版记录横截面 | 组织运行纵向流(函件/任务/验收/驳回) |

两半拼起来才完整:**AI 品味的机器学习 + AI 品味的组织设计**。前者生成评价能力,
后者让评价能力在一个组织里获得权威、行使职权、防止被收买。这是可联合的
研究议程,不是比喻。

## 二、compass 的价值:一个"内部化的外部性"器官

组织学一直有个经典问题:内部裁判如何不被生产者俘获?(审计独立性/风控独立性。)

我们的做法值得注意的地方:**外部性不是从外面请来的,是被制度设计成一个器官**:

1. **职能纯度**:compass 不生产任何业务产出,只评估。它有自己的仓、自己的
   记忆、自己的账本——与生产者**零实现关联**(它在每份复算函里自证这一点,
   可审计)。
2. **判据先冻结**:复算前判据入目录(CATALOG_v0:verdict-recomputability-v1 /
   external-verified-provenance-v1 / evidence-schema-v1),预注册思想,
   只许更严(棘轮)。
3. **写入权垄断**:生产者可以声明自己失败,不能声明自己被验证——
   `external_verified` 的 False→True 只能由复算者写入(带 verifier+时间戳),
   这是收入的唯一入账门。
4. **实证(上周)**:compass 首批复算 10 条历史判分,10/10 不可复算——
   生产侧的"已验证"是自我置位的;时间序列溯源定位到一次换管造成的载荷断供
   (450 条空壳记录);一小时内三道守卫上线。**自报的失效、被独立发现、
   被制度修复**——全链条日志、代码、决策函可审计。

对研究者的价值:这是一个**运行中的"评估器独立性"组织设计**,
失效-发现-修复有完整档案——相当于组织版的"过度自信模型被排除出集成",
但发生在权限层,且有事故全记录。

## 三、架构:一个组织学意义上的实验装置

从组织学维度看,这个架构对每个经典问题都给了非默认答案:

- **分工**:五个 agent 框按**职能专门化**(基础设施/认知/验证/业务/自主改进),
  各有独立仓库与记忆,有领地纪律(动他框文件前必须摆选项)。
  ——不是任务分工,是器官分化。
- **协调**:全部靠**协议不靠会议**——跨框函件(结构化+2h SLA)、任务总线
  (五件套:类型/判据/交付格式/SLA/消费者)。协调成本显式化为协议条款,
  全量留痕。
- **治理**:**人机权力边界写在宪法层**——目标/判据/生死三项拍板权为人类专属
  ("三道闸");agent 只有绩效标准(SLA/判据/消费计数),不拥有目标。
  判据单向棘轮(只许更严,宽松须人类明批)。"人被放回中心"在这里不是口号,
  是权限表。
- **激励**:消费计数 KPI(从"建了多少"改为"被消费多少");收入入账的唯一
  通道=独立验证通过——**激励结构性地反对自报**。
- **可重建性**:"邮箱即账本"——组织全部状态可从函件序列重放重建(事件溯源)。
  对研究者的意义:每次状态变化都有因果链,组织是一个**可回放的实验**。
- **失效学**:三个月积累了完整的事故档案(部署假成功工厂/载荷断供/
  声称上线≠部署生效……每次有根因定谳+制度修复)。高可靠性组织(HRO)
  文献关心的问题,这里是 AI 组织的第一手案例序列。

## 四、agent-first 的思想:业务是代谢产物,组织本身是主要交付物

我们的顺序与"用 AI 工具做业务"相反:**先造 agent 的生存环境,再让业务在
环境里长出来**。三个月的产出排序——通信→任务→治理→验证→自主交付→
然后才是具身数据业务与验证服务。

这恰好是你们招募文路线图的实现顺序("需要工具,需要 infrastructure,
然后用这些 infrastructure 去做探究、做实验")——**第一段我们已经跑出来了**,
并且愿意把它作为研究者可用的基础设施:

- 研究者可以注册成组织的一个"框",用同一套函件/任务/验证协议做实验;
- 组织的纵向痕迹(脱敏)本身就是研究数据;
- **研究团队是我们新物种市场的一部分**——不是客套,是真实的供需:你们需要
  AI 原生组织做田野,我们供基础设施并从研究反馈中改进。

另外两个可能有研究价值的极端性质:
- **1 人 + 5 agent** 的极限压缩:如果这个结构能运转一家公司,组织学的基本
  单位(部门/科层/中层)需要重写——这正是"人被放回中心"的极限 case;
- **agent 的职业身份**:身份不靠提示词维持,靠结构(独立仓/记忆/领地纪律/
  协作接口)——多智能体研究中 role 的组织化实现。

## 五、可联合的三个具体研究问题(从最小到最大)

1. **互为被试**(一周内):我们的下一个研究 pitch 用 Gatekeeper 评;
   你们看一个真实 AI 原生组织如何消费你们的工具。
2. **方法对表**(一月级):你们的 holdout 校准协议 × 我们的判据预注册+
   非实现者复算——两套防自报机制互审,可合写方法对照短文。
3. **纵向数据+评估器独立性的组织设计**(一学期级):我们的三个月纵向痕迹
   (脱敏)作为你们的补充数据源;更进一步的实验设计——有/无独立验证器官的
   agent 组织,长期产出质量与自报率的差异。
