## 一、架构如何设计(详见 SITE_ARCHITECTURE_V1)

**一句话**:三层叙事讲组织,四域分放服务,零新栈渲染,装订制治理。

```
访客视图:  首页(组织是什么) → 操作系统(凭什么信) → 产品线(卖什么) → CTA(怎么买)
域名视图:  根域 nautilus.social(门面+判分线+products)
           ├ bench.(v5评测·候挂) ├ data.(flywheel具身) ├ compass.(记忆层)
           └ i.chunxiao.wang/org/(文档镜像) + api.chunxiao.wang(中转站)
```

**分层铁律**:L0 品牌(hero)→L1 信任(操作系统六件+基础设施)→L2 变现(六线产品+CTA)。访客不信任组织,就不会买单——所以信任层在变现层**之前**。

规则:**内容权在各框,装订权在平台**;跨框件走信箱总线;每件关闭=坐标+验收读数。

## 四、如何实现(实现路径·四步流水线)

```
①材料入库   各框 md 正本+坐标 → 信箱提交(或直接自家仓正本,平台拉取)
②渲染质检   flywheel 渲染器出 HTML(og 自动)+G5 壳检硬门(空壳包 FAIL 拦截)
③装订上站   平台装订员:审材→考古前置→部署窗上站(push+restart+curl 三验)
④验收登记   外网 200+标记命中+md5 与云侧一致 → 台账登记 → 回函坐标
```

**基础设施**:nginx 多 server 块(根+三子域)/acme.sh 证书/限流 60/min/md5 变更登记防竞态;正本散各仓(git 为准),部署源=nautilus-mvp 主仓。

**节奏**:V1(10/12 开业,作战板 17 件全绿)→V2(10/20:发单台+状态页+搜索)→V3(L2 首单后:托管客户面)。
