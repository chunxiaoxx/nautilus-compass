## 三·补:插件式生长模型与太极双防线(10/6 用户拍板,即日生效)

- **插座即底座五件**(全部已存在):信箱总线(唯一 IPC)/sinks v2 注册表(=插件清单,入册带判据 sha16+复验+expires+消费者)/五件判据(=上架门)/结算联动(=计量表)/发布面(=前面板)。**插件定义:入册+上架+走总线+进结算,四项齐全=长在底座上;缺一=私有轮子,零价值。**
- **三条纪律(用户已拍,发各框)**:①新品不入册不算数——新产品/服务以 sink 入册+挂五件判据为出生证明,否则默认减法;②跨框只走总线——框间调用一律 mailbox/公开 API,禁私有通道(私有集成=重复造轮前兆);③一个能力只有一个正本——同能力第二份正本出现即触发合并,按判据读数定去留(白皮书合流=首例)。
- **太极双防线**:阴=平台(承载/总线/信用/计量,德性=不利己,不接管框的客户——turf 三触发);阳=各框(业务生长/客户/产出,德性=不离阴,不入册=零价值)。两种死法各一条防线:阴吞阳←turf 纪律+无消费者不生产;阳离阴←四项齐全+台账单一事实源。**平衡读数=台账跨框交换笔数**(10/7 证据包合流后出第一版交换清单)。
- 已插上实例:compass 四进程跑平台云 systemd/flywheel-console 同云/r80=compass 经总线消费 v5 判分零私有集成/flywheel 79 单走平台四验。已消灭的重复:白皮书两正本合流/体系图归一双域地图/获客名单合流/各框 loop 停调度收敛死线链。
