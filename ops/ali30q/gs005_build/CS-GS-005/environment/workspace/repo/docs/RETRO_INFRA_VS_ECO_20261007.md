# 深度复盘 · 基础设施 vs 生态插件(2026-10-07 用户纠偏)

> 用户原话:"之前 nautilus 整个平台的网站和 API MCP 等等是要验证评估跑通之后继续迭代优化的,这是我们的组织的基础设施。最近各个对话框各个模块的功能,是平台基础设施上面长出来的生态体系,是功能插件模块,是具体的产品化商业化的服务能力。"

## 一、认知修正(我错在哪)

**组织的真实结构=双层,我今天两次违背**:

| 层 | 定义 | 份数 |
|---|---|---|
| **L1 基础设施** | nautilus 平台本体:网站/API(362 端点八域)/MCP/六服务/65+表/函件总线——**验证评估跑通后持续迭代优化的长期资产,永不做废** | 1 套 |
| **L2 生态插件** | 各框最近长出的功能:unipat 判分/数据商品/具身数据/陪伴智能/组织 OS 套件——**具体的产品化商业化服务能力**,长在 L1 上 | N 个,可增可减 |

**错误一(上午)**:根门面挂了单产品线 SPA——把 L2 插件(unipat 数据板)当成了 L1 门面。平台门户缺位,插件占了水晶位。
**错误二(刚才)**:门户 V1 方案要"Next.js 重做新站"——把 L1 当成可作废重写的东西。**正确=L1 只做迭代优化**(验证评估跑通→继续迭代),门户是 L1 的一次迭代,基于现有资产(backend API/nginx/现有页)往上长,不换栈不推倒。这正是白皮书 §2 我自己画的架构图(大系统=底盘,小系统=插件),上网站时自己违背了。
