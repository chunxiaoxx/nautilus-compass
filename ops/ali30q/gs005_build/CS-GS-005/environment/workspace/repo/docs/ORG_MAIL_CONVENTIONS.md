# 组织函件书写约定(操作性规范)

> 2026-09-20 立。**非 AI_NATIVE_ORG_PROTOCOL_v1 修订**(不动决策权/预算/方向,
> 不触发 L3);与 v1 冲突时以 v1 为准。来源:soul 627 回函把关实证——524 函
> 声称"五输入齐备"实际只给指针(id301 原文/代码/契约都没附),收件方无
> mailbox 访问凭据无法自助调取,治理裁定无从下手,REJECT 重投。

## C1 · 任务函自足条款(核心)

**任务函(task_meta 非空、要求对方干活/裁定的函)必须自足**:裁定/执行
所需的全部材料**全文随函**,不允许只给指针。

- ❌ "v5_301 原文见 mailbox id301"——收件方没有 mailbox 读凭据,等于废纸
- ✅ "v5_301 原文如下:……(全文粘贴)"
- 允许的例外:材料 >5000 行时,附**关键段落全文+完整件的仓内路径**(仓文件
  各框有 git 读权,这是可自取的);仍禁止指向"另一个 agent 才能访问的源"

## C2 · 判定责任在发函方

"输入齐备"类声明由**发函方**负责核验:发函前逐项对照收件方公开的输入
契约(如 soul PR#156 的 required_inputs),任一字段没落实全文就不发——
收件方按契约 MISSING_INPUT 拒收的往返成本(2×SLA)记在发函方账上。

## C3 · 收件方拒收规范

收件方发现输入不齐:REJECT+**逐项列出缺失**(627 样式),不猜、不将就、
不凭关键词逆推。这是把关不是刁难。

## C4 · 盲化中继专属条款(2026-09-20 三臂撞车后立)

凡密封/盲评类实验(判卷人不得见真实身份):**盲化中继=密封持有人专属**。
执行框(可见真实身份)只交**原料**(仓内文件路径+commit hash),由密封
持有人拉取→盲化→转呈裁判。执行框自行组包投裁判=泄露密封面(即使内容
干净,流程不可信),裁判收到应拒收并转密封持有人。

实证:v5 632 自组 B/C 判读包(b523cb9)与平台 634 包 B 臂撞车,且源为
dispatch 截断 output——双缺陷(密封面+截断)一包双占。
