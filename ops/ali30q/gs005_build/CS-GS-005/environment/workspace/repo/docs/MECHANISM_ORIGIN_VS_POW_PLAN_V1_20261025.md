## 三、系统化/产品化/工程化方案:让 DMAS 与 PoW 真正转起来

### 核心洞察:本次任务天然就是 PoW 试验场

每道题的工作量**客观可验证**:
- git commit hash(代码存在性)
- 金标 passrate 实测(30/30 等,正确性)
- 五模型×4 轮判分矩阵(区分度证据)
- 13 门表自检记录(合规性)

这四件=教科书级的 PoW"work proof"。**我们缺的只是一道铸造工序**。

### 三层落地

**① 工程化(今天可跑通):PoW 铸造器最小版**
- 每题铸一条凭证:`{题ID, 生产者, git_hash, UT数, 金标passrate, 判分矩阵sha, 验收人, IRT(b,a)}`→写入 fuel_trajectories+NAU 记账
- 验证者=compass 判读层(第三方判分=组织核心差异化,天然 validator)
- **第一单**:平台 6 题(P101 等,v5 四验 4 过 1 改)——铸 6 条 PoW+按 IRT 难度计价入 NAU

**② 产品化(本周):判分结算=四 SKU 首个可复购服务**
- 判分 $0.003/单起(10/6 商计书定价已有)——甲方 500 场判分就是第一笔真实外部收入
- 晓天平台接入=渠道扩大;我们的判读层+IRT 校准=产品差异化(防自评作弊的第三方判据=组织核心竞争力)
- 30 题入选=白皮书"AI 原生组织产线"章节的实证案例(初心①:装进外壳)

**③ 系统化(10/26 后):结算自动化**
- capability-settle timer 恢复:每题 status→settled 时自动 IRT 计价→NAU 入账(fuel_settle 范式,机制已有,激活即可)
- 路由规则固化+额度监控+渠道健康(10/25 维护手册已建)——产线自转的组织 OS

### 与北极星的合流

本次 26 题改造的全部过程数据(判分矩阵/断点处置/IRT 参数/协作函)→燃料池→**既是出题素材(同族新题)也是白皮书实证**——初心三句"装进外壳"在这里合流。
