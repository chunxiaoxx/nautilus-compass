# 调研 agent 模板(7/17 已验证 5 次:0 挂死,均 3-6 分钟返回)

> 血泪来源:曾有调研 agent 挂 9 小时 0 产出。硬约束模板后 5/5 成功。

## Prompt 骨架(逐段必含)
1. **角色+主题一句话**,并给出时间窗要求(如"2026-01 至 2026-07 信源优先,旧闻不要")。
2. **硬约束(逐字抄)**:
   - 最多 10-12 次 WebSearch/WebFetch,用完立即汇总;
   - 任何单个 URL 抓取失败,立即跳过,绝不重试;
   - 宁可交部分结果,不许空手超时;
   - 每条事实带信源名+日期;搜不到的直接说"未检索到",不编造。
3. **调研问题按优先级编号**(3-6 问,先重后轻——预算耗尽时保住头部)。
4. **输出格式**:markdown 分节对应问题;每节末尾一行"对我们(裁判+基地+灵巧手SKU)的含义"。
5. 若为纠错二轮:开头写明"上一轮结论已作废,原因是 X",防止 agent 沿旧路。

## 返回后的处理(不做=白调研)
1. 结论并入相关页面(ops-map/external)对应板块;
2. 原文沉淀进 nautilus-core `docs/research/2026-*.md`(带信源,标注"未覆盖清单");
3. 若推翻旧结论:旧文标注作废+原因(参照 D→D2 先例),不删除(留判断轨迹)。
