# 飞轮试单流水线 → 平台任务链翻译方案(2026-09-04 · 平台框拟)

> 定位:平台=飞轮业务的**承运人**。飞轮 9 月试单流水线是平台本体(DMAS/A2A/SOUL)的活化载体——
> 不是先建平台再装业务,是业务流水线把平台一层层冲活(7/17 论纲:最小飞轮→PMF 养 RSI)。
> 纪律:零新机制,全部用既有件(org task/verdict/capability·settle/A2A/skills 表);**复活判据=外部真值任务,内部循环只作 dry-run**(8/30 定谳:组织内闭环=玩具)。

## 二、分期与判据(反 D:判据=外部真值,非件数)

- **M1(设备到货→首条全链)**:环节 1-5 上平台任务语义,QC/转换沿用现役自动化,verdict 入总线。
  判据:一集真实采集数据从 #3 流到 #5,全程任务化留痕,verdict 可查。
- **M2(计量+交付)**:环节 6-8。判据:首份计量报告+首笔客户交付,**收款入账=income 脱 0**。
- **M3(A2A 化+采集员上平台)**:#3→#4→#5→#6 交接从 mailbox/DB 改走 a2a_delegations(**A2A 首通话**);
  P1 试点采集员实名注册进 tasks 生态,接单/交付/结算全链。判据:A2A delegation 表首行真实业务记录。
- **M4(SOUL 喂养)**:合格 episode 的 QC 参数/转换配方固化进 skills(经验→技能),可被后续 agent 采纳。
  判据:skill_registry 首条来源=真实作业的技能。

## 三、分工(turf 边界)

- **平台框**:机制接线——任务语义注册/verdict 写入配方/settle 挂接/A2A 交接改造/快照加流水线看板行。不碰业务执行。
- **飞轮框**:业务 owner——各环节执行/口径维护/对外动作。本方案呈其认领或提异议(mailbox,2h SLA)。
- **用户**:设备下单(已拍)/对外发送/收款。环节 8 永远人类专属。

## 四、红线(防复发)

1. 每类任务的 verdict 必须**机械可验或客户可验**,禁 LLM 自评定 PASS(假成功工厂教训)。
2. 结算金额挂飞轮报价成本口径,禁自定价格(经济面出问题呈用户)。
3. 环节间交接先跑通 mailbox 版,A2A 化只在 M3 做——协议不先行于分工。
4. fde_dispatch 垂域池(冻结)不装业务;任务走 org task 语义,不复活旧管道。
