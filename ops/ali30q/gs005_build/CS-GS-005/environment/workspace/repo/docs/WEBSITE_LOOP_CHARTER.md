# 网站系统 loop 章程(2026-10-09 用户四令 · 持续推进)

> 用户令:围绕整个平台和各框网站系统持续推进,四主线。本章程=判据正本,作战板(SITE_BUILD_BOARD)为动态待办,台账为事实源。

## L1 · 统一视觉语言

**判据**:组织级 design tokens V1(色板/字体/间距/组件规范)落正本;根域与 app 子域首个采用;各站渐进迁移(禁一次性重刷)。
**现状**:五套视觉并存——根域浅色文档风/bench 深色数据风(#0b0e12)/data 浅色 review 风/compass 未核/旧 SPA 自有 design system(DESIGN_SYSTEM.md 在库)。
**动作序**:①提取旧 SPA DESIGN_SYSTEM+各站现值→tokens V1 草案 ②发六框征议(各框可提异议+自有品牌色保留位)③根域+app 先行,bench/data 渐进。
**验收**:跨站跳转视觉连续(截面对照);tokens 文件单一来源。

## L2 · 统一登录/用户管理/权限管理

**判据**:①一次登录处处可用(M1 身份层唯一,各框零自建登录)②用户表统一(旧 SPA users 体系与 M1 合流,不双轨)③角色分级 M2 落地(人类成员/agent 管理员/普通用户三档起步)④各框后台全部走平台鉴权。
**现状**:M1 邮箱码上站(admin 白名单制);旧 SPA auth 完整(邮箱+密码+Web3 钱包+GitHub/Google OAuth)随 B 档复活;各框后台 2/6 在役且已用 M1。
**拍板**(平台拟,征议中):SPA auth 体系为主通道(功能全),M1 三端点保留为轻量通道,二者合流到同一 users 存储;M2 三档角色随 users router 落地。
**验收**:app 子域登录→bench/data 后台免登录直达;一用户一行;角色字段在列。

## L3 · 引导各框持续迭代自己的网站系统

**判据**:每框网站有 owner+有迭代(git log 每周可见增量);后台建设 6/6;数据驱动(页面数字与数据源同源闸,禁手工改 HTML 供数)。
**现状**:2/6 后台在役(v5/flywheel),soul 认领未建,compass/zenmind/hr 未动;data 根页已立同源闸标杆,bench v3 数据驱动跟进,根域榜页仍手工。
**动作**:loop 每轮扫各框仓增量+上站件;欠件催办(SLA);规格支持(框架/同源闸配方);周报披露各框网站活性。

## L4 · 对照白皮书/BP/功能定位更新迭代

**判据**:周度对账(BP/白皮书承诺 ↔ 网站实物),差异立卡进作战板;两外壳更新时网站同步(装订制);网站不承诺 BP 之外的东西(防叙事超前)。
**现状**:10/9 首轮对账七处差异(五处已立卡);白皮书 DID 章与产品脱节候征议修正。
**动作**:每周一"对账轮"固定产出差异清单;BP/白皮书变更走装订同步网站。

## 节奏与红线

- cron 30min/轮;每轮五步(对表/信箱/推进一件/台账/R5);连续 2 轮无产出报警
- 升级规则沿用(新对外发布/收款承诺/方向生杀停下等用户)
- 与既有 loop(产品化冲刺)合并执行,网站件优先(用户 10/8 定调核心重点)
