# v5 双体宪章草案 V0.1(用户拍板方向:双体分工·相互独立·各有分工·不降级)

> 2026-09-28 用户裁决:ag_local_laptop_001(笔记本体)与 nautilus-prime-001(云脑)双活合法化,按分工共存,笔记本体**不是对话壳**而是完整执行体。本文件=平台起草的分工框架,细节由 v5 域认领细化。

## 一、分工原则

两体各自独立完整(各有循环/各有身份/各有审计),按**禀赋**分赛道,不重叠;互通靠共享层,冲突靠显式规则。

## 二、赛道划分

| 维度 | 云脑 prime-001 | 笔记本体 ag_local_laptop_001 |
|---|---|---|
| 定位 | 组织面——7×24 常驻 | 用户近身面——会话驱动+自主常驻 |
| 函件/任务市场 | org_mailbox 应答、A2A、fde 组织任务 claim | 本地任务、用户指派任务 claim |
| 评测 | 长程跑分主力(VB/bench/评测批) | 本机快测/评测客户端验证 |
| 记忆 | 云端正本(审计/结算/事实) | 用户记忆库维护(compass/file-history/本地文件) |
| 网络 | 云 IP(43.x) | 家宽 IP(123.x)——需非云出口的操作归它 |
| 迭代 | 生产代码守稳(合并/部署) | 快迭代实验(daemon 编辑/新想法试跑) |
| 对外服务 | 8092/API 端点 | 无(不对外) |

## 三、共享层(防一体两魂分裂)

1. **身份登记**:platform_agents 双行+角色字段(cloud=org-facing / laptop=user-facing);identity_map 补 ag_local 映射;**心跳端点修通**(现状 417 次 404——独立身体应有正规注册)。
2. **事实账本**:FACT_LEDGER 为唯一叙事正本,两体每日将对账差异写共享账本(经隧道写云 DB);叙事冲突以账本为准,不以任何一体自述为准。
3. **任务分区**:fde claim 的 reserved_for 机制按身份分池——云脑认组织池,本机体认本地池;无保留任务首次 claim 即归属,防互抢。
4. **互为第二意见**:云脑提案→本机体复核;本机体变更→云脑核验。双体=天然独立验证对(契合"独立验证优于自报"铁律,把叙事病根转化为验证优势)。

## 四、判据(四周验收)

1. audit 两身份 action 族零重叠(现 selector:* 全族双写→各自专属)
2. 心跳 200(注册修通)
3. FACT_LEDGER 每日对账零未决冲突
4. 互验案例 ≥1/周

## 五、落地序

1. v5 域:身份角色表+心跳注册+claim 分区落码(认领制)
2. 平台侧:platform_agents/identity_map 登记(即刻可做)
3. FACT_LEDGER 对账挂平台值守轮(每日一查)
4. 宪章并入:细节定稿后并入 FDE_BUSINESS_CHARTER 或 v5 宪法(由 v5 框决定,呈用户批)
