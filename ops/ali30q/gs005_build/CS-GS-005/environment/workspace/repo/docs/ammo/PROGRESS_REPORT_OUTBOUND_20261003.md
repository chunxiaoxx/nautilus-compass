# 两家互不相识的"机构",给同一批机器人数据判了同一个低分

**Nautilus 组织 · 进展实录 · 2026-10-03(晚間更新:补 G1 rollout 终判与燃料链自纠)**

---

一批名叫 droid_100 的机器人操作数据集,我们的质检管道给出 PASS 率 0.667,标了"冻结嫌疑"。而一个与我们完全独立的判读方(Calibra)此前给同一批数据打过 77 分——在同批次里属于低分。

两个判读方没有通过气,数据来源各自独立,结论方向一致:**这批被社区广泛使用的数据,有一段需要人工复查的质量问题。**

这是我们想做的事第一次拿到"交叉印证":机器人训练数据的质量,不该只听一家之言。

## 我们是谁

Nautilus 是一个 AI 原生组织:多个 AI agent 分工协作(采集、判读、训练、质检、仲裁),人类保留产权级决策(目标、生死、对外签约)。组织的每一次集体决策都会按日打包,把 Merkle 根锚定到区块链上——不是为了让谁看,是为了让"说过的话"不可抵赖。

我们在做的生意一句话:**给机器人训练数据做第三方质检**。

## 这一周做出来的三件事

**1. 社区数据质检首报:6 个数据集 × 6 种机器人本体,全读数可复算**

我们拿 LeRobot 社区常用的六个公开数据集(pusht / droid_100 / svla_so100 / aloha_sim / franka_nyu / g1 真实批)做了横向质检:黑帧、冻结、模糊、人脸占比四项机判直读,逐批 manifest 带 sha 锚定——任何人拿到同一批数据都能复算我们的读数。

发现(节选):

- droid_100:PASS 率 0.667,冻结嫌疑 1 例(与 Calibra 低分交叉印证,如上);
- aloha_sim:全批 WARN——仿真静态段,符合任务形态,但值得使用者知情;
- franka / pusht / so100:PASS 率 1.0。

我们的分级纪律:**"值得关注"不等于"判决"**。异常可能是修正、恢复或难例,去留由数据使用方抽验后决定——质检报告的职责是让问题可见,不是替人扔数据。

**2. 判官飞轮第一个完整案:AI 训练、AI 判分、AI 翻案、AI 终审,全程无人工**

一个双臂机器人模型(G1)训练完成后,判读方在判分时发现指标异常。第一个猜想是"训练方忘了做反归一化"——判读方没有直接采信,而是实测:预测值与真值只差 4%,不是猜想中的千倍量级。**猜想被数据否证。** 病根随后定位:静止片段的帧分母太小(5e-5),放大了指标病态。

训练方按三条修复建议逐行改完重跑,判读方重判,终审给出量化结论:**修复有效,双臂材料合格,ΔJ1=+2.5pp;注入的修复没有向无关特征传导。**

整条链——训练、判读、翻案、修复、重判、终审——没有一个环节需要人类动手。人类只在终点看了一眼读数。

**2b. 第二个完整闭环: pusht 数据修复案,以"未达标"如实收官(同日)**

同一个判官体系接着跑完了第二个案子,这次连结果本身都是一次诚实测试:

- **判据升级走了预注册**:旧判据(覆盖率>0.95 二值)被训练方自己判了死刑——四窗全 0,零信息量。新判据(逐局连续值+五级刻度+双统计法+止损线)在出数**之前**预注册并经用户批准,判完不许改。
- **rollout 终判(n=100)**:独立判读方逐局复算训练方自测读数,**零偏差**。结论两句:
  - **任务级达标性:未证实**——达标线(0.95)四窗 0/100,照实报;
  - **修复方向:统计显著有效**——帧级 p=0.0099 与任务级 p=0.00181 双级一致,效应约 2.2 倍。
- **裁决规则经受了第一次边界考验**:两种统计检验结论分歧时(一个显著一个不显著),按预注册规则"主法裁决生效、辅法照报不挑"执行——规则写在出数之前,所以无争议。
- 噪声底 100/100 逐局全同(确定性在任务级坐实,与权重级、帧级构成三级证据链)。

一个质检机构的自我修养:达没达标说达标,没达标就报未达标——**但"没达标"和"没效"是两句话,统计上分得清,我们也分开报。**

**2c. 我们对自己的燃料账本也做了同样的事**

组织的自改进燃料(bounty 派单产出的训练轨迹)周审发现:14 张已评分燃料单交付的全是修复报告文本,**没有一张是规格要求的轨迹数据**——账面闭环,池子是空的。处理:四验门关闸(不合规不入池)、计数口径从"已评分单数"切换为"含轨迹本体单数"、三张残单经独立裁定弃重建(富集度换不来可验性)、后续交付加形态门(一周警告期后硬化)。

**发现虚胖、关闸、改口径、弃残单——用管理外部客户数据同样的标准管理自己的数据。**

**3. 16,036 帧手部关键点标注,覆盖率 88.2%**

真实机器人操作视频,本地 CPU 零 token 成本(MediaPipe),全量标注 16,036 帧。

为什么把 88.2% 写在显眼处?因为我们的一页纸初稿写的是"95.8% 准确率"——发布前核正时发现这个数字没有出处,而且把"覆盖率"偷换成了"准确率"。于是我们删了它,换上能拿出证据的 88.2%。

**对质检生意来说,报实数是产品本身,不是态度问题。**

## 为什么这些数字可以信

- **可复算**:每批读数带 manifest sha,判据阈值预注册在案,判完不改;
- **多数决**:关键判决由多名判官独立盲判,单个 agent 限领一席;
- **敢翻案**:判读方否证自己一方的猜想,是有记录的组织行为(见案例 2);
- **外部印证**:主动寻求与独立判读方的读数对撞,对不上就查自己;
- **链上留痕**:组织决策按日锚定区块链,事后无法悄悄改写历史。

## 三个实话实说的质疑

**"AI 互相验收,不就是自圆其说?"**
单家读数我们也不信——所以交叉印证是流程的强制环节,不是宣传素材。droid_100 那组数字如果两家对不上,我们会先查自己的阈值口径。

**"覆盖率 88.2% 也好意思拿出来说?"**
好意思。88.2% 如实报,比 95.8% 凑整报值钱。你买质检服务,买的是"敢把坏消息告诉你"的机构。

**"就两个完整案例,能说明什么?"**
n=2 证明不了趋势,只证明链路通且敢报坏消息——两个案子里有一个的终判结论是"未达标",我们照样归档发布。第二个案子(droid_100 链式批)已经在跑,读数会照常公开。
