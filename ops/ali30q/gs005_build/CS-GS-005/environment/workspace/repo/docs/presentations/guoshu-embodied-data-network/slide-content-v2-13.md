# 国曙具身数据生产网络：v2.0 对外 13 页内容底稿

**沟通任务**：让机器人本体企业、世界模型/VLA 企业和数据平台相信，上海国曙人工智能有限公司可以以边界清晰的付费 POC，把其指定的真实任务组织成可审查、可联合验收的数据包；POC 的证据决定后续是否扩大，而不是用未经验证的规模承诺换取首单。

**主叙事**：具身训练需要可闭环的真实任务经验。EGO 和 UMI 决定采集协议；协同基地、分布式众包和垂直现场决定供给与运营。国曙从协同基地的付费 POC 起步，对人员组织、质量闭环和最终交付负责，并以样本验收、授权、可复现性和结算四道门槛决定扩量。

**对外阶段标签**：

- `当前可启动`：合作基地支持、人员组织、项目运营、质量闭环与交付总责。
- `按项目配置`：客户共同选择 EGO/UMI、设备/传感器、场景、格式和验收标准。
- `条件触发路径`：在 POC 证据成立后，逐项开启众包、垂直现场及 Agent 辅助运营。

**统一边界**：不写客户 Logo、成功案例、固定产能、成熟全国网络、数据集规模、模型提升、已上线的自动验收、第三方认证或数据市场。国曙体系的历史数字只标注为“国曙体系积累”，不作为具身数据业绩。

## 01｜让真实工作成为具身智能可学习的经验

- **唯一叙事任务**：建立“真实世界训练数据生产伙伴”的定位，而不是泛化人力外包定位。
- **页面标签**：真实世界训练数据生产伙伴。
- **屏幕文案**：
  - 面向具身本体、世界模型与数据平台的真实世界训练数据生产伙伴。
  - 从客户指定的真实任务开始，把场景、操作、任务结果与验收证据组织为可进入训练与验证的数据包。
  - 先以任务边界清晰、可联合验收的 POC 建立合作，再用证据决定是否扩量。
- **视觉目的**：用“真实任务 → 合格数据包 → 训练/验证”三段式主线，留下明确的合作入口。
- **证据与阶段**：U01、U03、U04、U06、U14；`当前可启动`。
- **禁止误读**：不写现成大规模网络、首单客户或模型效果。

## 02｜具身训练缺的不是更多视频，而是可闭环的数据

- **唯一叙事任务**：将客户采购标准收束为可用、可调试、可验收的任务数据单元。
- **屏幕文案**：
  - 观察：场景、物体、人手与过程发生了什么。
  - 动作：手部/末端状态、时间关系与可对齐的操作线索。
  - 任务：指令、步骤、成功/失败与异常原因。
  - 证据：采集条件、质量记录、授权范围、版本与交付边界。
  - 可闭环，意味着同一任务可以被复盘、拒收、修订并再次验证，而不只是累积视频时长。
- **视觉目的**：四段连续链，不做“数据类型清单”。
- **证据与阶段**：C01、C06、E08；`按项目配置`。
- **禁止误读**：不把任意视频或时长当作训练价值保证。

## 03｜一条训练闭环，两条采集线

- **唯一叙事任务**：解释本体/策略与世界模型共享同一个数据闭环，EGO/UMI 是两条可组合的采集线。
- **屏幕文案**：
  - 真实任务：由客户定义场景、对象、成功标准与使用边界。
  - EGO：补足场景、任务语义与人类工作流程。
  - UMI：补足更接近机器人末端的操作观察、状态与动作线索。
  - 统一任务协议、质量验收与数据权利，形成可交付的**合格 episode**。
  - 世界模型学习环境、时序与任务先验；本体/策略学习可验证的动作示范，并在机器人上接收任务反馈。
  - EGO/UMI 可单独使用或组合使用；人类示范到机器人执行仍需按任务进行对齐验证。
- **必建图**：横向“真实任务”起点；橙色 EGO 与青色 UMI 双轨并行，汇入“统一任务协议 → 合格 episode”，再分流至“世界模型”和“本体/策略 → 机器人验证”。
- **证据与阶段**：E10、E11、E12、C09、C11；`按项目配置`。
- **禁止误读**：不说 EGO 可以直接生成任意机器人动作，不说 UMI 无需适配。

## 04｜EGO：采集真实世界的任务经验

- **唯一叙事任务**：清楚说明 EGO 采什么、适合什么、怎样控质，以及它不能替代什么。
- **页面标签**：`按项目配置`｜第一视角采集协议。
- **屏幕文案**：
  - 采集视角：头戴或穿戴式第一视角装置；相机、IMU 与其他传感器按任务书确认。
  - 数据字段：第一视角视频、时间戳、任务/步骤语义、场景/物体状态；经授权时记录手部或姿态信息。
  - 适用价值：覆盖复杂现场、长流程、人—物—环境交互与隐性工作顺序。
  - 质量要点：设备标定与时间同步、任务提示与回放、场景隐私清单、人工抽检和客户定义的验收阈值。
  - 技术边界：EGO 记录人类经验，不自动等于机器人可执行动作；任务结构、动作表示和人机对齐须在 POC 验证。
- **视觉目的**：一幅从佩戴视角到字段层再到质量门的技术剖面图；字段与限制同屏可读。
- **来源页脚**：NVIDIA EgoScale — https://research.nvidia.com/labs/gear/egoscale/；EgoMimic — https://ego-mimic.github.io/
- **证据与阶段**：E01、E10、S01、S15；`按项目配置`。
- **禁止误读**：不写国曙已有自有双目/多传感帽，不宣称模型效果或直接机器人迁移。

## 05｜UMI：采集更接近机器人动作接口的示范

- **唯一叙事任务**：把 UMI 解释为可按项目评审的操作采集路线，不包装为国曙现有设备。
- **页面标签**：`按项目配置`｜操作接口邻近的采集路线。
- **屏幕文案**：
  - 路线参考：以手持夹爪或末端邻近接口记录操作过程，使观察视角更接近机器人执行端。
  - 数据字段：末端邻近视觉、时间戳、位姿或相对动作、夹爪状态、对象状态与任务成功/失败。
  - 适用价值：针对抓取、放置、开合、装配等操作子任务，保留可与机器人动作空间对齐的线索。
  - 质量要点：坐标与时间对齐、夹爪/对象状态校验、成功判据、设备标定和回放复核。
  - 技术边界：设备选型、标定和本体适配须写入 POC 任务书；该路线不承诺跨本体零适配迁移。
- **视觉目的**：从人手/夹爪、末端邻近相机、位姿/状态流到任务结果的简洁技术链，突出“对齐”而非泛化 AI 形象。
- **来源页脚**：UMI — https://umi-gripper.github.io/；EgoMimic — https://ego-mimic.github.io/
- **证据与阶段**：E11、S16、S15；`按项目配置`。
- **禁止误读**：不把 UMI 写成国曙自有成熟设备，不承诺模型或机器人效果。

## 06｜基地、众包、垂直现场：一个标准，三类供给

- **唯一叙事任务**：彻底拆开采集协议层与供给/运营层，说明三类供给单元如何承载 EGO/UMI。
- **页面标签**：供给与运营层，不是第三种采集技术。
- **屏幕文案**：
  - 横轴回答“采什么”：EGO / UMI。
  - 纵轴回答“在哪里采、谁采、怎样控质”：协同基地 / 分布式众包 / 垂直现场。
  - 协同基地：当前/POC 的质量起点，可形成金样本、设备标定和高控制任务包。
  - 分布式众包：条件触发的场景覆盖与弹性供给，前提是准入、设备一致性、授权、拒收与结算均已验证。
  - 垂直现场：条件触发的真实工作流入口，前提是客户授权、低打扰流程、隐私与业务连续性可控。
  - 同一任务协议贯穿三类供给单元；垂直现场不是第三种采集技术。
- **必建图**：2×3 矩阵。列为 EGO、UMI；行为协同基地、分布式众包、垂直现场。仅“协同基地”标橙色“当前/POC”；众包与垂直现场标青色“条件触发”。
- **证据与阶段**：C09、E13、U02、U08、U14；`当前可启动` + `条件触发路径`。
- **禁止误读**：不将三类单元写成已同时规模化运行的网络。

## 07｜基地：金样本、标定与高控制任务的质量锚点

- **唯一叙事任务**：说明基地的价值是把任务做成可复跑的质量方法，而不仅是提供场地。
- **页面标签**：`当前可启动`｜协同基地 POC。
- **屏幕文案**：
  - 任务进场：客户任务书明确对象、场景、设备/传感器、格式、成功标准和拒收边界。
  - 金样本：在可控条件下形成首批可回放样本，并固定设备标定、时间同步、标注与异常分类。
  - 质量锚点：以金样本训练执行人员，校准抽检口径，形成可复制的任务包与拒收字典。
  - 联合验收：客户与国曙共同确认样本是否合格、哪些应返工、哪些不得交付。
  - 当前分工：国曙组织人员，承担现场运营、质量闭环和最终交付；合作资源提供基地支持、指导培训与派单协同。
- **视觉目的**：任务书 → 金样本 → 培训/标定 → 联合验收 → 可复制任务包的闭环，而不是基地照片展示。
- **证据与阶段**：U02、U03、U06、U08、U14、E06；`当前可启动`。
- **禁止误读**：不写自有成熟基地、固定产能或已完成客户案例。

## 08｜众包：通过验证后才打开的弹性产能

- **唯一叙事任务**：给出众包的运营顺序和证据门槛，强调质量与积极性必须一起被设计。
- **页面标签**：`条件触发路径`｜POC 验证后的受控扩量。
- **屏幕文案**：
  - 只有当金样本、任务包、拒收字典和授权规则已被验证，才评审是否打开分布式众包。
  - 准入 → 设备自检 → 任务包与 Agent/人工引导 → 上传 → 预检/抽检 → 通过验收后结算。
  - 每一环均需可记录：参与者与场景授权、设备一致性、任务完成度、质量漂移、返工和结算依据。
  - 众包的目标是扩大覆盖面，不以牺牲任务可复现性、隐私边界或验收门槛换取规模。
- **视觉目的**：一个带准入门、预检门、验收门和结算门的受控流程；“通过验收后结算”应是视觉落点。
- **证据与阶段**：E03、E07、E08、E13、C10；`条件触发路径`。
- **禁止误读**：不写已运营常态化众包网络、自动化验收已上线或现有参与者规模。

## 09｜垂直现场：不打扰业务地进入真实高价值工作流

- **唯一叙事任务**：解释垂直现场以真实任务价值为目标，而以授权、低打扰和可复制性为进入条件。
- **页面标签**：`条件触发路径`｜经授权的真实任务现场。
- **屏幕文案**：
  - 从业务流程中定位可重复、可观察、可定义成功标准的操作子任务，而不是要求员工额外表演。
  - 先确认现场、员工与客户授权；再定义设备佩戴/使用窗口、敏感区域、上传方式、访问权限与删除规则。
  - 在不改变服务流程的前提下，尽量压低对客户体验、员工效率与业务隐私的影响。
  - 用基地金样本和统一任务协议判断现场差异是否仍可交付为同一版本的数据包。
  - EGO/UMI 仍是技术路线；垂直现场只是高价值真实任务的供给入口。
- **视觉目的**：业务流程勘察 → 授权/低打扰设计 → 采集窗口 → 安全上传/现场交付 → 质量回流的现场运行图。
- **证据与阶段**：E07、E08、E13、C09、C10；`条件触发路径`。
- **禁止误读**：不写已在任何行业完成批量在岗采集或已取得行业客户授权。

## 10｜同一任务协议，交付不同模态的合格 episode

- **唯一叙事任务**：让客户看到“合格 episode”不是泛泛数据包，而是一套可验收、可追溯、可控制权利的交付单元。
- **页面标签**：交付单元由客户共同定义。
- **屏幕文案**：
  - 任务上下文：任务 ID/版本、场景与对象、步骤、成功/失败判据、目标格式。
  - EGO 模态：第一视角场景流、时间戳、任务/步骤语义与经授权的状态信息。
  - UMI 模态：末端邻近视觉、位姿或相对动作、夹爪状态、对象状态与操作结果。
  - 质量证据：同步/标定记录、完整性、成功判据、抽检结果、拒收原因与返工版本。
  - 权利与交付：主体/场景授权、访问权限、保存与删除、脱敏要求、交付版本与使用范围。
  - 合格 episode 以客户共同确认的任务协议为准；同一协议可让世界模型和本体/策略从不同模态读取所需信息。
- **视觉目的**：一个“任务协议外壳”包住 EGO/UMI 数据流、质量证据和权利记录，避免把它画成单纯文件夹。
- **证据与阶段**：C06、C10、C11、E08；`按项目配置`。
- **禁止误读**：不写固定通用数据标准、默认可复用客户原始数据或第三方认证。

## 11｜国曙如何对交付负责

- **唯一叙事任务**：把信任从“资源描述”落到客户、国曙与合作资源之间清晰的责任边界。
- **页面标签**：`当前可启动`｜项目责任可追溯。
- **屏幕文案**：
  - 客户：定义任务目标、使用场景、数据规格、验收门槛与反馈节奏。
  - 国曙：与客户签约；组织人员；负责项目运营、质量闭环、进度沟通、问题升级与最终交付。
  - 合作资源：提供基地支持、指导培训与派单协同，不替代国曙面对客户的合同与交付责任。
  - 共同治理：任务书、版本、样本验收、权限、返工与变更均留在联合确认的项目机制中。
  - 当前边界：设备配置、实际产能、现场可进入性和扩量路径均以项目勘察与 POC 证据为准。
- **视觉目的**：简洁 RACI 责任图。客户在左、国曙居中为“合同/运营/质量/交付”责任主体、合作资源在右；问题升级和联合验收回路可见。
- **证据与阶段**：U02、U03、U07、U08、U14、U15；`当前可启动`。
- **禁止误读**：不写战略合作、独家基地、合作方背书、可立即提供固定容量。

## 12｜先做付费 POC，再按证据扩量

- **唯一叙事任务**：将客户的第一单变成风险、权利、质量与价格都可控的购买路径。
- **页面标签**：`当前可启动`｜付费 POC 是第一项可购买合作。
- **屏幕文案**：
  - 任务 001：客户与国曙共同锁定一个明确任务、目标本体/模型、场景、数据格式与成功标准。
  - 门槛一｜样本验收：金样本、拒收字典与联合验收通过。
  - 门槛二｜权利/授权：采集对象、场景、访问、保存、删除与交付使用范围明确。
  - 门槛三｜可复现性：人员、设备、场景与任务协议能够稳定复跑，差异可被记录和处理。
  - 门槛四｜价格/结算：合格单位、返工阈值、交付版本、结算依据和责任分界确认。
  - 付费 POC 后的选择：扩量、调整任务包，或停止；由证据而非预设承诺决定。
- **必建图**：任务 001 → 样本验收 → 权利/授权 → 可复现性 → 价格/结算 → 扩量/调整/停止。四个可视门槛必须清晰，扩量路径须标为“证据触发”。
- **证据与阶段**：U03、U06、U07、U14、C10；`当前可启动`。
- **禁止误读**：不写固定价格、承诺必然扩量、把 Agent 自动化或第三方认证当作当前前提。
