## 人机分工判据
这件事需要出现在物理世界或动用人的信任关系吗?需要→人(拍板/签字/见客户/要 spec/政府高校/算力);不需要→agent(调研/构建/验证/沉淀/守状态)。

## 五条协作协议
1. **人说目标,不写需求**——上下文由 SSOT+记忆自动供给,人不用交代背景。
2. **交付必带证据,验收看证据不看声称**——对人对 agent 同样生效。
3. **决策点弹窗,人只做选择题**——agent 把选项/代价/推荐整理好再问。
4. **纠错一次,固化终身**——人指出的错必须变成红线/规则/记忆,不劳人说第二遍。
5. **异步为常态**——人给方向即可走开;agent 留痕于 git+工作台;人不当传声筒(系统间搬信息用 SSOT/合约通道)。

## 网页融合协议(7/21 补充)
这次页面混乱的根因不是"内容不够",而是把不同用途的页面互相替换,造成内部、外部、团队三套入口口径漂移。以后按下面协议执行:

1. **旧骨架优先**:Fable5 做的 `/embodied/`、`/embodied/public/`、`/embodied/team/` 是基线。新增内容先找插槽,不能直接重写页面结构。
2. **三入口不互替**:`/embodied/` 是内部作战地图,`/public/` 是唯一外发能力册,`/team/` 是团队工作台。三者可以互相链接,不能互相覆盖;旧 `/partner/` 只做 301 兼容跳转,不维护实体页面。
3. **同源增量**:3 天闭环、Paris demo、世界模型分析、基地 SOP 等增量先沉淀成状态/打法/证据,再分发到对应页面。
4. **浏览器验收**:curl 只能证明 HTTP 可达,不能证明页面可用。上线前必须至少做 Chrome 截图;关键交互要能点,点不了就写明未验证。
5. **团队可感知**:任何页面改动如果团队工作台没同步,等于没交付。人不像 agent 能自动吸收上下文,所以每次增量必须写进 `OPS_STATE` 或速记卡。
