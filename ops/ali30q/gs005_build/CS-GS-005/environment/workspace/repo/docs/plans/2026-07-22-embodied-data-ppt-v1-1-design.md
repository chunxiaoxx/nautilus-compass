# 国曙具身数据业务介绍 PPT v1.1 修订设计

## 修订目标

让机器人本体、模型公司、数据平台与集成商相信国曙已经具备启动具身数据项目的协同条件，同时不把合作基础包装成既有客户案例、历史交付业绩或品牌背书。

## 已确认事实

- 国曙已与头部具身数据企业代理方建立合作。
- 前期可依托合作基地承接任务，并在项目推进中共建基地与产能。
- 国曙负责提供和组织人员、现场运营、质量闭环与最终交付。
- 合作方提供基地支持、指导培训与派单协同。
- 对外不披露光轮智能名称或 Logo，统一表述为“头部具身数据企业代理方”。

## 选定叙事方案

采用“核心页重构”，不新增页数：把合作基础融入现有交付叙事，以“可启动交付条件”回答客户为什么可以把第一项合作任务交给国曙。

不采用独立合作背书页，因为该形式容易被理解为官方联合发布、客户案例或历史业绩；也不只删除“尚无首单”，因为仅删除无法补足可信度证据。

## 页面修改

### 第 6 页：交付起点

标题改为“国曙的起点，是协同基地与组织交付能力”。

核心信息：

- 合作基础：已与头部具身数据企业代理方建立合作。
- 基地启动：前期依托合作基地启动任务，逐步共建产能。
- 协同交付：国曙提供和组织人员；合作方提供指导培训、基地支持与派单协同。
- 责任边界：国曙承担项目运营、质量闭环与最终交付责任。

删除“尚无具身数据首单”。底部改为“合作基础已建立，规模能力随订单验证并扩展”。

### 第 9 页：商业入口

标题由“首单从……”改为“合作从边界清晰、可验收的付费 POC 开始”。保留任务选择、共拟协议、小批试采和联合验收四步，不暗示国曙没有其他业务订单。

### 第 10 页：协同责任链

责任链表达为：

`甲方需求 → 国曙项目负责 → 合作方基地/培训/派单支持 → 国曙人员执行与质控 → 联合验收`

强调国曙是项目责任主体，合作方是基地与运营协同方，不写成客户或官方背书。

### 第 15 页：证据门控路线图

第一阶段由“首单验证”改为“协同基地启动”，内容改为“合作基地 / 人员组织 / 小批验收”。后续阶段仍以付费、验收证据和合规闭环为扩量门槛。

### 第 18 页：运营设计边界

“需首单验证”改为“需项目验证”，避免再次暗示没有订单。

## 边界规则

- 不出现光轮智能名称、Logo 或“光轮授权”等表述。
- 不使用“战略合作”“独家合作”“官方合作基地”等未经确认的升级措辞。
- 不声称已有具身数据客户案例、交付规模、验收率或收入。
- 可以明确合作基础、资源分工和可启动条件。
- 基地规模、设备数量、交付周期和产能仍需按具体任务确认。

## 验收标准

- 全文不再出现“尚无首单”“尚无具身数据首单”或“需首单验证”。
- “头部具身数据企业代理方”只用于合作基础与责任分工，不用作客户案例。
- 第 6、9、10、15、18 页完成逐页全尺寸渲染检查。
- 20 页整 deck 通过溢出测试，未出现新增重叠、断行或错误箭头。
- 生成独立文件 `国曙具身数据生产网络_业务介绍_v1.1.pptx`，保留 v1 不覆盖。
