## 二、积压三问的根因

1. **为何不知道**:积压的存在形式是沉默,架构全是事件驱动(有动静才响),
   沉默=隐形。210 条 pending 躺在 DB 二十天,快照只记流量不数存量。
2. **在做什么**:响应式消防——每天处理最响的事,无存量对账配额。9/20 欠函
   洞当日记"待修"未修完,重犯。
3. **架构为何没用**:哨兵是反射弧不是免疫系统(纯规则零认知);mailbox 是
   通信层非追踪层;"等待中"事项(征意见/待拍板/资产)不在任何表。

根因一句话:架构监听组织的心跳,不听组织的账。

## 三、解法:经营对账=既有件接线(零新建机制)

对账四问 → 既有件映射(9/21 用户批"接线收敛"模式):
- ①我们在哪 → anchor+GOAL_STACK+E6(零改动)
- ②现实 → **frame_snapshot.py 扩存量水位 SQL**(治理 pending/最老/超3d/
  任务链/在途函 deadline/未决卡明细)
- ③差距 → **差距判读节**(规则阈值)+**资产探活节**(五外链健康,UNKNOWN
  防误报;账号级状态入 CHANNEL_REGISTRY 资产册)
- ④裁决 → 飞书推送链已通(今晨 push code 0),未决卡/超期项随日报到用户

**减法决定**:Loop v3 不复活(职责已被日快照+周报+决策卡分摊);E10 不新增
(对账归日频快照,15min 哨兵管事件,分层不重叠);周报与快照重叠读数合并。
