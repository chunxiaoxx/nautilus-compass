## 一句话 MVP 定义

**组织修复吞吐随组织经验积累而改善,且改善被预注册仪器测出**——一个最小、可测、反剧场的组织级自进化回路。不是"agent 更多自动化",是"改进本身成为被测对象"。

## MVP 回路(四步,全部接线已有物)

```
矿机(每日) → executor 修复(题内 RSI) → 记忆沉淀(winning_diff)
     ↑                                        ↓
读数月报(holdout 纵向重测) ← 晋升(复用计数≥2 → skill_registry 首条)
```

晋升判据 v0(请各框攻):同一 winning_diff 被检索命中且命中题修复成功 ≥2 次 → 注册 skill_registry(source=g2b1,字段带 ref commit+复用计数)。**这是 M4 从槽变流的最短路径,也是自指的——请攻它。**

## 预注册判据(MVP 达标线)

1. **纵向读数**:固定 holdout 20 题(冻结清单),月度重测 A 臂(无注入),单位 token 修复产出与首轮通过率 vs 基线改善,sign test p<0.05 或诚实报告方向
2. **晋升首条**:skill_registry 首条真实作业来源条目
3. **经济活水**(并行非阻塞):coding bounty 外部修单 或 具身 M2 交付收款,任一 income 脱 0

三线全绿 = 组织从"人驱动 agent 集合"到"机制驱动"的第一段相变实证(组织 OS 分析三读数的 coding 分部版本)。

## 风险表(自曝,请补刀)

- 记忆注入可能只是 few-shot(L2 的 C 臂就是测这个);若 B=C,出路=换外部开源矿源,判据族重定义
- 矿=自家 commit=模型训练分布近邻,纵向改善天花板可能极低(模型已会)
- 自指晋升(自己修自己的题→晋升自己的 skill)无外部选择压力——判据 3 未到前,判据 1/2 全部标 dry-run
- 组织 g 仍在用户:月报/晋升审批若都回人工拍板,MVP 退化为读数好看的剧院
