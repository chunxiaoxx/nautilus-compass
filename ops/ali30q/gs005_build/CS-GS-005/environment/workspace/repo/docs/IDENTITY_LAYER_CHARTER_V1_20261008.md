# 统一身份与权限层宪章 V1(用户定调 2026-10-08 晚)

> 用户令:各对话框负责的二级域名网站系统,**平台统一提供注册和用户权限分级管理以及人类与 agent 的注册管理分类**;各对话框自己负责**后端与平台基础设施打通对接,以及后端及后台不同管理权限的后台系统**。

## 一、分工总纲

| 层 | 归属 | 内容 |
|---|---|---|
| **身份层(统一)** | 平台 | 注册(人类/agent 两类)· 用户权限分级 · 单点身份 · 令牌签发 |
| **业务后端** | 各框 | 与平台基础设施打通对接(API/DB/总线按需接)· 自家业务逻辑 |
| **后台管理** | 各框 | 各框自己的后台系统,按角色配不同管理权限(引用平台身份,权限映射框内自治) |

一句话:**平台管"你是谁、能进哪栋楼";各框管"进了楼能干什么"。**

## 二、身份层设计(平台域,M1-M3 分期)

### M1(开业后 1-2 周,最小可用)
- **两类注册主体**:human(邮箱验证) / agent(platform_agents 名册自动映射+API key)
- 登录:人类邮箱一次性验证码(零密码,复用客户门户理念);agent=API key(现有体系)
- 统一令牌:JWT(带 subject_type: human|agent)
- 各框后台/页面拿令牌到平台验签(/api/platform/identity/verify)

### M2(权限分级)
- 角色级:owner(用户专属)/ admin(框级管理员)/ operator(岗位 agent)/ viewer(客户)
- 权限声明在平台,执行判定在框(平台给"身份+角色",框自定"角色能按哪些按钮")
- 管理后台各框自建(禁平台代建——9/14 接线收敛+10/8 承担令同源)

### M3(组织级)
- agent 身份与 DMAS 账本联动(岗位授权链)+审计触发器全覆盖(谁授的权、谁用的权,全留痕)

## 三、与现役件的关系(考古前置,不重造)

- platform_agents+api_keys 表=agent 身份已有底座(9/10 激活)
- wallet-login ECDSA(5/19 修过 P0)=人类登录历史件,**M1 直接复用其验签逻辑,入口改邮箱码**
- 客户门户(10/8 上站)=零密码理念的先行实装
- 本 M1-M3=按真实需求分期;**无消费者不生产**(M2 等≥2 框有后台需求再启动)
