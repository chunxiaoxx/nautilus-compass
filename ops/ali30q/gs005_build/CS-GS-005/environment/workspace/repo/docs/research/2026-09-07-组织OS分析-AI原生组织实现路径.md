## 一、历程:同一目标的六次瓶颈假设迭代

用户定性(2026-08-30):从第一天起目标就是"AI 原生组织的组织 agent",DMAS→超级 agent→compass→蒸馏全是同一目标下的瓶颈假设迭代,不是方向变更。按瓶颈转移重排:

| 阶段 | 时间 | 假设的瓶颈 | 主攻物 | 转移节点(证伪/升维) |
|---|---|---|---|---|
| ① 多 agent 协作 | 3-5月 | 组织缺"手脚" | DMAS 任务平台(362 端点雏形) | 假成功工厂事故:agent 会跑≠有产出——缺的不是手脚是判断 |
| ② 记忆 | 6-7月 | 组织缺"经验沉淀" | compass(锚点/召回/drift);最小飞轮→PMF 定调 | 有记忆≠会用——缺外部选择压力 |
| ③ 能力蒸馏 | 7-8月 | 组织缺"能力增长管道" | FDE 三期/G2-B1 executor(9000010) | 9/2 定谳:瓶颈是燃料不是算法(蒸馏冷启动关闭,重启条件 10⁴⁺) |
| ④ 组织操作系统 | 8月底 | 各框孤岛,缺总线 | SSOT §⓪:四框集合体/六服务/对外 MCP(workbuddy)/git+mailbox | 8/30 三连拷问:组织内闭环=玩具,自指飞轮无外部 fitness |
| ⑤ 外部经济环 | 9月初 | 业务方向 | 具身数采+飞轮+第三方验证(9/2 方向锚);承运契约/一页纸/港区四中心 | 现行假设:经济活水是组织相变最后一闸,M2 收款=income 脱 0 |
| ⑥ g 机制化 | 9/5-今 | 组织评估/门控全在用户本人 | 挖矿定时化/决策卡/默认生效条款/verdict 机械判据/M1 配方 | 进行中 |

元规律:**每次迭代都在把"人的隐性职能"换成机器可执行机制——换到今天,最大的未替换项是拍板本身**(9/2 用户 12 项动作积压=组织 g 全压在一人身上的死锁实证)。

## 二、组织算子表(单体学习系统的第五列)

flywheel《四系统底层算子对照》列了 ICL/SSI/Waddle/compass 四列单体学习系统。组织(nautilus)是第五种介质——多主体共识介质:

| 算子 | 组织层实现 | 成色 |
|---|---|---|
| 写 | git commit / 函件 / DB 行 | ●(共识开销极高) |
| 读 | mailbox 扫描 / 架构档案(ARCHITECTURE.md) / 全框快照 | ◐(全貌是分布式资产,无人天然拥有——解法=判断时视野匹配判断半径,9/3 定谳) |
| 选 | 三道闸 / turf 纪律 / 注入面预算 | ●(组织最强算子;三次 turf 越权全是"选"的失败被拦) |
| 合并 | SSOT / 拍板登记处 | ◐(拍板散落是已知病) |
| 忘 | 9/2 注入面清洗(561→25 行) | ○(唯一一次,靠人工;缺读侧按龄降权) |
| 组合 | 四框 × 六服务 | ● |
| 评估 | verdict / income / 决策卡 | ◐(自报未全封) |

**组织特有、前四系统没有的三个算子:授权**(谁有权写谁的地址空间;turf 事故=非法写)、**协商**(函件协议:deadline+2h SLA+默认生效)、**结算**(reward/income/capability 三张表=组织自进化经济的结算层,呼应 flywheel"准入判据=自进化经济的结算层")。

组织版 stability-plasticity 与单体相反:单体怕写新冲旧,组织怕**记忆单调增长×注入面预算有限**(提示词过度工程化事故即组织版可塑性过剩)。解法=按判断半径动态装配注入面(读门控)。

## 三、实现三步论与三个相变读数

**核心论点:AI 原生组织不是"把人换成 agent 的组织",而是把组织操作系统原语从人际协议(会议/邮件/口头拍板/职级信任)换成机器可执行协议(函件协议/任务语义/分层记忆/授权矩阵/结算表)的组织。**

- **第一步 介质改造(已基本完成,耗时六个月)**:记忆/协作/资产/决策全落 agent 可读写介质
- **第二步 g 机制化(进行中,当前主战场)**:高频人工仲裁降为机制。已落地:默认生效条款(承运契约逾期即生效)、机械判据(M1 三环节禁 LLM 自评)、挖矿定时化(矿源补给无人化)、决策卡(拍板异步留痕)。三道闸(方向生杀/对外承诺/签字支付)永久人类专属不是借口——那是特权指令保护,其余仲裁都该往机制迁
- **第三步 经济闭环(未开始,最硬的闸)**:income 活水→结算表流动→capability 有真值→skill 晋升有判据→组织第一次拿到外部选择压力。此前一切自指改进都是 dry-run(8/30 定谳未过期)

**三个相变读数(判断"实现了"的判据,全部用已有读数,不设新机制):**

1. **income 脱 0**(M2):经济环闭合
2. **skill_registry 首条真实作业来源条目**(M4):晋升管道从槽变流,自进化环闭合
3. **g 机制化率**:拍板积压(现 12 项)趋势下降 + 默认生效/机械判据承接比例上升:组织吞吐与用户个人带宽脱钩

三者全绿 = 从"人驱动的 agent 集合"相变为"机制驱动、人只在特权级出现的组织"。

## 四、coding 领域率先实现 AI 原生组织

### 4.1 为什么是 coding(不是具身/写作)

flywheel 论证"g(评估)是所有学习系统共同欠拟合算子"。各领域的 g 成本:

| 领域 | 评估器 g | 现状 |
|---|---|---|
| coding | **pytest/CI 白送**:机械 verdict、分钟级周期、git diff 完美介质 | g 已存在 |
| 具身 | 要造(计量协议/判据库),硬件在环,周期天级 | 飞轮在造(下一站) |
| 写作 | g 是人(读者),无法机械化 | 不适用 |

**coding 是唯一"g 白送"的域**——所以在 coding 域,AI 原生组织的全环(发单→执行→评估→结算→晋升)可以全部机械化,不需要先造秤。这是"率先"的结构性原因,不是偏好。

### 4.2 已有活体部件盘点(全部已落地,不是设想)

| 组织 OS 组件 | coding 域实现 | 状态 |
|---|---|---|
| 任务语义 | tasks 表 task_type=CODE | ● |
| 矿源 | g2_b1_bug_miner + daily_miner 每日 09:30 五仓增量挖矿(幂等防重) | ● 9/7 定时化 |
| 执行体 | 9000010 executor,多模型臂轮换(k3/minimax/glm_plan/deepseek) | ● 21 天连续运转 |
| 评估器 | RED 预检(no_red/fixture_broken 分类)+ 重跑测试 verdict | ● 9/7 战果:58 题,PASS 17/实修通过率 63%,全天 273k token |
| 反馈协议 | 回滚明示+empty_diff 明示+dump 仓外(三轮死法修复) | ● 9/5 三修 |
| 熔断 | fail_streak ≥5 跳过+24h 半开+原子写 | ● |
| 结算 | reward 字段在;现烧平台自有 token(内部定价=自指,只能当 dry-run) | ◐ |
| 晋升 | winning_diff 沉淀在 evidence 堆积;skill_registry 空 | ○(有槽无流) |

注意关键事实:**g2b1 修的就是组织自己的历史 bug**——矿源是四仓自己的 fix commit,9/7 的 17 个 PASS 全是 compass/platform/fde 域真实修复。这就是"AI 读组织的过去、改组织的现在"的最小活环,coding RSI 雏形已在跑。

### 4.3 "AI 自己编程自己"的严格表述与边界

必须区分两个层次:

- **权重级 RSI**(agent 改自己大脑,SSI/TTT 路线):stability-plasticity 未解,行业开放域零实例,不是我们的路径
- **组织级 RSI**(agent 改组织的机制、代码与数据分布,不动权重):与 compass/Waddle 外置路线同构——写地址空间是 git/DB/skill 库(稀疏可寻址、无灾难遗忘、可审计可撤销)。**我们押的是这层**

组织级自我编程的分层权限(已在实践中):

| 层 | 内容 | 权限 | 实证 |
|---|---|---|---|
| L1 自己的工具层 | 挖矿器/hook/脚本 | agent 自由写 | 挖矿定时化=当日 agent 写 agent 的基建 |
| L2 组织业务代码 | 各仓 bug 修复 | 机械 verdict 通过即收(worktree 内,不自动 push) | g2b1 58 题/17 PASS |
| L3 核心机制 | 部署/宪法/对外承诺 | 人审(三道闸) | turf 三次拦截 |

RSI 的严格形态(承接 flywheel 定谳):**不是 agent 改自己的代码,是改自己的数据分布**——组织每修一 bug→winning_diff 沉淀→同类 bug 二次命中更快→修复率/单位成本随时间改善。这才是可测的递归。

### 4.4 缺的三件(从雏形到 AI 原生组织 coding 分部)

1. **外部 fitness(最关键)**:付费修单源。内部 token 预算=自指定价,只能当 dry-run。候选:开源 bounty(GitHub 赏金 issue)/企业存量代码维护合同/G2-B1 原始设计的 reward 语义激活。**income 脱 0 因此有两条并行路径:具身 M2(等设备到货)与 coding bounty(不等硬件,启动成本≈0,平台已在跑)**——后者是组织经济环的低成本先行解
2. **晋升闭环**:winning_diff→复用计数→skill_registry 首条(M4 同款判据)。先跑内部闭环读数:同类 bug 二次命中率
3. **防 reward hacking 纪律**:测试是自家的=可作弊面(agent 改测试让它过)。必须:reference fix 的 test 文件对 agent 只读,diff 触碰 test 文件即拒;判修复用 holdout 题集(固定不进矿,定期测纵向通过率,防"矿越吃越简单"的假进步)

### 4.5 RSI 判读纪律(防自嗨,与 8/30 定谳一致)

- 环内指标:同分布 holdout 上,turn-N 修复率/成本单调优于 turn-1(既往已有跨 3 repo/两套验证器的 turn-2>turn-1 实证)
- 纵向指标:单位 token 修复产出随时间上升(须 holdout 校准,新矿 63% vs 旧矿 87.5% 不可直接比——矿难度不同)
- 外部指标:付费修单成交+复购(唯一真值)
- 任一"我们在自进化"的声称,必须挂在这三类读数上,否则视为剧场
