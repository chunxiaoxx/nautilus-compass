## 0. 要解决的问题(一句话)

supervisor 检测到生产停机(ZERO)后只能发 telegram 给用户——**机器在喊,没人在听**(executor 停机 8h+ 无人响应实证:跨框异步信箱模式在单方忙时瘫痪)。

## 1. 设计原则

- **查资产**:管道两端全是现成件——supervisor(检测+状态机+telegram,在产)/ fde_dispatch(open→claim→report 生命周期+reserved_for 具名门,在产)/ a2a 派单模式(8/27 刚修好)/ 能力账本(④刚上线,可路由)。**只缺中间的翻译器(~60 行)**。
- **机制护栏**(三大教训关):
  1. agent 自修复会腐蚀(8/28 V5 教训)→ 值班任务只允许**白名单动作**(诊断/重启/重跑),禁改代码、禁动数据、禁对外发函;
  2. 自报不算 → 任务完成判据 = **verified_total 恢复增量**(三曲线自动复核),非 worker 自报 done;
  3. 幂等 → 同一连续 ZERO 期只派一次,全局最多自动派 3 次(超过即升级用户,不再自动)。
- **授权分级**(8/27 用户定):自动派单属 B 级(框自决+事后报备),但**首次实弹必须 A 级用户确认**。

## 2. 组件规格:ZERO→Dispatch 翻译器(supervisor 内新增)

- **触发**:状态机进入 ZERO 的那一轮(非每轮)。
- **动作**:
  1. 写 dispatch 任务:task_uid=`zero-response-{UTC时间戳}`,description 含诊断指令清单(查进程/查最后 verdict 时间/查 unit 状态/指定重启目标)+证据指针(report jsonl 行);
  2. reserved_for 留空(FCFS,任何注册 agent 可 claim;P2 再接能力路由);
  3. telegram 文案升级:"ZERO 已自动派单(任务 ID,白名单动作),2h 内未恢复将再次告警"——用户知情但不必须响应。
- **白名单动作**(worker 可做):读日志/查进程/`systemctl restart` 指定 unit(初版仅 nautilus-backend 及 executor 相关)/重跑指定只读脚本。
- **验收判据(预注册)**:派单后 2h 内 verified_total 恢复增长 = 成功(翻译器自动复核);未恢复 = telegram 第二条升级用户。
- **fail-soft**:翻译器任何异常不影响监督主链(检测/报告照常)。
- **死因分类(8/28 考古修正,P0 起内置)**:ZERO 时先分类再出指令——
  - `YIELDED`(让位):V5 仓 48h 内有实验类 commit(distill/dpo/loop/train 关键词)→ 指令=**升级函件**(向资源 owner 要 ETA/并行决策),白名单重启无效;
  - `CRASHED`(故障):无实验迹象 → 指令=诊断+白名单重启;
  - `UNKNOWN`(无数据) → 指令=诊断,不重启。
  实证依据:executor 8/25 停机 2.5 天死因=蒸馏/RL 轮让位,重启类动作对此无效。

## 3. 分期

| 期 | 内容 | 前置 |
|---|---|---|
| P0 dry-run(半天) | 翻译器上线但**不真派**:只写 dispatch 行 + telegram"建议派单(附指令清单)" | 用户 A 级批准本设计 |
| P1 实弹 | 真派单,首个值班 worker = 现有注册 agent(白名单动作内) | P0 观察 1-2 个真实 ZERO 事件指令质量合格 + 用户 A 级拍板 |
| P2 扩面(台阶二全套) | 其他红信号接入同一管道(矿红→续矿/QC 红行→训练料/对账分歧→复查) | P1 成功判据达成 |

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| worker 重启错东西 | 白名单+初版仅 2 个指定 unit;非白名单动作 claim 端拒绝 |
| 翻译器炸了监督 | fail-soft 隔离,监督主链不带派单 |
| 循环派单(重启又停) | 连续 ZERO 只派一次+全局 3 次上限,超限只升级不自动 |
| 动了 V5 turf(executor 是它的) | 派单即写知会函(事后报备制);P0 期间零接触仅观察 |

## 5. 征询

- **用户**:本设计批准 = P0 开工授权;P1 实弹另批。
- **V5**(一句话回函即可):值班 worker 白名单内重启 executor 相关进程,贵框是否接受?(不回默认接受——executor 停机损失实证 > 重启风险)

## 6. 判据(台阶二衔接)

P1 成功 = **第一笔"机器检测→机器派单→机器执行→曲线恢复"的无人闭环** = 台阶二判据"机器提案被机器执行并验证"达成。
