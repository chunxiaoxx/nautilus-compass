# 出题配方 V2·组合语义×业务口径(2026-10-25 深夜·平台方法论复盘)

> 根因:机制冷度路线(qwen修穿四连)与行为级单点坑(F01/025满分)双双失效——**训练数据几乎覆盖一切"有名字的错误模式"**,知识层与单点推理层无法产生稳定区分度。
> 升维:甲方出题人真正在测的是**语义组合层**(多模块交互的涌现行为)与**业务意图层**(字面需求vs业务真实意图的缝隙)——这两处无法靠背与模式匹配通过。

## 判定一道题好坏的试金石

**资深工程师看完题面,能否说出"真正的难点是XX,模型大概率折在YY"?**
- 说得出→题目有确定的区分机制→合格
- 说不出→题目在抽卡(靠模型当日状态)→不合格

## 配方 V2 结构

```
题面三层:
  表层任务:一个"看起来简单"的修复/实现需求
  中层陷阱:修复必然触碰的两模块交互边界(组合语义坑)
  底层考验:一个业务口径二义性(文档字面 vs 业务真实意图)

UT 四层锚定:
  L1 表层功能正确(防废品)
  L2 修复点本身正确(防不做)
  L3 组合边界行为正确(区分度主来源)
  L4 业务后果正确(区分度次来源)

反幻觉内嵌:误导草稿埋在"业务理解"层(模型对技术不自信会验证,对业务理解过度自信不验证——顺从即暴露)
```

## 三类歧途设计(替代旧"冷机制/行为坑"分类)

1. **组合语义歧途**:A、B 模块各自正确,组合产生两者都没有的副作用(CS-007:审计缓存拖住栈帧引用→GC 不回收)
2. **业务口径歧途**:代码完美实现字面需求,但与业务真实意图有缝(含税/净额、快照时点、重投计笔)
3. **错误前提歧途**:题内嵌"看似专业的分析草稿",模型顺从即坐实(技术细节会验证,业务自信不验证)

## 素材矿脉(采集方向升级)

**旧**:扫"单点事故"(某个 API/函数的坑)
**新**:扫"**模块交互边界的真实故障**"——65 表+362 端点的组织真实系统中:
- A 模块输出进入 B 模块时变形/丢失/时序错的事故
- 两边口径定义不一致的对接缝
- "各自都对、合起来错"的真实案例

每一处=一道 CS-007 级的题矿。

## 验证

- CS-007 逆向:跨模块生命周期涌现——天然 V2 样本,实证达标(唯一 1/34)
- 平台 CS-018 反例验证:单文件解析+明确规则=V1 失败形态(qwen 满分)
- 明晨试水 2 题(B+C 分层案)若含组合边界→按 V2 复核题面
