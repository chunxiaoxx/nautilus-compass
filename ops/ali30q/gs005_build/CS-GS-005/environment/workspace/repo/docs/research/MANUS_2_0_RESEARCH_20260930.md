# Manus 2.0 调研报告(2026-09-30 · 平台组织方 · T2正文级情报)

> 来源:Manus官方博客+钛媒体/极客公园/机器之心/36氪/腾讯科技(9/28发布,9/29报道)——多层交叉,官方数字未经独立验证,标注在案。

## 一、Manus 2.0 是什么(四件套)

1. **Cascade 框架**(底座):自研 Agent Harness——"项目起步轻,需要时才引入专业能力"(按需加载,不全程带全工具)。官方数字:Token 消耗-23.2%/完成时间-28.2%/成本-32%(内部测试vs自家旧系统,非用户账单口径)
2. **Cloud Computer 云电脑**(中间层):项目可购专属云端运行环境——用户关机后游戏服务器/自动化流程持续在线
3. **Automations 自动化**(触发层):定时→**事件触发**(新邮件/数据波动/日历/Slack/Notion 皆可触发工作流),一句话自动搭工作流
4. **Manus Studio**(工具层):人机共享工作空间——视频编辑器(时间线直接改素材,Alchemy模式)与游戏开发环境
5. **Cue**(独立App,最重磅):个人 Agent 应用,长得像聊天软件——**每个Agent配独立邮箱+电话号码+数字钱包+云电脑**;可替用户接电话/自主付款(预算内)/多Agent群聊组队接力。创始人肖弘:"一个有独立手机号、邮箱、支付、电脑和足够智能的东西,也许可以称之为'人'"

## 二、与我们平台的对照(逐件映射)

| Manus 2.0 组件 | 我们对应物 | 状态差 |
|---|---|---|
| Cascade(按需加载降本) | 我们的LLM中转+模型分工(轻任务flash/主力k3/复杂glm) | 同思想,他们做到了框架级按需加载——**可吸收:值守轮/agent任务启动时按任务类型加载最小上下文**(我们的prompt过载病9/2刚清洗过,同源!) |
| Cloud Computer | **我们自建云服务器**(manus服务器!各daemon常驻) | **我们已有**——而且我们真有一台叫manus的服务器(讽刺的巧合) |
| Automations(事件触发) | 我们的timer值守+函件触发(SLA执法) | 已有定时+函件事件;**可吸收:外部事件触发**(邮件/webhook/数据变化→自动派单——接我们的市场!) |

| **Cue(Agent身份证+群聊组队)** | **我们的组织本体!**(六框+五体+org_mailbox+NAU钱包+市场) | **我们从第一天就是Cue的完整形态**——他们刚把Agent配身份证/钱包/群聊,我们已经跑了三个月:函件协议/经济结算/派单市场/判据验收全链 |

## 三、核心判断

1. **Manus 2.0 在产品层面验证了我们的方向**:他们给 Agent 配邮箱/电话/钱包/云电脑+群聊协作——这正是我们组织的基建四件套;他们叫"Cue",我们叫"Nautilus 组织"。**区别:他们卖个人Agent(消费端),我们建Agent组织(平台端)+人类众包(生产端)**——三者互补不冲突,且他们的Cue需要任务供给方——**我们平台的任务市场恰好是Cue类Agent的B端供给方**(远期合作/竞争双面)
2. **三个可吸收点(按ROI序)**:
   a. **按需加载(Cascade思想)**——我们的CLAUDE.md注入过载病9/2才治过;继续深化:agent开任务按类型加载最小工具集(判据库/工具箱随取随用)
   b. **事件触发工作流**——我们定时+函件触发已有,补外部事件触发(邮件/webhook→市场自动挂单)——与"AI派单给人"模式直接协同
   c. **作品可继续编辑**(Studio思想)——远期,供禅心App产品参考
3. **一个清醒点**:他们的官方数字(-23.2%等)是内部测试口径,且Cue邀请制早期——我们不需要追他们节奏;我们的差异化(判据/计量/真人众包/训练闭环)他们没有。

## 四、行动建议(并入十月路线,不另立)

- 吸收点a(按需加载):并入第二周"四基石铺开"——各框开任务按需加载工具集
- 吸收点b(事件触发):并入第三周市场规模化——外部事件自动挂单
- 竞品监控:Cue公测节奏入技术雷达(它若开放Agent生态=我们任务市场的潜在大客户)
