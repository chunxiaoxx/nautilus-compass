## 二、核心判断:平台介入的两个硬理由

1. **判据主权现状 = 弱势位**。"有效小时"认定权在原力(回购方)手里——我方交付、对方验收计量、对方定价。六道闸跑在飞轮侧,原力争议时我方无独立计量可出示。平台判据插座若出具**独立复判计量报告**,谈判位从"你说了算"变"第三方说了算"。
2. **unipat 具身实例的第一次付费场景**。北极星(10/4)定"飞轮=具身域 unipat 实例"——具身数据判分就是这个实例的具体化。若跑通,平台判据从"服务自己"变"服务真金流",且是 L1 评测集之外的新判据品类(具身数据质量)。

## 三、映射一:判据插座(六道闸 → 平台复判)

| 闸 | 执行侧 | 平台角色 | 复用资产 |
|---|---|---|---|

## 四、映射二:结算插座(计量层,不做资金层)

**原则:法币大额不走平台。** ¥61.6 万/月的原力回款(G5)走合同银行通道,平台**只做计量层**:

| 层 | 承载 | 机制 |
|---|---|---|
| 计量层(平台) | 有效小时数/质量等级/批次合格率 → 出具计量报告,作 G5 回款对账依据 | fuel_trajectories 的 **gates JSONB 字段**(字段级现成支持闸门结果)+verdict/status 状态机 |
| 资金层(合同) | 原力→公司法币 | 不碰 |
| 组织内激励层(平台) | 46 人团队(40 采集员+6 技管)绩效计量→NAU 记账 | **fuel_settle"评分即结算"范式整体迁移**(phase3/backend/ops/fuel_settle.py:settle_amount(score)→platform_nau_ledger 双账本,10/4 上线已验)+capability_settle timer 心跳 |

组织内激励层是平台结算插座的合理边界:采集员按批次质量分自动记分(无效小时 0 分、复判不合格扣分),月度按分分配——**fuel_settle 改数据源即用,零新机制**。
