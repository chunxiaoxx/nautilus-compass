## 1. 定位

**unipat-in-agent:为 DeepSeek/Xiaomi 及各 agent 研发企业做 agent harness 一站式「基准评测 → 能力提升」平台。**

核心判断:agent 能力的天花板在 harness(结构)而非模型(2026-09-14 用户定调,"问题从来不在模型");市场上 harness 评测无中立一站平台,数据集质量参差无机器判读。我们已实证的独特资产=**评测判读体系(不可写面+δ判读+held-out 宪法)×真实任务数据飞轮(四验门+判分结算绑定)×训练闭环(SFT/GRPO+复考锚)**三环,今天市场上三环齐备者空缺。

## 2. 系统总架构:一大系统+小系统群+涡轮增压

```
┌─────────────────── 大系统(平台底盘,唯一对外门面)───────────────────┐
│ 身份/NAU结算/函件总线 A2A/榜单发布/判分服务入口/Assay登记·判据·复核      │
│ 网站系统(本白皮书 §6,唯一新建 UI,三步切片)                            │
└───────────────────────────┬───────────────────────────────────┘
                            │ API/函件(一切接线收敛于此)
   ┌────────────┬───────────┼───────────┬────────────┐
   v5 框        compass 框   flywheel 框   soul/v7/kairos
   执行引擎+数据  评测判分侧    具身数据 unipat  组织生态框
   (harness 主体  (基准/判据/   (数据出售先例)   (外围,弱耦合)
    +飞轮承载端)   榜单/协议)
   └────────────┴───────────┼───────────┴────────────┘
                外部:飞轮对话框(客户触达/社区/HF 通道)
```

**涡轮增压机制(大小系统之间的数据泵)**:小系统(agent 框)在真实任务中产生轨迹(执行)→大系统固化(四验判读+入池+结算,判分-结算绑定防刷)→合格数据反哺训练引擎→复考锚验证提升→更强的执行臂接更难的任务。飞轮每转一圈,小系统能力与大系统数据资产同时增值——这是 10/05 单日入池 70 行、pass 率 36%→60% 的机制本质。

## 5. 评测体系(判分侧资产,compass 主责)

- 四锚登记(RSI_BENCH_PANEL):B1 周考/B2 VB 长程/B7 J2-RL 三门/B4 周报,口径冻结+死期纪律
- 不可写面:判分永不闭环自评;机器判(发射计数/三门/官方判分器)
- δ 判读:最小可判差 2.1pp,差值<δ 记 flat 禁声称改进
- held-out 宪法:改进样本永不入测池(交集=0 实证)
- E1 金标:flywheel sealed 双包 1000 行(506+400 帧,14 对 footnote 校准)
