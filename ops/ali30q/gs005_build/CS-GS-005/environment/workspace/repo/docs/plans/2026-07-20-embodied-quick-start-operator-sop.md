# 3 天闭环启动：操作 SOP（给执行者看的最小版本）

## 0. 你现在先做什么（今天 0-2 小时）

1. 打开：`docs/embodied-3day-cockpit.html`  
2. 点「内部版本」核验字段：  
   - pass@5、重复一致率、E-D 一致率  
   - 失败样本是否有回流  
3. 点「复制当前视图 JSON（同源数据）」保存一份到会议文件  
4. 用「3 分钟讲法」对外做首次汇报（不讲算法细节）

## 1. 术语一键降噪（给非技术方）

- **pass@5**：同一题重跑 5 次里有多少次达标。  
  可理解为“重复测试稳定性”。
- **A/B/C/D/E**：不是 5 个系统，是 5 个阶段。  
  语义解释 → 场景解释 → 仿真解释 → 交互解释 → 真实轨迹先验对齐。
- **Ego 先验**：给模型一个“人在现场看到的参考轨迹”，帮助它少走偏路。
- **失败回流**：模型没答好不直接删样本，而是当训练任务。

## 2. 对内/对外口径不分叉执行规则

1. 同一个字段对象（pilot\_id）只维护一份 JSON。  
2. 外部页只读展示可复核指标，不展示内部判罚明细。  
3. 内部页保留全部失败模式与修订历史。  
4. 每次会前先执行：`状态 = 内部/外部视图` + `JSON 已导出`。

## 3. 客户讲解模板

### 3 分钟版本（只给决策者）
1. 问题：行业废片率高、验收口径乱。  
2. 方案：用一条样板打通 5 个阶段闭环。  
3. 结果：pass@5、重复一致率、E-D 一致率均达标。  
4. 风险：把 `薛美雪_001` 这类失败样本放入失败回流。  
5. 下一步：在你确认后扩到 3 条样板线。

### 15 分钟版本（给合作方）
1. 演示闭环图（A/B/C/D/E）。  
2. 演示 Paris 导览 Demo（JSON 可改）说明“生成式交互”能力。  
3. 展示失败样本处理过程（不是隐藏，而是复用）。  
4. 给出下一周期验收门槛（见下方）。

## 4. 第 1 周目标（对里程碑）

### 目标门槛（硬约束）
- `pass@5 >= 0.8`  
- `重复一致率 >= 95%`  
- `E-D 一致率 >= 90%`  
- 失败修订有记录，有回流任务入队

### 里程碑
- 第 1 天：现有样板通过会签  
- 第 2 天：固定一条失败样本修订完并复跑  
- 第 3 天：导出对外材料 + 对内规则更新报告

## 5. 你现在可以直接抄的会签清单

- 是否接受 3 天闭环作为“首里程碑”  
- 是否同意失败样本不作为否决，而是训练输入  
- 是否同意只扩 1 → 3（非一次性大规模新增）  
- 是否指定 1 名对接负责人（对外）与 1 名复盘负责人（对内）
