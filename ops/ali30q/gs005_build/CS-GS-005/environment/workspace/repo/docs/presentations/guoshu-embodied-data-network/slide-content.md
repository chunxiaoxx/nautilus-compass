# 国曙具身数据生产网络：逐页内容基线

版本：v1 content baseline / 2026-07-22  
主版本：16 页通用定向投递版  
受众：机器人本体企业、具身模型企业、数据平台/集成商  
目标动作：进入“任务定义 → 付费 POC → 联合验收 → 规模复制”的商务与技术讨论

全局标识：

- 【当前】国曙当下可承诺并承担责任。
- 【可配置】具体项目需按任务与合作资源配置。
- 【路线图】尚未成熟，仅表示建设方向。
- 主页面避免复杂免责声明，使用页脚小标签和措辞区分阶段。

---

## 01 封面

**标题**：让真实世界的工作，成为机器人可学习的经验  
**副标题**：国曙具身数据生产网络｜定制采集、质量协议与规模化运营

**叙事任务**：从“人力外包”升级为“经验生产”，建立全篇核心隐喻。

**屏幕文案**：

- REAL WORK → TRAINABLE EXPERIENCE
- 面向机器人本体、具身模型与数据平台

**视觉**：工人/作业者第一视角双手与机器人末端执行器形成左右呼应，中间以数据轨迹连成一条“经验流”。  
**证据**：C01/C02  
**阶段**：【当前】定位；“生产网络”用“正在构建”。  
**禁用**：客户 Logo、订单数字、平台已建成。

## 02 问题重定义

**标题**：具身智能的下一道瓶颈，是可验证的任务经验

**叙事任务**：把客户从“缺视频/缺小时”带到“缺有效任务经验”。

**屏幕文案**：

- 视频很多 ≠ 动作可学
- 轨迹很多 ≠ 任务可复现
- 数据交付 ≠ 训练可用
- 缺口：任务边界 × 动作语义 × 质量证明 × 人机对齐
- 机器人需要的不是世界被看见，而是工作如何被完成。

**视觉**：一条原始视频流经过四道结构化关口，最终成为可训练任务片段；失败样本从侧面被剔除。  
**证据**：E01/E02/E05/C01  
**阶段**：外部研判，标注“国曙研判”。  
**禁用**：声称行业已一致认同或任何数据必然提升模型。

## 03 五个核心研判

**标题**：五个判断，决定未来的数据生产方式

**叙事任务**：体现国曙不只卖执行，而是对行业供给结构有独立判断。

**屏幕文案**：

1. 数据单位将从“小时”走向“合格任务片段”
2. 人类第一视角经验将成为机器人数据的重要补充
3. 基地与分布式不是二选一，而是控制与覆盖的组合
4. 验收协议将比单一质量分更重要
5. 自动化首先改变运营闭环，而不是替代所有人工

**视觉**：五条由近到远的工业跑道汇入一个“TRAINABLE EXPERIENCE”核心节点，避免卡片阵列。  
**证据**：E01-E08/C01  
**阶段**：国曙研判。  
**禁用**：把研判写成既成行业事实。

## 04 供给架构

**标题**：基地解决控制，分布式解决覆盖  
**副标题**：两套生产方式在同一任务协议下协同

**叙事任务**：回答“为什么既要基地又要众包”。

**屏幕文案**：

- 基地：设备一致｜环境可控｜任务复跑｜标定校准
- 分布式：场景长尾｜自然分布｜行业触达｜供给弹性
- 共同底座：任务规范｜设备协议｜权限边界｜统一验收

**视觉**：左侧“控制塔/基地”，右侧“城市与行业节点”，中央由统一任务协议贯穿，底部回流质量数据。  
**证据**：E03/E04/E06/E07/U09  
**阶段**：【路线图】总体架构；具体项目可选择单一模式。
**禁用**：已建成全国网络、已有基地规模。

## 05 国曙方案

**标题**：国曙正在构建订单驱动的具身数据生产网络

**叙事任务**：第一次完整回答“我们做什么”。

**屏幕文案**：

客户任务书  
→ 任务拆解与验收共识  
→ 设备/场景/作业者配置  
→ 采集、回传、标注与质检  
→ 合格任务片段交付  
→ 复盘沉淀与规模复制

一句话：以订单为起点，以验收为边界，以组织网络完成现实世界的数据生产。

**视觉**：一条带反馈回路的生产线，订单与验收是起点/终点，拒绝“平台功能大而全”的 UI 图。  
**证据**：U03-U10/C02  
**阶段**：【当前】订单驱动与项目责任；【可配置】资源组织；【路线图】自动化网络。  
**禁用**：自研平台已上线、全流程自动化。

## 06 我们是谁

**标题**：国曙的起点，是协同基地与组织交付能力

**叙事任务**：用已建立的合作基础和清晰分工证明项目可以启动，同时不虚构客户案例或规模产能。

**屏幕文案**：

- 合作基础：已与头部具身数据企业代理方建立合作
- 基地启动：前期依托合作基地开展任务，逐步共建产能
- 协同交付：国曙提供和组织人员；合作方支持指导培训与派单
- 项目责任：国曙承担现场运营、质量闭环与最终交付责任

页脚：合作基础已建立，规模能力随订单验证并扩展。

**视觉**：一名“交付负责人”站在中央，连接设备、场地、作业者、技术合作方与客户验收人。  
**证据**：U02-U08/U14-U15/C04
**阶段**：【当前】。  
**禁用**：具身项目案例、已交付客户、组织规模直接映射成具身产能。

## 07 竞争引擎

**标题**：四种能力，共同构成国曙的竞争引擎

**叙事任务**：明确核心竞争力与差异化。

**屏幕文案**：

1. 任务工程：把自然语言需求变成可执行、可验收的动作协议
2. 组织运营：把人、场景、设备和合作方组织成稳定班组
3. 质量运营：从采前校准到拒收原因回流，而非末端抽检
4. 场景扩展：基地控制 + 分布式覆盖，逐步进入行业现场

中心结论：国曙竞争的不是单点设备，而是“把现实工作持续变成合格数据”的运营系统。

**视觉**：四个偏心齿轮围绕一个合格任务片段旋转，每个齿轮只有一个关键词与一条结果。  
**证据**：U03-U10/C02-C06  
**阶段**：【当前】项目责任与组织能力；其余按项目验证、逐步沉淀。  
**禁用**：把四项都写成成熟平台能力。

## 08 产品单位

**标题**：客户购买的是合格任务片段，而不是临时人力

**叙事任务**：定义可收费的最小交付单元与双方责任。

**屏幕文案**：

每个任务片段至少回答：

- 做什么：目标、对象、起止状态
- 怎么做：动作步骤、自由度、传感模态
- 在哪里做：场景、光照、干扰与安全边界
- 如何证明：完整性、同步性、成功条件、拒收原因

结算原则：以双方确认的验收单位与通过结果为准。

**视觉**：一个任务片段的“解剖图”，从视频/传感信号拆出任务、动作、环境、质量四层。  
**证据**：E02/E03/E05/U06/C03  
**阶段**：【当前】产品设计；具体字段【可配置】。  
**禁用**：固定价格、固定接受率。
