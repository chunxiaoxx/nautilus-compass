## §0 拍板锚(已定,不征议)

1. 用户 10/7 口述三点:网站=当前最大短板;**组织即平台=基础设施**,平台有自己的门面;各框工作=长在基础设施上的产品体系,对外=平台的产品体系。
2. 网站必须体现「基础设施+产品体系」架构,不是单框文档堆(v5 全站 md 墙已拍回退为产品页之一)。
3. 双层模型(10/7 用户纠偏):L1 基础设施只迭代不重写;L2 各框产品=长在 L1 上的插件。
4. CUDA 生态位(10/6):底座+五插座(出生证/流量/结算/信用/总线),交付即入册候选、过审即曝光。

## §2 目标架构提案(两层,供表决基稿)

**门面层(平台装订)**:根站=基础设施叙事(五插座/两域一组织)+产品体系导览+两外壳;产品页群=各框 own 内容、平台装订(信箱总线提交+渲染器统一视觉);每产品页带闭环 CTA(提测表单/询价/HF 导流),不是文档墙。

**服务层(各框子域/管道)**:bench(评测提测)/data(具身)/compass(记忆层)三子域已成型;管道三步切片按白皮书 §6 演进(Step2 10/20 预演);API 面(api.chunxiao.wang+提测 API M1 已 live)与 A2A/MCP/DMAS 总线在「开发者」页统一披露。

## §3 六项表决议题(每框逐项表态:附议/反对+理由+补充)

1. **域名体系**:三子域模式确认(bench=评测/data=具身/compass=记忆);是否新增子域(如 zenmind 陪伴智能、soul 治理)?命名规范(产品线名单域 vs 平台根路径)?
2. **装订模式**:平台中心装订(各框交 md/HTML,平台渲染挂载,统一视觉)vs 各框自部署子域(平台只做导览链接)?或混合(门面装订+服务层自部署)?
3. **技术栈**:零新栈(md→HTML 渲染器路线,现 flywheel 自动化)vs 引轻前端栈(模板引擎/组件化)vs SSR?判据=10/12 可达性+维护成本+观感上限。
4. **闭环入口**:每产品页 CTA 统一规范(表单/邮箱/提测 API 直连);收单路由到 org_mailbox/assay submissions/邮箱三通道怎么定?
5. **关联系统呈现**:DMAS/A2A/MCP/API/中转站在网站的暴露度(开发者文档页?状态页?);自研 agent 用自建中转站的关系如何在「基础设施」叙事呈现?
6. **节奏**:10/12 V1 门面最小集(首页+产品页群骨架+两外壳刷新,平台 5 天冲刺排期已认领)vs RFC 全量结论后再动;V2(Step2 发单台 10/20 等)路线确认。
