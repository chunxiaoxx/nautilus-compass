# 具身数据生产网络 PPT：13 页重构设计

日期：2026-07-23  
状态：用户确认叙事原则，待进入实施计划  
目标读者：机器人本体企业、世界模型/VLA 企业、数据平台与集成商

## 1. 设计决策

新版不按“本体版”和“世界模型版”拆成两套销售故事。它们共同需要的是：把真实世界任务转化为可进入训练、验证与迭代闭环的数据资产。

对外定位统一为：

> 面向具身本体、世界模型与数据平台的真实世界训练数据生产伙伴。

核心闭环：

```text
真实任务
→ EGO 获取场景、任务语义与人类工作流程
→ UMI 获取更接近机器人末端的操作示范
→ 统一任务协议、质量验收与数据权利
→ 世界模型学习环境与任务先验
→ 本体/策略学习动作并在机器人上验证
```

本体企业更关注动作可达性、任务成功和 rollout；世界模型企业更关注真实场景、多样性、长流程和任务语义。这是同一数据包的不同价值，不应分裂为不同商业模式。

## 2. 两层模型

不得再混用两层概念：

| 层级 | 要回答的问题 | 内容 |
|---|---|---|
| 采集协议层 | 采什么、怎样形成训练数据 | EGO、UMI、时间同步、任务语义、动作表示、人机对齐 |
| 供给与运营层 | 在哪里采、谁采、怎样控质和扩量 | 协同基地、分布式众包、垂直行业现场、任务包、准入、验收、结算 |

“垂直行业”是高价值真实任务和场景的入口，不是第三种采集技术；同一条 EGO 或 UMI 路线可在不同供给单元中执行。

## 3. 可信合作模型

PPT 的目的不是证明国曙已经具备成熟大规模网络，而是让甲方相信：将第一项具体任务交给国曙做付费 POC 的技术、交付、合规和责任风险可控。

信任链：

1. 任务理解：按客户本体、模型、任务、场景和验收边界选择 EGO、UMI 或组合。
2. 技术可审查：明确设备/传感、同步、标注、质量门槛、人机对齐与限制条件。
3. 交付可承担：国曙组织人员、现场运营、质量闭环并承担项目交付责任；合作方提供基地、指导培训和派单协同。
4. 风险可分段：先以付费 POC 固化任务规范、金样本、拒收字典、数据权利与联合验收，再决定扩量、改版或停止。
5. 资产可合规积累：仅经授权沉淀任务协议、培训、工具和质量方法，不默认复用客户原始数据。

## 4. 当前事实与路线图

### 当前可表述

- 已具备协同基地启动条件；国曙组织人员并承担项目运营、质量闭环和最终交付责任。
- 可从客户付费需求出发，围绕指定任务、设备/传感器、场景、格式和验收要求组织定制 POC。
- 可与客户共同定义任务协议、样本包、拒收字典、版本与联合验收机制。

### 只能作为条件触发的建设路径

- 自有 EGO 双目/多传感帽、UMI 采集套件。
- 分布式众包准入、派单、质量、结算网络。
- 垂直行业在岗、低打扰批量采集。
- Agent 自动引导、预标注、自动验收、质量护照、第三方认证和数据市场。

禁止把“国曙体系积累”表述为具身数据项目业绩、成熟基地或现成规模产能。

## 7. 三个必须新建的图

1. **具身训练闭环图**：真实任务 → EGO → UMI → 统一 episode → 世界模型 / 本体策略 / 机器人验证。
2. **二维生产网络图**：横轴 EGO / UMI，纵轴 协同基地 / 分布式众包 / 垂直现场；当前 POC 与后续路径必须用不同状态标识。
3. **门槛式合作图**：付费任务书 → 基地金样本 → 可复制任务包 → 众包或垂直现场扩量 → 统一验收回流；每一步标注验收、授权、可复制性与结算门槛。

## 8. 成功判据

- 主册 13 页，不保留内容重叠的抽象愿景页。
- 客户可在前 6 页理解：为何需要两种数据路线、为何需要三类供给组织。
- 客户可在第 10–12 页判断：交付物、责任、质量、权利和第一单合作动作。
- 当前能力、可配置资源、路线图能力严格分层；不产生客户案例、规模、自动化或模型效果的未验证承诺。
