二、整体架构(四层引擎)

┌─ RSI 进化拱顶:消费三流外部信号 → 改进 → 下次更好 ──────────┐ │ 🔴 fitness = QC verdict + 买方验收 + 真$ · 非内部自评 │ ├─ 三流:业务流 · 信息流(verdict-bus)· 财务流(缺口) │ ├─ 原生 AI 能力七件(职能全 agent · 人 = 作者+终验+HR+PM 三席) │ │ 项目管理 · 生产组织 · 培训咨询 · 审核验收 · 全流程编排 │ ├─ 引擎+数据模型(已证转):双 producer = agent(线3)+人(线1/2)│ │ surface 适配器:飞书表(#1·已用)· 未来网页/桌面 │ └──────────────────────────────────────────────────────────────┘

人类席位仅 3 个:HR 招聘 · 项目管理 · 专家作者+终验。其余职能全 agent。

三、入口与角色(一张图)

┌──────── 飞书多维表格(唯一面·零安装)────────┐ 运营/PM(内部·人)─▶│ FDE派活表:填任务 / 分派 / 看进度 │ │ │ 领域专家(外部·人)▶│ 我的派活行:领活 / 看验收标准 → 亲笔 → 提交 → 看QC│ │ │ 买方(外部·保密)─▶│ 交付物表:隔离·只看成品·🔴绝不见内部 │ └──────────────┬────────────────────────────────┘ │ 平台 poller(每5min自驱·已LIVE) ┌──────────────┴── 平台引擎(后台·agent自驱)───┐ │ 派单→认领→产出→QC→结算 · soul/compass/v5 agent│ └────────────────────────────────────────────────┘

核心:人只在飞书操作(零安装零学习);agent 后台自驱;平台 poller 是飞书↔引擎的桥。运营另可看 control-plane 控制面(引擎/verdict/RSI · 内部网页)。

四、内部:运营/PM

入口:飞书派活表 + control-plane 控制面。

  1. 派活:飞书填一行(task/线/类目/L级/指派专家/验收标准必填/状态=待派单)。
  2. 自动:poller 每 5min 读「待派单」→ 派单+具名认领(防 agent 抢)→ 转「已派单」。不用手动 dispatch。
  3. 盯进度:派活表视图看每行阶段。
  4. 卡点+结算:管理 agent 推提醒;运营决策优先级、确认应付。

✅ S1 LIVE 进度看板/管理agent/结算 = S3/S5。

五、外部:领域专家

入口:飞书(收邀即用·零安装)。

  1. 进场 → 飞书派活表看自己的行。
  2. 看验收标准列(什么算合格/什么被拒)。
  3. 领活(改「已领取」)。
  4. 亲笔写题/教案(副驾驶只结构化校验,不代写)。
  5. 飞书提交 → 看逐项 QC 反馈 → 改 → 过。
  6. 过审结算。

✅ S1 领活 提交→QC 反馈环 = S2。

六、外部:买方(保密)

入口:单独「交付物」飞书 base(物理隔离)。

买方只看成品交付物表 + 验收。

🔴 绝不可见:派活表 / QC 内部列 / 避坑语料 / "我方=伊洛" / 其他专家稿。

🔴 未建 S3 + 引擎设计 §E 权限分层。

七、推广(诚实定位)

战略锚:客户获取 defer(买方已有)。推广重心 = 供给侧招募专家,非找客户。

A 专家招募(主):垂直社区/前同事/KOL → 飞书做一道试做题过 checklist_scorer = 客观筛(不靠简历)→ 发一页纸进场。

B 能力展示(谨慎):平台网页展示能力与方法论。🔴 FDE 业务保密:不宣传具体甲方、不晒买方交付。

九、培训咨询落地

核心:培训内容自动来自 QC 反馈——不单独编教材。专家被打回的 reason = 避坑知识 = 教材。

  1. 避坑库:QC fail-reason → ingest compass 记忆 + 飞书避坑表。
  2. 副驾驶答疑(咨询):agent 基于 RUBRIC+避坑库 recall 答"怎么写/为何被拒"。
  3. 样板:RUBRIC=方法论底本 · data_001 录屏=操作样板 · 首篇教案=范文。

载体=飞书。🔴 未产线化(S2/S4 的活)。

十、项目管理落地

定位:给专人 PM(人)的 agent 服务台——人决策,agent 备数据/提醒/催办。

  1. 进度看板:飞书派活表视图(看板/甘特·谁领什么/卡在哪)。
  2. 管理 agent:扫流程出提醒/卡点告警/周报(复用 control-plane+企业微信)。
  3. 结算视图:每专家应付 + token 成本归集。

复用飞书多维表格+control-plane 不自建。🔴 S5(没数据的面板=装饰,放最后)。

你是谁

金融 / 法律 / 医疗 / 工程 / ML 研究等领域资深专家(从业 ≥3 年,做过影响真金白银或重大决策的事,有一份可脱敏代表作)。

你做什么

  • 出题:写一道你领域"≥8 小时专家级、AI 做不了"的真场景难题 + 隐性验收点。
  • 教案:亲笔写一篇领域知识正文(1k–30k 字),沉淀你的专业知识。

为什么是你

这些内容 AI 写不了、网上搜不到——只有你的真实专业经验能产出。AI 帮你加速(结构化、查漏、排版),但 核心内容必须你亲笔(客户会跑 AI 检测,拼凑的整批拒收)。

怎么开始(全程飞书 · 零安装)

  1. 收邀请 → 打开飞书「FDE派活表」。
  2. 看到指派任务 + 验收标准(什么算合格)。
  3. 点「已领取」认领。
  4. 按标准亲笔完成 → 飞书提交。
  5. 看逐项反馈 → 修改 → 通过。
  6. 通过即结算。

副驾驶帮你什么

自动生成检查清单、按客户格式排版、解析附件、查完整性和 AI 味。帮你达标,不替你写。
