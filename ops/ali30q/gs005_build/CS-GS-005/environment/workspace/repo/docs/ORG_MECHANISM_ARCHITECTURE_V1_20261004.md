# 组织机制架构 V1(2026-10-04 · 平台起草 · 承用户定调:组织核心目标=RSI)

> 用户定调:火力方向不是要点;要点=把平台和组织机制梳理清楚,**把各对话框的核心主线和功能沉淀到平台机制上**,避免再次漂移、再次犯错、降低成本。
> 本文件=机制架构正本:目标函数、三层架构、每框主线沉淀对照、RSI 写回循环、缺口与补缺提案。

## 〇、核心目标函数:RSI(正名,不再被任何复盘摇摆覆盖)

- **组织核心目标 = RSI(递归自我改进)**。正身 = 真值成本压缩器(宪法第十二条):合法性来自"获取真值与提升智能的成本持续下降",不来自自我评价。
- **两判据(2026-10-02 用户认同,本文件首次配度量设计)**:
  1. 同类错误复发率 → 0;
  2. 同类任务成本递减(token/人工/时间)。
- **外部收入 = RSI 的外部真值源**(7/17 论纲:income 不涨=改进没价值)——是 fitness 读数,不是目标替代物。三口径经营读数(外部收入/判官交付/决策数据集)均服务于"改进是否真实发生"的验证。
- 10/3"零价值周"定谳的 RSI 解读:一周全部产出,既未沉淀为复发率↓/成本↓的机制,也未推动 fitness 读数——**目标函数两侧同时落空**。防两极翻转:不得因本周否定内部机制的必要性,也不得再以内部件吞吐量替代改进本身。

```
┌─ 目标层(改框=用户专属) ──────────────────────────┐

│ 北极星(首笔外部付费+11月重估) · RSI两判据          │
└──────────────┬───────────────────────────────┘
┌─ 行为层(平台运营的组织机制) ─────────────────────┐
│ 函件协议(mailbox/ack/2h SLA/分层)                  │

```

| flywheel | 具身数据飞轮+QC 管道 | 飞轮章程V1(域正本)·形态门·fuel Issue 派单流 | QC 锚/判据/报表正本在 flywheel 仓,平台无独立读数位 |

**沉淀的定义**(防"文档不是肌肉"复发):一条主线算"已沉淀到平台机制",当且仅当——①有平台侧可读的判据或读数;②有触发器(timer/hook/loop 步骤)让它周期性被执行或被检查;③有台账落位。三者缺一,只算"写在框自己的文件里"。

## 三、RSI 写回循环(现状)

```
错误/漂移发生 → 教训提炼 → 免疫册入册(强制位) → 物理闸/hooks → 下次自动拦截 → 复发?
                    ↑______________________________________|
缺口A:复发率无度量——免疫册只记"教训",不数"同类再犯";
缺口B:成本递减无度量——同类任务(部署/判分/发函/修洞)无成本基线记录,无法对比递减;
缺口C:沉淀靠会话自觉——教训是否"在工作路径上"取决于当轮 agent 是否 recall(10/2 定谳的病根)。
```

## 四、补缺提案(最小仪器,三条)

1. **复发率账本**:免疫册每条目加"复发事件"计数列;组织日报月度一行"本月复发 X 起/涉及 Y 条"。判据:复发率→0(RSI 判据①的仪表)。
2. **成本账本**:同类任务二级分类(部署/发函/修洞/判分/触客物料),每次记录耗时+人工介入数;同类 ≥2 次自动出对比行。判据:同类成本递减(RSI 判据②的仪表)。
3. **教训上路径**:三道物理闸(10/2)从平台 settings 推广为各框可选配置——免疫册条目生成时强制回答"这条教训的物理触发器是什么",无触发器不入册。

三件均为度量仪器(判据读数呈用户,不改变任何框的目标与权限)。按 9/2 冻结令"新机制默认拒收",**三条等你批**;批哪条建哪条,不批不建。
