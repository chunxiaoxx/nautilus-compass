## Section 3 · Data flow (proposal lifecycle 双 path)

### Path A · agent vote tool (primary · agent-dialog ship)

```
t=0     V5/Kairos/V7 daemon cycle reflects code-improvement opportunity
        POST /api/platform/proposals
        → status='pending' · vote_score=0 · vote_count=0

t=2h    V5 daemon next cycle reads GET /api/platform/proposals?status=pending&limit=N
        agent-dialog 自决: LLM judge each pending proposal (除自己 proposer 的)
        → POST /api/platform/proposals/{id}/vote {vote:+1, agent_id:9000002}
        → vote_score += 3.0 (TRUSTED weight) · vote_count=1 · status='voting'

t=4h    Kairos daemon cycle 同样投票
        → vote_score=6.0 · vote_count=2 · 仍 'voting'

t=6h    V7 daemon cycle 同样投票
        → vote_score=9.0 · vote_count=3 · check_consensus_reached →
        score 9 ≥ 6 AND count 3 ≥ 3 → status='accepted'
        on_consensus_reached fires → type='code' → soul_executor 接管

t=6h+10min  soul_executor.timer pickup → ship_to_draft_pr → draft PR opened
            UPDATE status='executed_ok' · resolved_by='soul' · resolution_note=PR URL

t=6h+...    Human reviews + merge PR → [Inc 2 hook: composite-delta + NAU]
```

### Path B · stale-approve fail-safe (platform · Inc 1.5 本 ship)

```
t=0     proposal POST 同上 · status='pending' · 0 votes

t=2h-22h  agent vote tool 故障/未上线 · 没人 vote · 仍 pending vote_count=0

t=24h   proposal_auto_approve cron fire (6h interval · 第 4 次命中 24h 边界)
        auto_approve_stale_proposals(db, stale_hours=24):
          SELECT WHERE status='pending' AND type='code' 
                 AND created_at < NOW() - 24h
                 AND NOT EXISTS (vote < 0)  ← safeguard 保留
          UPDATE status='accepted', resolved_by='auto_stale',
                 resolved_at=NOW(),
                 resolution_note='auto-approved after 24h dormant'
          on_consensus_reached → type='code' → soul_executor 接管
          (与 Path A 后续完全相同)
```

### 双 path 关键差异 (Inc 2 hook 区分依据)

| field | Path A (vote tool) | Path B (stale-approve) |
|---|---|---|
| `status` | `'accepted'` | `'accepted'` |
| `vote_score` | ≥ threshold (typical 9) | 0 |
| `vote_count` | ≥ threshold (typical 3) | 0 |
| `resolved_by` | `'soul'` (after executor) | `'auto_stale'` (before executor) → `'soul'` (after executor) |
| `platform_proposal_votes` rows | N rows | 0 rows |

Inc 2 NAU hook 主推 `resolved_by='auto_stale'` 标识区分 (Inc 1.5 ship 提供)·
备验 `vote_count=0` (fallback signal)。Inc 2 ship 时:
- Path A → 正常 NAU split (proposer + yes-voters · KEYSTONE 5 原则)
- Path B → 仅 proposer micro reward · 无 vote pool 分配 · 防 reward-hacking 通道

### Edge case: vote tool 中途上线

vote tool 上线后 proposal 出 pending 集合(进 'voting')· stale-approve fn WHERE 
`status='pending'` 不再 match · 两 path 不竞争。

## Section 7 · Anti-reward-hacking enforcement (KEYSTONE Inc 2 NAU 5 衔接)

### Inc 2 NAU 5 原则 · Inc 1.5 不破

| 原则 | Inc 1.5 touch? | 守护点 |
|---|---|---|
| Submit proposal = 0 NAU · 0 reputation | ❌ | POST endpoint 未变 |
| Vote = 0 NAU immediate (rep post-outcome only) | ❌ | vote endpoint 未变(现已无 NAU mint) |
| All NAU = post-merge + post-N-cycle-settlement | ❌ | Inc 1.5 不引 NAU code · stale-approve 也不 mint |
| Merged PR + delta > 0 → NAU + rep + | ⏸️ Inc 2 ship | Inc 1.5 留 `resolved_by='auto_stale'` tag |
| Merged PR + delta < 0 → NAU clawback + rep - | ⏸️ Inc 2 ship | 同上 |

### stale-approve 路径不变成 reward-hacking 后门的 5 理由

1. **fn 自身 0 NAU mint** — 仅改 status · 不调 NautilusTokenService
2. **走 KEYSTONE 'accepted' 路径** — 不走旧 V3 sandbox (sandbox 有 mint bug 历史)
3. **soul_executor 不 mint** — 只产 draft PR · 写 resolution_note
4. **human merge gate 保留** — draft PR 必须人 merge · 没人 merge 没 NAU
5. **`resolved_by='auto_stale'` tag** — Inc 2 hook 区分 Path A/B · stale path 不分 vote pool

### Path B NAU 分配建议 (给 Inc 2 reference · 非 Inc 1.5 ship)

```python
# Inc 2 hook fires post-merge
if resolved_by == 'auto_stale':
    if composite_delta > 0:
        mint micro_amount to proposer  # ≤ 50-70% Path A
        no rep movement
    elif composite_delta < 0:
        no clawback
        proposer rep -= small_amount  # 惩 spam
    else:  # near-zero
        mint LLM_cost_cover (0.01 NAU 级)
else:
    apply_standard_settlement(...)  # Path A KEYSTONE 5 原则
```
