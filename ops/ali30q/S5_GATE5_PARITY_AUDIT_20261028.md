## 二、判定器/数据缺陷发现(独立审查主产出)

1. **[实测] 双命名变体双计**:`_s5` 同存 `kimi-k3-ark_run*` 与 `kimi-k3_run*`(canon 归并后同堆一 list)。实测 CS-102/103/301/401/507 kimi 均得 8 轮、CS-301 opus 5 轮、CS-001 opus 9 轮。gate5 的 ②整体通过率=全过运行数/20 分母硬编码 20,运行数>20 时可算出 >100%;⑤qwen passrate 分母同样失配。**46 题中仅 5 题五模型齐,齐的 5 题里 4 题 kimi 双计**。
2. **[实测] git 合并冲突残留混入数据**:CS-003 等 8 个 `*_result.json` 正文含 `<<<<<<< HEAD`/`=======` 冲突标记(v5 worktree 未解决冲突即落盘),load() `except: continue` 静默丢弃、零留痕。
3. **[实测] 无批次纪律**:gate5 load() 不做批次区分,重跑新旧读数混算一池——违反同仓 collect_for_quickscreen.py F-009 已立的"同题读数按 mtime 聚簇,默认只取最新批"纪律(审计 A1 根修成果未同步到 gate5)。
4. **[实测] ①先拦设计掩盖部分可判条件**:CS-518 的 qwen/opus/kimi 判读数据齐(③④⑤理论可判),但①不过即整体 return"不可判"。对拍/验收场景下会隐藏真实缺口位置。

## 三、修复建议(候裁定,不擅改判定器正本)

- load() 增加:同模型同 run 号取 mtime 最新一份 + 丢弃留痕(bad_file 清单入输出)+ 判读轮数≠4 时显式告警;
- kimi-k3-ark 变体件去留候 v5 定(若 ark 线已废,应清理历史文件而非靠 canon 兜底);
- CS-003/CS-518 补齐判读格式数据后方可重做 E 节对拍(补数坐标归 v5);
- v5 worktree 内 8 件冲突残留文件需 git 侧清理后重生成。
