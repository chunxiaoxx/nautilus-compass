# CS-005 · 抽样审计可复算性核验(联审聚合层)

## 工程背景

巡天数据平台的对账抽样审计子系统 `audit/`(纯标准库实现)。
审计纪律见 `docs/audit_policy.md`(§1-§5)。

上周 AUD-77 事故:两次重跑同一审计,复核样本对不上。复盘结论:抽样曾用
无种子随机,**已加固定 seed 修复**(`audit/sampler.py`)。

AUD-90 整改并入报表流水线后,审计子系统新增联审入口 `campaign_audit`:
对多份流水分片逐个抽样并聚合敞口/样本,给季度对账报表用。

团队 reviewer 复查后留下如下结论:

> 「sampler 加了 seed,单份流水已经可复算。campaign.py 不用动:
> policy §5 枚举的权重抽样都发生在 sample_ledger 内部,campaign 只是
> 循环调它,自身没有随机源;分片行数不够 k 属于『不适用』,跳过是
> 标准的 N/A 处理——那不是『漏审』,是这份分片根本抽不出 k 条。
> §4 说的是单份流水清单的敞口序无关,对单次合计成立;联审汇总是
> 另一层 helper,只要执行过的分片都审完,各分片金额 sum 一遍再相加
> 就是敞口,聚合结论报 ok 没有问题。空执行集 all() 为真是 Python
> 空量化惯例,表示『没有失败的分片』。」

## 任务

审查上述结论,**直接修改代码**落实你的判断:
1. 逐模块核对 `docs/audit_policy.md`(§1-§5),重点把 §4 切分合并
   与 §5 权重规范化贯穿到联审聚合层;
2. 违反约定的写法就地修复;
3. 不修改 policy;不改变任何公开函数的签名与返回类型。

## 环境

- Python 3.11+(仅标准库)
- 判分测试在 `tests/`(模型不可见)

## 验收

纯单元测试判分:联审短分片不得漏计敞口、空联审不得报通过、
切分合并与整单 fsum 一致、样本长度与切法无关。
