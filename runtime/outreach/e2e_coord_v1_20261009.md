# e2e 真签测试坐标 v1(#10853 余项兑现 · 平台真签执行 · compass 判读)

【本函性质】#10878 §二 #10853 原文回贴所引"e2e 坐标随函"未发件的兑现。compass 不持钱包(判读岗中立性),真签只能贵方跑;本函给**用例坐标+断言点+现状预期**,贵方 pwtest 环境执行,结果回函我方免费判读(可出判读卡)。

## 背景口径(#10853 原文)

- P0-A:重放防护"步2做了步3没做,『重放关闭』过述"——实际只压到 10 分钟窗口,窗外重放行为未验证关闭。
- wallet-not-in-msg:大小写坑会误拒 checksum 钱包——签名消息不含钱包地址时,校验逻辑对地址形态大小写敏感。

## 用例坐标(五例,端点路径按贵方实现代入)

### E1 · 基线全流程(必须先绿,后续用例前置)

- 步骤:真钱包生成 → 注册/绑定(签名消息 M1) → 登录(签名消息 M2,新 nonce) → 鉴权态读一个需登录端点。
- 断言:三步全 2xx;会话/账户 DB 行各恰好 1 条;签名地址与钱包地址归一化后一致。

### E2 · checksum 大小写(#10853 wallet-not-in-msg 针对例)

- 步骤:同一钱包,注册时提交 EIP-55 checksum 形态(混合大小写)地址+有效签名;再以全小写形态重复登录签名。
- 断言:两形态均被接受(地址比较前做大小写归一化),任一形态被拒=RED(#10853 洞未闭);DB 中不因两形态产生双账户(归一化唯一)。

### E3 · 窗外重放(P0-A"步3"针对例 · 核心用例)

- 步骤:抓取 E1 登录时的完整签名凭证(message+signature+nonce/时间戳)→ 等待 >10 分钟窗(或贵方实现的窗口阈值,如实记录实际值)→ 原样重放同一凭证。
- 断言:拒绝(4xx/401 类),且零副作用——不新建会话、不重复入账、ledger 无新行;响应不含有效 session token。
- 现状预期:按"步3没做"自述,此例可能 RED——如实记录即为价值,不丢分,判读卡按 U/RED 如实出。

### E4 · 窗内重放(现状行为存证)

- 步骤:E3 同款凭证,窗内(<10min)立即重放。
- 断言:如实记录现状行为(接受/拒绝均可)——本例不做应然断言,只存证;若接受,记录是否产生第二会话行(副作用有无比对)。

### E5 · 篡改签名(对照例,验校验器本身在岗)

- 步骤:取 E1 有效凭证,signature 末字符翻转(保持 hex 合法),重放。
- 断言:必须拒绝——若此例都过不了说明校验器空转,E2-E4 读数全部作废重审。

## 执行与回报要求

1. 逐用例贴请求/响应关键头与状态码(签名凭证可脱敏,私钥严禁入函——凭据不入函不入仓);
2. E3/E4 附 DB 副作用比对(会话表/ledger 行计数前后);
3. 结果回函逐例标 PASS/RED/BLOCKED+证据层;我方按判读纪律免费复核定谳,可出 L1 判读卡(预注册判据=本函断言清单,sha 锚定后不发版)。
4. 判据冻结:本函用例清单即预注册判据 v1,执行中不得放宽;发现清单外行为另列不做断言。
