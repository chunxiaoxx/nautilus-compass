**Q1 Assay-Bench v0 还缺什么工程件**

BC1(9/27 发布)本身就是第一个可开源评测件:考卷+判分器+签名成绩单+
复算链+上墙五件齐。以它为基线,缺口四件:
1. **多被测系统适配层**(最大缺口):现只有 mem0 适配;要成为"评测件"
   需 mem0/Zep/Letta 三家统一 harness 接口(write→search→answer 三钩子)
   ——mem0_baseline 已是第一个适配器,模式可复制
2. **留痕 schema 统一**:raw_responses.jsonl 是雏形,应与 VerifyPack claim
   对齐(输入/输出/判定/版本四字段),复算才一键可跑
3. **verify 契约标准化**:verify_bc1.py 单文件 CLI 已接近"verify.py 极简
   契约",差输入 schema+三态输出+签名的接口文档化
4. **复算三步文档**:clone→跑判分器→对成绩单,写进 README

slot 洁净室:数字版薄(BC1 每题独立 qdrant 实例已做 80%,补端口隔离
+即毁);**具身版厚**——物理终态=环境快照+传感器读回两件,工程量大,
建议 v0 锁数字记忆域,具身另册(v1)。轨迹留痕 JSON 上面第 2 件已覆盖。

**Q2 独立标定与 judge-the-judge 并轨**

同一条线两段:**标定账记判绩(Ledger 侧),注册表发上岗证(Forge 侧)**。
- 判分器/验证器上岗须过标定门:标准集上假阳/假阴率达标才入注册表
- 判绩 30 案滚动窗口决定保岗/降权/吊销——与我 1056 号函评委票权
  加权同构(判绩好=票重 ↔ 判绩好=注册等级高),数据结构复用 Assay Ledger
- **红线:标定集不得由被标定者自出**(T7 反自指)——标准集来源=
  BC1 holdout 12 题+τ-bench 判因复核案,第三方工件

**Q3 命名:Assay**

三点理由:①资产已全挂 Assay 牌(Ledger/运营方/wall 签名 pubkey/BC1
发布页/X 帖文案/投流预注册),VerdictHall=全线重命名+链接断+新词重养;
②语义覆盖:Assay(化验/试金)兼容"测量/校准"(DCR 不是判决),VerdictHall
的法庭隐喻盖不住 C1;③撞名史教训:发布前需再查一次 Assay-Bench 查重
(9/17 七候选时 Assay 净,但"发布前 24h 再查"是我们的惯例)。

产品名一旦呈用户拍板,五件套对外一套话:Assay Bench/Audit/Forge/Ledger。
