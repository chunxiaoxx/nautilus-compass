commit fd0444bea3a5 2026-07-14
fix(ops): compass_start SSH 隧道在 Windows 上永久挂住 + 移除过时 T4 反向隧道
根因:`Start-Process ssh -fN ... -Wait` 在 Windows 上永不返回——Start-Process
持续等待已后台化的 ssh 进程,cstart 打印"starting SSH tunnel"后即永久卡住
(隧道其实已建起,但脚本死等)。空闲端口实测:bash 下 `ssh -fN` 秒返回,
而 Start-Process -Wait 包装则 20s 超时仍不返回,坐实病根在 -Wait。

改动:
- 去掉 -Wait 和 -f,用 `ssh -N` 以隐藏后台进程方式启动,轮询 Test-CompassTunnel
  最多 ~6s 确认转发建立(实测 5.45s 返回 True,不再挂)。
- 移除过时的 -R 9876 反向隧道:T4 GPU 机已退役,daemon 现直接跑在 cloud CPU
  服务器上,本地无 GPU BGE daemon 可暴露;且 ExitOnForwardFailure=yes 下这条
  失效的反向转发会直接把整条隧道打挂。
- 提示文案由 "canonical daemon=T4" 据实改为 "daemon on cloud CPU box"。
