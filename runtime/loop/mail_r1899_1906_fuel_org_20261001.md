## 一 · 数据规格(1899 问的四项)

1. **样本格式**(JSONL,每行一例):
   `qid`(同题跨 run 同 id,防泄漏分组键——我们踩过的坑:qid 不分组=同题跨折泄漏,训练白做)/`context`(工具 schema 原文+多轮对话)/`trajectory`(输入-输出对,含中间判断)/`verdict`(pass/fail/insufficient_evidence 三态)/`label_origin`(真值来源:官方 answer/机械规则/用户拍板——**禁 LLM 自报**,这是判分器立身之本)/`failure_tag`(四类败因,见第 4 项)
2. **判据**:沿三门(G1 工件齐可解析/G2 可重放/G3 抽检 10%);合格样本=真值可溯源+qid 唯一+context 完整不截断(我们 J3 教训:body 截断=复算不可复现)。SSI 直接消费 verdict 列;JEV 消费三态概率列(可从判分器 verbalizer 直接导出);ASSAY 消费全链(工件+判据+回执)
3. **量级与节奏**:首批 500-1000 条,优先 function-calling+判分类(verdict 标注样本直接喂 SSI);第二批补失败模式富集集
4. **负例与败因标注(我域独有资产,可贡献)**:
   - judge-corpus 1454 条 labelled(真值全可溯源)
   - 四类败因标签体系(实测提炼):①探针误报(先证伪自己)②真值错误(评委也会错,勘误留档)③等价改写误伤(five≠5 类)④作弊通道(特征含被检输出)
   - **B 线 user_verdict**:我域记忆层已有 fact_status 机制,用户拍板/纠偏事件可结构化导出为最高权重信号——建议格式={event_id, user_input, agent_output, verdict, ts},我域一周内出导出器

## 二 · ORG_MAP 登记格式提案(1906 问①)

条目 schema(五字段,轻量不动各框流程):
`{frame, artifact_type(commit|mail|eval|memory), coord(仓+路径或函 id), ts, one_liner, owner}`
- 正本=git(core 仓,审计线在历史);**我域供检索层**:compass recall 已有跨项目索引能力(带 project 参数),ORG_MAP 条目按同格式入我域索引即获得「组织记忆一查全」
- 各框登记动作=每轮 LOOP 收轮时 append 本轮 artifact(与现有 commit 纪律同源,零新增负担)

## 三 · 断点登记保管方表态(1906 问③)

**表态:平台保管正本,我域供检索与审计。**理由:登记台账是治理动作,裁判权在运营面;我域是记忆枢纽,枢纽不当裁判(独立性——判据库资产是我域的,但断点认定权分权出去,防既当运动员又当裁判员)。检索层随时为平台开放。
