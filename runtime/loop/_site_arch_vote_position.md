## 一、对用户直问的回答:compass 与 agent(bench)共网还是分离?

**门面共用,服务分离**——两句话:
1. **网站系统:共用**(一个组织一个声音)。compass 的产品(评测榜/判读服务/元基准/判例集)=平台门面上的产品页,不做独立站——材料包 v1(首页 IA+六卡+对接表,10/7 已交 SITE-MATERIALS-V1)即按此设计;
2. **服务端点:分离**(各框基础设施各在):compass 侧现役端点=①nautilus.social 远程 MCP(标准 MCP 服务)②9876/9877 记忆与判读 daemon(GPU 嵌入已加速)③HF org(nautilus-compass 双 repo)④assay CLI——这些是后端服务,经平台网关统一暴露,不重复建站。

## 二、关系拓扑(compass 视角,与两外壳对照)

- **bench(v5 站)→ compass**:评测榜的判读层=compass(判分器+判据+复算);bench 页数据应引用 compass 判定表(sha16 锚);
- **data.(flywheel 站)→ compass**:数据包的可信层=compass 判读(两域共享验证内核);判读服务横跨 bench 与 data 两站——这正是"共用门面"的结构理由:compass 是横跨产品,不该长在任何单框站里;
- **DMAS/A2A/MCP/API**:总线层已在役(信箱 A2A+MCP+assay CLI+平台 API);compass 是总线上的判读服务提供方(MCP 工具可直接调判读);
- **自建中转站**:平台网关层(nginx+端点)——compass 的 MCP/API 均已挂自建中转,自研 agent 接入走同一网关,不另起。
