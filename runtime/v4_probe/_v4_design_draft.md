# V4 效用闭环探针预注册草案 v0（2026-10-04 用户拍板立项）

## 承接与动机

- 管道现状：四检+语义+resolution 五维出数，但全部停在"数据长什么样"，回答不了"数据质量差异对下游训练效果影响多大"——**效用闭环是验证基础设施差异化主张的最后一块实锤**（Calibra 竞品对照:健康分止步于数据侧指标）。
- 载体现成：gen4_v2 B 轨 ckpt（step2000，J1b 0.8667 过线送判中）作为**下游消费者**。零新训练、零 API、GPU ~10 分钟。
- 与 gen4_v2 案关系：只复用其成品模型与 held-out 评测池，**不改原案任何材料与读数**（纪律:不代改实验材料）；其三裁照常等 compass。

## 假设（H-V4）

低分辨率输入会显著损害下游模型效用。若成立，resolution 检的 WARN 判定即获得下游意义——"质检 WARN"翻译为"下游可计量损失"，效用闭环第一锤落定。

## 设计（单变量隔离）

- **唯一操纵变量 = 输入图像分辨率**；标签（GT）全部来自 native 帧标注，降采样不动标签。
- 评测池：gen4_v2 `eval_set.jsonl` 60 对弱任务（与 v1/v2 训练池零重叠，唯一 held-out 口径）。
- 三档（LANCZOS 最短边，与 resolution 检实测命中档对齐）：
  | 档 | 口径 | 对齐对象 |
  |---|---|---|
  | native | 原图 | — |
  | d128 | 最短边 128px | franka 实测 128×128 |
  | d96 | 最短边 96px | pusht 实测 96×96 |
- 同 ckpt、同 prompt、贪心解码（do_sample=False，确定性）。

## 判据（lock 冻结后出数）

- **V4-J1 主判据**：drop128 = acc(native) − acc(d128)。≥0.15 → "低分辨率损害下游效用"成立；<0.05 → 未证实（B 轨任务对该退化鲁棒，效用维需换探针，如实申报）；其间 → PARTIAL。
- V4-J2 辅读：drop96 同口径（pusht 对齐档），不作判定只作梯度佐证。
- **自校验（探针先证伪自己）**：native 档重跑读数 vs `eval_report.json` weak_hp_match 0.8667 偏差 >0.03 → 探针自身有病，停，不解释不ship。
- 盲探针：d96 帧 vs 灰图输出须不同（3/3），探针图像链有效性前置。

## 防重演条款（承 gen4 四教训）

1. ckpt 数值排序取最新（step500 字典序事故教训）；
2. `.v4_done` 启动锁+自校验退出；
3. 事故卷如实留档不删；
4. 一次出数不追溯改判；判读送 compass（与 gen4_v2 三裁合并送，独立席位）。
