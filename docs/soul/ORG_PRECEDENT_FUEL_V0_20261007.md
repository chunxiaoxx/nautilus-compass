# ORG-PRECEDENT-FUEL V0 · 组织历史判例燃料自动化机制(2026-10-07 · 响应用户提议)

> 提议(用户):把整个组织的所有历史作为判例燃料,自动化机制。
> 判定:方向正确且时机已到——语料是全部模型升级线的总闸(7B/动态权重/原生化全挂 3000 触发),而组织历史是**天然带 ground truth 的判例富矿**。本档=机制设计+防污染护栏+落地路径。

## 一、为什么组织历史是判例富矿(不是流水账)

组织每天产生大量**"判断→执行→验证结果"三元组**,每个都是天然可复算样本:
- 预注册判断 → 实际读数(E-NACRE-1 判了 FAIL=一条"路由片在 1453 条规模不成立"的带结果判例);
- 自报 → 复算(RSI 环#1 复算抓 2 自报绿=两条"这种自报会翻车"判例);
- 决策 → 后果(502MB lazy 决策→三天后堵车=一条"lazy 无增量下半场会堵"判例);
- 勘误/审计发现/值守崩溃修复(d3eb4e67 前的四发三崩)……
**组织每一次失败与修正,都是"什么做法会失败"的可复算证据。** 三天≈数百事件,一个季度≈数万——攒 3000 触发 7B 将从"月级"变"周级"。

## 二、机制设计(v0:采集→抽取→判定→入册,四段全自动化)

```
[采集] 五框会话日志/queue.md/信箱函件/勘误账/审计发现/值守记录
   ↓ 采集器(仿 v5 轨迹采集器,采集"判断-结果"事件而非原始文本)
[抽取] 结构化候选判例:{情境, 判断/动作, 结果, 结果来源(阻抗等级 L0-L3)}
   ↓ 规则+judge 初筛
[判定] 现役 NACRE judge 三态判:该"判断-结果"对是否构成有效判例(对/错/不可验)
   ↓ 证据三层强制(实测/推断/不可验)+qid 防泄漏+dedup(七算子审计教训:写必有 gate)
[入册] 过门者进 delta registry(fuel_eligible)→ corpus_pipeline 计数器自动+1 → 触发器链
```

## 三、防污染护栏(自指与信号衰减问题——用户核心关切)

1. **anchor_level 分层(理论基础档 §一落地)**:每条判例标阻抗等级——L0(物理执行/用户拍板/外部复算)直接入池;L1(专家/跨框互认)入池带标;L2(模型判)只作参考层不进训练集;**L3(纯自说自话)永不入池**;
2. **训练用途定向**:组织历史判例训练的是 judge 的**元判读能力**(识别"什么判断模式会失败"),不是教模型"组织说过什么"(那是记忆层职责)——两条线不混,防自指;
3. **原始文本不入池**:只入结构化判例(隐私+噪声双重理由);
4. **判例也要被判断**:机制本身产出的每批判例抽样 10% 人工复检(判绩账双向)——自动化不等于无监督。

## 四、与既有件的关系(零重复造轮子)

| 既有件 | 在本机制中的角色 |
|---|---|
| corpus_pipeline | 计数器+触发器(入册即自动+1,+500/3000 触发不变) |
| delta registry 棘轮 | 入册正本 |
| NACRE judge(实例 v1) | 判定段引擎 |
| 证据三层/锚定链 | 质量门标准 |
| 五框信箱总线 | 采集通道 |
| M5 记忆门(待部署) | 效用信号源(二期接入) |
