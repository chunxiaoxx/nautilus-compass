# 组织三小模型融合方案 V0(2026-10-07 · anti-重复造轮子 · 响应用户架构融合令)

> 问题:agent 域涡轮增压蒸馏小模型(v5)/判读小模型(compass NACRE)/具身数据飞轮小模型(flywheel)——如何在训练、架构、垂直域三层融合,不重复造轮子。
> 结论先行:**共享一个"模型工厂"(机制+管线+验证内核),三个域只换"语料适配器与底座"**——机制不重复,数据不混列,模型不合并。

## 一、与 JEV 架构的关系:上下游,不是同一个东西

- **JEV**=判分数据与证据体系(数据层):判官语料(1454+)、criteria 库、证据三层标注、TrustedJev 域校准仪器——它管"**数据从哪来、可信度怎么标、域适配怎么校准**";
- **NACRE 主线**=消费这些数据训练出的判分模型机制(模型层):压缩(SFT)×验证(三态+判据预注册)×因果倒置(delta registry→再训练)——它管"**模型怎么训、怎么升级、错了怎么回流**";
- **关系**:JEV 是 NACRE 的营养与质检体系。JEV 产好数据→NACRE 吃数据长能力→NACRE 判错产生的勘误又回流 JEV——一条上下游河,不重复造轮子的第一层含义就是:别在 NACRE 里再写一遍 JEV 的数据治理。

## 二、原生带记忆(mem0 式)能否同时实现:能,且是双层设计

- **mem0 式=外挂记忆**(可检索、可删除的事实库)——这本来就是 compass 本体在做的(MCP 记忆层+七算子);
- **NACRE 式=权重内记忆**(已消化的技能,SFT 压进权重,冻结式,靠 delta 版本升级);
- **两者不是二选一,是双层**:
  - 外挂层管"事实"(这个项目用过什么约定、哪条结论是 10/6 定的)——可查可删;
  - 权重层管"技能"(怎么判卷、什么算好轨迹)——稳定、可复算、可装订认证;
- **融合点(关键)**:compass 记忆层的**写入门(M5 记忆门三件套)**部署后,记忆层采集的"哪条记忆被证明有用/有害"(F2 delta 信号)就成为因果倒置柱的**新信号源**——外挂记忆的使用效果,反过来训练权重记忆。这正是 M5 在对齐账里"未部署不算 NACRE 部件"的边界原因:部署之日,双层打通。

## 三、三小模型融合设计:一个工厂,三个域,不合并模型

### 共性(全部共享,一份代码)

| 层 | 共享件 | 状态 |
|---|---|---|
| 验证内核 | 预注册判据+三态+复算+UNVERIFIABLE 墙+判例 registry(assay 方法论) | ✅ 已共享(rsi-bench 采纳首例) |
| 训练管线 | P3 六段:delta registry→训练→评测门→升格棘轮(REG-100 零翻转门) | ✅ 同一管线,NACRE 机制即此管线名 |
| 数据治理 | JEV 判据库+证据三层+qid 防泄漏+corpus_pipeline 计数器 | ✅ 已建 |
| 排产 | A100 排产表(有预注册判据才上卡) | ✅ 本次 B/C 即首单 |

### 差异(各域只换两样:语料适配器+底座)

| 域 | 语料适配器 | 底座 | 实例命名法 |
|---|---|---|---|
| agent 判读(compass) | 判例集+verdict 语料 | Qwen3-1.7B | nacre-judge-v1(已挂 HF) |
| agent 执行蒸馏(v5) | 轨迹→SFT 蒸馏对(r84 64%) | 按任务选型 | nacre-exec-v*(v5 命名) |
| 具身判读/标注(flywheel) | 具身轨迹标注对 | VL 多模态底座(VL-3B 已在盘) | nacre-embodied-v*(预留) |

### 不融合的部分(诚实边界)

执行蒸馏(教 agent 干活)与判读(评 agent 对错)**目标函数不同,模型不合并**——但数据流互通,这正是 TURBO 五段:轨迹(v5 供油)→判读(compass)→入池→结算→训练复考(v5),转一圈三域各取所需。

## 四、落地三步(挂 M 清单,开业优先级之后)

1. **M7a 管线通用化**:P3 训练管线代码从 compass 仓抽出为共享件(org_lib),具身域可直接调——工时小,防未来 flywheel 重写一遍;
2. **M7b M5 记忆门部署**(既有卡):部署即打通双层记忆,NACRE 因果倒置获得外挂记忆信号源;
3. **M7c 命名与入册律**:三域实例统一 nacre-* 命名+org 入册(HF nautilus-compass),新品不入册不算数(生态律既有)。
