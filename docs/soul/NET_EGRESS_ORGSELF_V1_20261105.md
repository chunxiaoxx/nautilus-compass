## 一、组织自用固定出口(线①)

### 1.1 需求盘点(先答"要它干什么",再谈买什么)

| 场景 | 现痛点 | 固定出口价值 |
|---|---|---|
| 外联账号一致性(dev.to/GitHub/HF/Gmail) | 出口随节点漂移,风控反复挑战(11/4 实测 GTT 机房 IP 被挑战) | 同一 IP 长期出现,降低挑战频率 |
| agent 出海访问(HF 下载/文档抓取) | 节点质量波动(11/4 实测 830KB/s-2MB/s) | 固定带宽+可监控 |
| 测量基准 | 网络韧性评测需要可控变量 | 固定出口=可控实验条件 |

### 1.2 采购候选(三家对拍,报价以实测为准 [推断,知识截至 2026-05])

| 候选 | 形态 | 估月成本/条 | 特点 |
|---|---|---|---|
| A. US VPS+独享 IP(Vultr/Linode/Hetzner Ashburn) | 自建出口节点 | $6-20 | IP 为机房段(风控弱于家宽),全控,QUIC/UDP 自由 |
| B. 静态 ISP 代理(正规商用供应商) | 商用静态住宅 | $5-15/IP | 家宽属性好,但 ToS 多禁代理场景,须逐家核合规 |
| C. 现有机场独享线路 | 订阅增值 | 按报价 | 最快但不控 IP 归属,作对照组 |

**建议(V2 修订)**: 不自建 VPS——主选 **C 采购主流商用服务**(SK9IP 类家宽出口 1 条做自用账号运维 + 一家主流 VPN 服务对照),B 类只做风控对拍试验位,不扩大。验收判据 §1.4 不变。

### 1.3 拓扑(复用现有 sing-box,不新增核心)

```
Mac/云 agent → sing-box(TUN,现有) ─ route 规则按域名/进程分流
   ├─ direct(国内,现有)
   ├─ us-exit-商购主线路(主流 VPN 订阅出口,新)      ← 主
   ├─ us-exit-SK9IP(家宽固定出口,新)                 ← 账号运维位+风控对拍
   └─ 既有节点池                                     ← 兜底
```
- 传输: 采购商用服务端到端加密为主;若采购对象只给裸 SOCKS5(明文段风险),该段仅限自用低敏流量,并在探针里单列其加密状态——不因自用而免验;
- 监控: 全链路探活(出口 IP 核验+DNS/IPv6 逐段),复用本会话分层计时探针(curl -w 四段)脚本化进 launchd 30min 轮;
- 切换: sing-box urltest 组+固定出口组并存,**默认不自动切换**(固定出口的意义就在不变),只在主出口死>5min 告警人工切。

### 1.4 验收判据(预注册)

- 出口 IP 连续 7 天不变(每日两次核验)≥95%;外联目标(dev.to/GitHub)首字节时延 P50 ≤ 现节点基线;断线重连≤30s;逐段 DNS/IPv6/UDP 行为有记录。
- 负结果照报: 若机房 IP(A)风控挑战频率与 GTT 无显著差异,B 的溢价才成立。

## 二、self-host 编排面板(线②)

### 2.1 定位(一句话)
"给有自己服务器和线路的人的多出口编排/监控/计量面板"——**只卖工具,不碰信道、不做托管、不经手流量**;客户把它部署在自己基础设施上。

### 2.2 竞争与差异化
- 现有: mihomo dashboard(单机 UI)/portainer 级通用面板——缺"多出口绑定+全链路探活+计量核对"这一层;
- 我们的可复用资产: 本周蒸馏试点刚建的全套模式——预注册判据/分层探针/机械核验器/两臂对拍方法论,直接平移为"出口质量评测"能力(这恰是 compass 本行: 测量机构)。
- 形态: 开源核心+企业 self-host 授权(MIT/commercial dual,参照 jev-trust 发布经验)。

### 2.3 合规护栏·五条铁律(V2 定稿·2026-11-05 用户拍板,功能设计否决线)

任何功能提案撞线即否,不进评审:

| # | 铁律 | 否决示例 |
|---|---|---|
| 1 | **空箱交付**: 不内置节点/默认订阅/节点市场/信道商推荐 | "开箱预置 3 个可用节点" ❌ |
| 2 | **不吃信道分佣**: 不与任何信道商(含 SK9IP 类)签推荐返佣/渠道分成 | "推荐返利链接" ❌ |
| 3 | **营销口径不指向翻墙**: 只讲企业组网/多线 failover/出口监控运维,不讲出海加速 | "一键解锁"文案 ❌ |
| 4 | **数据面不经过本方**: 首选 self-host;托管只做控制面(配置/监控/告警),客户流量零经过 | "帮客户代维节点并转发流量" ❌ |
| 5 | **ToS 转责+ICP 挂靠**: 用户协议明确线路合法性用户自负;托管控制面对境内收费挂 ICP 经营 | 匿名开放注册无协议 ❌ |

判定总则: 只卖铲子不挖运河——软件与控制面可卖,信道与数据面永不碰。
