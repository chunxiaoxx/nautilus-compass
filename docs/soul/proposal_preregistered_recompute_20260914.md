## 判据预注册+非实现者复算 · 流程模板 v1

### 一句话

判据在任何结果产生之前冻结落档;"完成"只能由未参与实现的会话按冻结判据
独立复算确认——自报不算,复算过门才算。

### 适用场景(任一即用)

- 重要功能上线前的验收(影响生产或跨框)
- 评测/跑分/数据产出的结论(对外要报数字的)
- 修复类改动(声称"修好了"的)

不适用:琐碎改动、纯文档、探索性原型(判据还没法定就用不了,别硬套)。

### 四段流程

**第 1 段 · 判据冻结(实现开始前)**
- 把通过判据写成正式文档落库(建议名:`docs/plans/<日期>-<事项>-preregistered.md`)
- 判据必须包含:逐条判据表(编号/判据/通过线/测法)、冻结时间、基线读数(若适用)
- 冻结后只允许改严,不允许放宽;任何放宽必须用户明示拍板并在档内追加记录
- 精髓:此刻没人知道结果会是什么,判据才没有事后凑数的空间

**第 2 段 · 实现(单分支可回滚)**
- 改动收在单分支/单 commit,保证随时可回退
- 实现方自测可以跑,但自测结果只作参考,不写进判据档的结论区

**第 3 段 · 非实现者复算(核心)**
- 开一个**新鲜会话**(未参与实现、未读过实现方结论)
- 交接档只给两样:判据档正本 + 坐标与命令清单(路径/端口/脚本)
- 🔴 交接档不得写任何"预期读数"——写了就等于引导,复算失去独立性
- 复算者只信冻结判据与自己的实测;发现 FAIL 如实记录,不改代码不放宽判据
- 复算者的红灯先证伪自己探针(路径形态/样本选择/计数口径),再归因被测物

**第 4 段 · FAIL 的处置**
- FAIL → 修复(修复者与复算者可同为新会话,但不得改判据)→ 重测挂掉的条目
  + 回归冒烟 → 全绿才闭环
- 全绿后回执回填判据档并 commit,据此发通报(如果有对家)

### 五条护栏(全部来自实战教训)

1. **自报不算**:连自家 README/日志说成功都不算,以独立复现实测为准
2. **只给坐标不给答案**:交接档无预期读数;防复算被引导
3. **判据只许更严**:放宽=作弊,须用户拍板留痕
4. **探针过幸运窗口 ≠ 功能成立**:实测样本必须覆盖典型位置(如"文件尾部"
   这类惯例场景),不是碰巧落在有效区间就算过
5. **红灯先证伪自己**:复算报 FAIL 时,先怀疑探针(三连问:路径形态对吗/
   样本选对了吗/计数口径对吗),再下结论——本案例 3 次红灯全是探针自己的错

### 实证案例:RSI 环 #1(2026-09-14,compass)

- 判据 9/9 冻结(四条 J1-J4+三条冻结查询),9/14 实现方合入并自报全绿
- 独立复算(新鲜会话、自选探针材料)结果:
  - **J1 FAIL**:新写记忆 30 条 0 条带 fact_status(0%)——写入门装在没人
    走的路径上,实际写入全走另一条无检查的路
  - **J3 FAIL**:沿链展开只扫描每条记忆前 500 字符,引用链接按惯例写在
    文件尾部——永不展开;实现方所举示例实测不可复现
  - J2/J4 PASS(核心检索无恙)
- 修复(2 处)+重测四条全绿 → 闭环 → 通报函
- 要点:**若无此段,两个缺陷就以"全绿"身份进生产了**——这就是流程的价值

### 可复用件

- 判据档模板:本文"四段流程"第 1 段的结构,直接照抄成新档
- 回归门脚本同构:`ops/regression_gate.py` 模式(冻结查询清单+hit 判定+
  基线 JSON 对照),各框可平移
- 交接档模板:坐标+命令两节,仅此两节

### 各框接入建议(最低成本路径)

1. 下一次"要对外报数字"的活,先花 20 分钟写判据档(不用等平台任何配套)
2. 干完后开新会话复算,交接档按护栏 2 写
3. 结果(无论全绿还是 FAIL)投 mailbox 或 verdict-bus——FAIL 同样是有效
   产出,它拦住了假绿
