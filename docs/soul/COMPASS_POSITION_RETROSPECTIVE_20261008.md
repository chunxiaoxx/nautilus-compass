## 三、根因分析：为什么串线了

1. **compass 主线定义在演进中**：纯记忆层→记忆+验证→记忆+判断→六组件统一机制——每次扩容自然覆盖前一次，但**每次扩容都应该主动确认"旧边界是否被替代"**；
2. **平台死线卡派件 ≠ 主线确认**：死线卡是任务分配，不是方向定义——我照单全收没有先核"这是否我的主线";
3. **JEV/assay 判断能力的应用场景(评测)与工具本身(assay/jev)混淆了**:assay/jev 是 compass 的工具→用它做评测服务= compass 的业务扩展→但评测服务的**运营主体**是平台(门面)+v5(执行)——compass 是**供弹方不是打枪方**。

## 四、沉淀:三条 SOP 级原则

1. **方向变化必追认**:每次用户拍板新方向时，主动列出"这与旧方向的关系(扩张/替代/并行)"并确认——不等出了问题再回头补;
2. **派件不等于定义**:接到平台/其他框的任务分配时，先核"这是否在我 own 范围内"——不在则走认领/改派程序,不沉默接单;
3. **工具与应用分离**:compass 的 assay/jev 是工具,任何人可以用;但用这些工具做的评测服务，运营归属看谁 own 客户关系——**compass 供弹,平台开枪**。
