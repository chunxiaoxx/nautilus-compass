# NACRE 原生化路线图 V0(2026-10-07 · 技术实现深挖 · 每条带实验设计)

> 回答"如何真正创新实现":六个原生化方向,每个=创新机制+为什么是我们才能做+实验设计+工程依赖。核心洞察:**业界做持续学习/自进化的普遍缺可信验证器;我们的独有资产=可复算判分器(88.51%)+判例 registry+验证内核——把验证从外挂质检变成训练与推理回路内的原生信号,这就是真创新**。

## 一、原生动态权重:"registry 条件化技能片"(判据路由 LoRA 库)

- **创新机制**:不做单一大模型的通用持续学习,做**"基座+按需挂载技能片"**——registry 里每个 delta 域(判例域)训练一个小 LoRA 技能片,推理时按判据 sha/域路由动态挂载。每个技能片自带验证证书(挂载前过 REG-100 零翻转门)。
- **为什么是我们**:技能片的"准生证"需要可信验证器发放——没有可复算判分器与判据冻结,技能片漂移无人能查。我们的 registry 天生是证书体系。
- **工程可行性:今天就能做**——vLLM 原生支持多 LoRA 动态挂载(v5 的 bootstrap_nacre_serve.sh 已在用 `--lora-modules`);基座常驻,技能片按需热挂。
- **实验设计(E-NACRE-1)**:按 domain 字段把 verdict 语料分 2-3 个域片,各训小 LoRA;对比 ①单一大 LoRA(现役)②路由多片——判读 acc≥现役 且 域内 acc 提升 = 原生动态权重 v0 成立。预注册判据照 PRECOR 制式。

## 二、原生 RSI 自进化:"双模型互锁"(反自指的工程化)

- **创新机制**:自训自进化的最大风险=自指漂移(自己教自己越教越偏)。我们的护栏差异化:**NACRE-exec(被训方)与 NACRE-judge(裁判方)分离互锁**——exec 的每次自进化批次,必须过 judge 按冻结判例锚(frozen anchor)的验证;judge 自身只允许从外部勘误(判例集)更新,不允许从 exec 的输出更新。
- **为什么是我们**:互锁需要两侧都是可信部件(judge 可复算+判例 registry 防篡改);单模型自进化(MemRL 类)没有这种结构性护栏。
- **实验设计(E-NACRE-2)**:v5 蒸馏小模型(exec)用涡轮增压自训两轮;每轮后由 judge 判读同一 held-out 集——judge 判定与 ground truth 的一致率不降 = 互锁有效;exec 的任务成功率提升 = 自进化有效。两门同过才算。

## 三、原生记忆:"记忆效用信号→训练燃料"(双层打通的具体协议)

- **创新机制**:记忆层(M5 后)每条记忆带**效用遥测**(被检索→被引用→任务成败),高效用记忆自动**晋升为 delta 训练条目**进 registry;低效用自动衰减。记忆不再只是"可查",而是"可转化为权重"的活数据。
- **为什么是我们**:效用信号的可信判定需要验证内核(任务成败=可复算判定);mem0/MemRL 类无此闭环。
- **实验设计(E-NACRE-3)**:M5 部署后跑 2 周,取效用 top-10% 记忆构造训练条目(经三态判读验证),混入 P3(按回放配方 10-15%);对比混入前后 judge 在记忆密集型 qid 上的 acc。

## 四、原生专家技能:"专家=域判例的函数"(分域原生化)

- **创新机制**:各域专家技能不靠通用大模型 SFT,靠**域判例集蒸馏**(Agent Distillation,NeurIPS 2025 已证可行)+域判据验证门——软件工程判读/具身标注/各垂直域,每个域=判例集+小模型+验证证书三件套。
- **为什么是我们**:蒸馏的教师信号与质量门都是我们独有(判分器+判据冻结);数据飞轮(v5 轨迹/flywheel 具身)天然产判例。
- **实验设计(E-NACRE-4)**:具身域首发——VL-3B 底座+flywheel 标注判例(vdd4 已有栈),照 nacre-embodied-v1 命名入册;判据=flywheel 四验门预注册。

## 五、推理时域适配:"判分器 TTT"(测试时训练,新技术引入)

- **创新机制**:新域/新基准冷启动(无足量判例时),不做全量重训,做 **TTT 式小幅适配**(该域少量判例即时微调,判据 sha 锁定,用完即弃或验证后入 registry)。
- **学界依据**:TTT for Long-Context(OpenReview 2026)证明小量上下文特定训练优于推理时搜索——迁移到判分域适配。
- **实验设计(E-NACRE-5)**:caliber-bench 首个外部域单(如 L1 收录的某 harness 域)冷启动,TTT 适配 vs 零适配对照。
