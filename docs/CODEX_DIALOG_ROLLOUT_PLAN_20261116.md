## 统一工作机制

四个对话框都使用同一套短汇报：

```text
目标：
当前事实：
本轮只做：
完成判据：
结论：
证据：
阻塞：
下一步：
```

统一的部分是表达、证据、交接、分叉和归档规则；每个对话框的业务正本、写入权限和验收标准仍然分开。

## 分阶段改造

### 阶段 0：盘点（已完成）

- 读取四个仓库的 `AGENTS.md`；
- 读取分支、dirty 状态、Worktree、近期提交和交接候选；
- 生成 `runtime/cross-dialog-inventory-20261116.json`；
- 不修改其他仓库。

### 阶段 1：每框建立状态卡（下一步）

按 Compass → 平台 → Agent/V5 → 飞轮的顺序，每次只处理一个框。每框补一张状态卡，内容只有：

- 主线目标；
- 当前负责人；
- 当前证据；
- 当前阻塞；
- 下一动作；
- 完成判据；
- 允许写入的路径。

### 阶段 2：对话框收敛

- 选一个主线程；
- side chat 只做审查；
- fork 只做平行方案；
- Worktree 只做隔离代码；
- 完成线程写回主线后归档；
- 不删除历史证据，不把多个线程的事实直接拼接。

### 阶段 3：跨框交接

跨框只传递版本化交接，不传递“我记得已经完成”的口头状态。交接必须包含：

- task_id；
- owner；
- 判据；
- 证据坐标和哈希；
- 剩余问题；
- 下一动作。

### 阶段 4：周期复盘

每轮只检查三件事：

1. 是否产生了新的业务或工程成果；
2. 是否有新的失败、阻塞或证据损坏；
3. 是否需要调整主线或归档旁支。

没有实质变化时只报告“本轮无新增”，不再增加重复日志。

## 四框完成标准

- Compass：用户能在一张状态卡中看懂整体目标、进度和下一步；
- 平台：任务合同、代码、测试和平台回执能逐项对上；
- Agent/V5：每个执行动作有原始输出和退出状态，不能自报验收；
- 飞轮：业务正本、数据权利、QC、客户验收和结算仍由飞轮自己负责；
- 跨框：没有一个框把自己的本地成功冒充成另一个框的客户成功。

## 暂不做的事

- 不批量重命名或删除旧线程；
- 不在四个 dirty 工作树之间互相复制未审查文件；
- 不把旧的 Windows 路径脚本直接当成当前 Mac 审计工具；
- 不用对话框数量、记忆数量、进程数量替代业务验收。
