## R1 区分度(甲方判定认知:国内模型平均分比 SOTA 低 10-20 分以上)
- **平均分=二值口径**:4 轮里全过轮数÷4(不是 UT 均分!)
- passrate=UT 通过率均值;**两者趋势必须一致**(不一致=质检卡)
- 目标带:qwen 二值均分 0.55-0.65 / SOTA 0.75 左右
- 反面教材:我方 CS-001(均分差 0.079)/CS-004(0.0)/CS-005(-0.032 国内反超)——5 题不达标;CS-002(0.166)唯一合格样板

## R2 难度带(中等缺口)
- 外部专家题把 qwen 压至 passrate 1.9%——甲方要**中档补充**:qwen passrate>0 但<SOTA
- 实操:qwen 能通过非陷阱 UT(大部分),陷阱 gating UT 决定全过与否——"发现但修复不全"层次

## R3 题型(新增 feature 优先)
- 现有题改 bug 居多;甲方指定 feature 型六 badpattern:
  1. 目标或口径理解错误→D01.1 后端接口与业务逻辑
  2. 交付形态或实现对象错位→D08.0 技能包开发迭代
  3. 明确需求或约束遗漏→D05.0 数据分析与SQL取数
  4. 边界与异常处理缺陷→D08.0 技能包开发迭代
  5. 范围遗漏漏项→D05.0 + D01.1
  6. 口径语义错位→D05.0

## R4 领域契约(违者质检直接卡)
- 每题必须:甲方 badpattern 机制ID × 指定领域 × 诱发场景 三对号
- 前车之鉴:CS-001(被要求嵌入式 D09.1,实际 cel-go)/CS-002(被要求后端 SQL D05.0,实际 GraphQL mock)
- bug 型同样受领域约束(CS-018→D05.0,CS-019/020/21→D01.1)
