## 评测集(自家分布,三件)

- **Set A · 全库自监督**:155 条记忆正文为语料;seed42 抽 30 条,每条取正文前 200 字符为查询,金标=该条本体;指标 recall@1/@5/MRR
- **Set B · 中文切片**:Set A 中 CJK 占比>50% 的子集,同指标
- **Set C · 实弹三查询**:J4 三冻结查询(hit@3),即真实使用分布

## 判据(冻结)

- **换模型** = 候选在 Set A recall@1 **≥ 现役 +2.0pp** 且 Set B recall@1 **≥ 现役 +2.0pp** 且 Set C hit@3 不低于现役(3/3)
- 任一不满足 → bge-m3 留任,结果照发(负结果一等公民)
- 同分(±0.5pp)→ 留任(迁移成本不为零:全库重嵌+缓存版本键)
- 全部读数带 [实测] 标注;脚本与结果 JSON 入仓可复算

## 工程

- A100:模型走 modelscope(R303 pattern);eval 脚本用 transformers(与 embed_server 同栈);语料=本地 155 条 md 打包上传(仅进我方 A100,不出组织边界)
- 切换工程(若触发):全库重嵌+缓存键加 embedder 版本+外网终检回归——另立执行窗

## V2 深化(用户批评响应:选型要深度思考)

### 2.1 任务本质五特征(选型的锚)

1. **非对称检索**:查询=短情境描述("r80 判读材料到没")而非信息需求;金标=长先例文档——指令感知/非对称训练的模型占优
2. **跨语混排**:中文叙述嵌英文错误串(WinError 10053/swebench/cla-bot)——zh 语义+en 词面双敏感
3. **领域**:软件工程运维叙事(错误码/工具名/流程动词)
4. **时效未用**:条目带日期但现役纯语义排序(时序融合列后续,不入本轮判据)
5. **规模延迟**:155 条本地/1500+ 云;A100 后吞吐无忧,瓶颈在质量不在速度

### 2.2 硬过滤(一票否决项)

zh 强+代码词面容忍 · 自托管(transformers 栈) · 宽松许可(Apache/MIT;装订线商用,NC 一票否) · ctx≥2k · **禁外部 API**(4/28 用户隐私裁决,gemini/doubao 嵌入系全否)

### 2.4 评测设计升级(批评的正解:选的不只是模型,是考法)

- **原 Set A(正文前 200 字查自身)=lexical 送分题**,对所有模型虚高,测不出"情境→先例"的非对称鸿沟——降为参照项
- **Set A+(新主判据)**:每金标条目用 LLM 生成**情境化改写查询**(模拟"再次遇到此情况时 agent 会输入什么");硬负例=同主题相邻条目故意留库(制造真实混淆)
- **Set C 扩容**:attributions.jsonl 真实事件流持续喂入(业务即考题)
- 判据 V2(换模型门)= **A+ R@1 ≥+2.0pp 且 B 切片不降 且 C 不降**;原 Set A 仅参照

### 2.5 执行序

Qwen3 双模下载中(~20min)→ Conan-v2 排队下载 → A+ 改写查询生成(判读线 LLM)→ 全量评测 → 按 §2.4 判据判读 → 结果文档+delta 候选
