## 一、计量问题(对应对方宣称的逐条验证)

| 对方宣称 | 计量问题 | 方法 |
|---|---|---|
| "100% official channel access" | 响应是否来自宣称的模型本体 | 模型身份指纹题+对照腿 |
| "99% 主流多模态覆盖" | 覆盖模型实际可用率 | 全模型清单逐个探活 |
| "稳定低延迟" | p50/p95/p99 及时段稳定性 | 定时探针 3 轮/日 |
| "itemized 明细计费" | usage 返回与实际扣费一致 | usage 对账 |
| (未宣称但行业通病) | 偷换小模型/上下文截断 | 指纹+长上下文 probe |

## 二、Probe 集(五类,每模型每轮)

1. **身份指纹**(10 题/模型):该模型独有训练截止知识、风格特征、拒绝模式、自我身份报告。示例:`你的训练数据截止到什么时候?请给出一件 2025 年 Q2 的行业新闻`+模型特有行为题。**判定:任一指纹与官方对照腿矛盾=红旗单列,不计均化**。
2. **能力锚**(10 题/模型):固定难度梯度(数学/代码/指令跟随),测输出质量漂移(同题 30 天 90 次采样的一致性)。
3. **长上下文**(3 题/模型):~100k token 注入,尾置关键信息提问,验证无截断(收长窗的钱给短窗=行业通病)。
4. **结构化输出**(5 题/模型):JSON schema 遵从率(F15 Choice 三态同款格式)。
5. **延迟/可用性**:以上全部请求记录 latency、http_code、SSE 断流。

## 三、执行参数

- **频率**:每日 3 轮(10:00/16:00/21:00 北京),每轮每模型 10 请求
- **30 天累计**:每模型 ~900 请求,5-10 模型,总 4.5k-9k 请求
- **对照腿**:同 probe 集打官方直连(现役 key:zhipu/MiniMax/ARK/TypeSafe 覆盖到的模型);无官方 key 的模型,指纹判定退化为「与该模型公开文档/已知行为特征比对」并标注 U(不可核)
- **调度**:Windows 计划任务调 `tools/infistar_meter.py`;轮内值守监控缺轮
- **落盘**:`runtime/infistar_meter/raw_YYYYMMDD_HH.jsonl`(原始)+`daily_YYYYMMDD.json`(日汇总);原始日志不改写,勘误走追加

## 四、预注册判据(全部满足=PASS;任一 FAIL=教程不发布)

| # | 维度 | 判据 | 口径 |
|---|---|---|---|
| J1 | 可用性 | 30 天总成功率 ≥99%,无连续 ≥5 次失败段 | 5xx/超时/断流计失败 |
| J2 | 延迟 | p95 ≤ 官方对照腿 p95 ×1.5(无对照模型标 U 不计) | 每日分时段取 p95 再取 30 天 p95 |
| J3 | **身份指纹** | 指纹矛盾次数 = 0 | 任一矛盾=FAIL 且单独披露,不允许均化掩盖 |
| J4 | 计费一致 | usage 返回 vs 对方账单扣费偏差 ≤1% | 逐周对账 4 次 |
| J5 | 上下文保真 | 长上下文尾置信息提取正确率 = 100%(9/9 以上) | 截断一次即单列 |
| J6 | 结构化 | JSON schema 遵从率 ≥95% | 30 天累计 |
| J7 | 稳定性 | 能力锚得分无单日漂移 >2σ(防高峰期偷偷降智) | 30 天时序 |

**三态**:全过=PASS;任一 FAIL=FAIL(教程不发);对照缺失致无法判定=U(该项如实披露)。
