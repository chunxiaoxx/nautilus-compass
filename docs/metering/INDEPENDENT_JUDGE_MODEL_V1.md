# 独立判官架构模型 v1(INDEPENDENT_JUDGE_MODEL_V1)

> 2026-10-04 出件 · 承沉淀提案 2734(件二)· 正本唯一源=本文件,实例与判例均 sha 锚定可回溯
> 定位:compass 判分机构(验证机构)的判读方法学正本——任何一方(含我方自己)拿材料来判,判读过程长什么样、凭什么信、错了怎么办,全部在本档可查。
> 素材源:JUDGING_EVIDENCE_TIERS_20261003 + CASEBOOK_V1 八案 + paper2_judge_hygiene(P1–P7) + verdict_schema_v2 校验器。

## 〇 · 一句话

**判官的权威不来自判官,来自结构**:判据先于材料冻结、材料指纹锚定、判读者与实现者分离、证据分层强制标注、判例双向勘误——五层各自砍掉一类自报作弊通道,叠起来才叫"独立判官"。

## 一 · 五层架构

```
L1 预注册判据层   判据先冻结,材料后到;判据只许更严,宽松化归用户裁
L2 材料锚定层     材料落盘即取指纹(sha16),判读对象=指纹指向的字节,不是口头描述
L3 独立复算层     判读者≠实现者;自报读数必须独立重放后才可引用(对我方自己也一样)
L4 证据三层层     每条结论标 [实测]/[推断]/[不可验];推断带 upgrade_path;不可验单列不作依据
L5 判例装订层     终判进 CASEBOOK,附复算命令;勘误双向留档,评委也会错
```

### L1 · 预注册判据层

- 判读开工前判据档已冻结,含指标定义、门槛、统计法、止损线;判据正本形态可以是独立 jsonl(如 REG-100 冻结件)或函件正文(如 G1 criteria_J=flywheel 函 2389——首演时未独立落盘,2026-10-04 抽查坐实并如实记,后续判据一律独立落盘)。
- **判据零放宽**三不:不改阈值、不延长步数、不以代理读数顶替冻结语义。判不动就报"判不动"(案 5:成功率 0/20 地板,照报 U 态,不以 coverage 代理顶替)。
- 判据宽松化裁决权在用户,不在判读方与材料方任何一侧(宪法十三条①;案 7 留痕)。

### L2 · 材料锚定层

- 材料交付时即取逐件指纹(rows_sha16 / ckpt_sha16 / manifest_sha16),verdict 只引用指纹,不引用"对方说的那份文件"。
- 验签:交卷包(如 E1 双包)按映射表 sha16 验签后才开工(sha 不合=材料未达,判读不启)。
- 交付后材料不可变;要改就是新材料新指纹新判读,旧判读不追溯(案 7 追溯边界)。

### L3 · 独立复算层

- 判读者与材料实现者角色分离;实现方的 summary 只算"自报",必须逐项独立重放后才能进判读(案 6:四窗 summary 与 compass 逐帧复算互证全等后才引用)。
- 对账件归档不占燃料计数(案 8:自勘类归对账件);**复核背书≠独立发现**,独立性看发现主体(S2 更正:label_origin 应为 self_recompute,我方复核不改性质)。
- 非实现者复算的强度梯度:新鲜会话>子进程>实现者自跑(禁止自跑)。

### L4 · 证据三层层(正本 `docs/metering/JUDGING_EVIDENCE_TIERS_20261003.md`)

| 层 | 标注 | 判分效力 |
|---|---|---|
| 实测 | `[实测]` | 一手读数,附命令与 sha,可作判分依据 |
| 推断 | `[推断]` | 须带 upgrade_path(怎么验);可作依据但不得冒充实测 |
| 不可验 | `[不可验]` | 不作判分依据,单列披露 |

- 三态判定(PASS/FAIL/U)与证据层独立:U 态可由实测得出(材料缺陷实测坐实);PASS/FAIL 不可仅凭长推断链。
- 初判缺口不粉饰:coverage 段如实记("目检 3/16 帧")。
- 本纪律对内对外同标——我方判读件同样过 schema 校验+复算。

### L5 · 判例装订层(正本 `docs/cases/CASEBOOK_V1.md`)

- 终判装订成判例:背景/判据/材料锚/判读/边界/verdict 正本/复算命令七段制,外部读者按坐标可独立复验。
- **勘误双向**:材料方勘误与评委自我证伪同档留痕(案 2/案 4 判读方探针先自证伪;S2 请降=材料方主动请降首例)。勘误留档是信用资产,不是污点。
- verdict 全件过 schema v2 校验(`tools/verdict_schema_v2.py validate <verdict.json>`),结构不合=判读不出件。

## 二 · 两个程序件

### 程序件 A · 判据演进程序(判据 v1→v2 怎么合法换)

触发:冻结判据在实际材料上判不动(地板效应)或暴露选择自由度。
四要件缺一不可:①用户批准(宽松化归用户裁)→②预注册草案先落档→③技术审定(压缩判读自由度的修订冻结前补)→④记录义务与追溯边界明文(旧材料不追溯)。
全链判例=案 7(#2551→#2568→#2574→v2-final)。

### 程序件 B · 止损条款程序(判读什么时候停)

触发:判据零放宽下连续判不动(n 扩到预设上限仍无信号)。
动作:止损线生效,不再扩 n/不再换代理;结论按预注册 NS 分支出件("方向显著有效+达标性未证实"可并存);首案归档口径随 NS 分支走。
判例=案 6(n: 20→100 后地板依旧,止损生效照报)。

## 六 · 边界(模型不做什么)

1. 判官不做效度终判的替身:帧级辅助读数不顶替层 1 主判据(案 3/4 边界)。
2. 判官不做材料方的过程担保:过程性事实属[不可验],单方陈述不作判分依据。
3. 判官不做自家成绩的终判:自家成绩永远三供应商外置+人审(反自指护栏,见 P3 管线正本 §八)。
4. 判读免费,装订收费:判例集/认证/协议植入只做判后事,不为付费改判读。
