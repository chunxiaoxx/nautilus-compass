## 2. License 战略(B 路径的地基,本章为决策材料)

### 2.1 现状(实测)

- `LICENSE` = MIT,版权人 **Yiluo Technology Co., Ltd.**(公司实体,对**未来版本**协议可单方面决定;已发布版本不可撤回)。
- `anchors*.json` 已 split CC0(commit 3bd53f6)——仓内已有"代码/数据分层许可"先例。
- git 历史永久 MIT。**不重写历史**(证据链文化);若切新协议,fork 者能拿到的旧 commit 停在 v0.9 功能水平,自然衰减。

### 2.2 关键判断:MIT 之下没有"商业 license"这张牌

MIT 已把 use/sell/sublicense 无条件授予所有人。**"MIT + 商业授权"双许可是伪命题**——双许可(dual licensing)只对 copyleft 或 source-available 协议成立(AGPL / FSL / BUSL),因为只有它们制造了"要么开源、要么买商业授权"的选择。素材文档里"商业 license 与 MIT 双条款边界"这条待拍板项,前提不成立,须先拍 license 本身。

### 2.3 时间窗口(最重要的判断)

| 时点 | 改协议成本 |
|---|---|
| **现在(第①层传播未开始)** | ≈0。无采用者即无反弹;只有我们自己知道。 |
| 发布后任何时点 | 背信叙事。HashiCorp(BUSL 2023)、Elastic(SSPL 2021)、MongoDB、Redis 全是在宽松协议积累社区后收紧 → 被指控 + 被分叉(OpenTofu/OpenSearch/Valkey)。第①层传播每推进一天,就在积累反弹成本。 |

**结论:要改就是现在,或者永不。**

### 2.4 选项对比

| 选项 | 社区传播 | 防云厂商托管套壳 | 政企私有化(B) | 成本/复杂度 | 先例 |
|---|---|---|---|---|---|
| a. 保持 MIT | ★★★ 最优 | ✗ 无保护 | 不妨碍,但无法律抓手(只能卖支持/服务) | 零 | Mem0(Apache)活得不错——但人家有 VC+销售团队;我们的代码+证据链是唯一能被拿走的资产 |
| **b. FSL-1.1-MIT** | ★★ 良好(全源码可得,2 年自动转 MIT) | ✓ 唯一被禁的是"竞争性使用"(拿它做托管服务卖) | ✓ 不受影响(内部部署=允许用途) | 低(标准化文本,照抄官方) | Sentry / Plausible(Fair Source 运动) |
| c. AGPL-3.0 | ★ 受抑(大量企业合规部门拉黑 AGPL) | ✓✓ 最强 | ✓ 内部部署不受影响 | 低 | MongoDB / MinIO |
| d. BUSL | ★ 观感差,且**生产环境外使用受限→政企拿源码部署受限,直接伤 B 路径** | ✓✓ 最强 | ✗ 受损 | 低 | HashiCorp(背信+分叉舆论最烈) |
| e. open-core 拆仓 | ★★ | 部分 | 无抓手 | 高:hosted 代码(auth_api 等)与核心同仓,拆分费工;**削弱"全开源+$3.50 复现"可信度卖点** | GitLab |

### 2.5 推荐:FSL-1.1-MIT(待用户拍板)

三点理由:

1. **精准打击唯一威胁场景**。FSL 只禁一件事:把本软件(或衍生品)作为托管/受管服务提供给第三方,使其无需从版权方获取即可使用——即"云厂商直接托管套壳卖钱"。自用、修改、内部分发、私有化部署全部自由。
2. **B 路径零损伤**。政企内部部署不是竞争性使用,源码免费用;付费买的是支持协议/SLA/合规审计包/合规件——这本来就是 B 的卖法。同时拿到抓手:不经我们做"对外记忆托管服务"的集成商/竞品必须来找我们授权。
3. **传播友好**。两年后自动转 MIT(Change License),"FSL now, MIT later" 是 2026 开发者圈的正面信号而非争议点;全源码公开 + $3.50 复现 + 证据链,开放程度仍超 99% 的"开源"AI 项目。

**代价与坦白**:HN 上仍可能有人问"为什么不是纯开源"——标准答案一句话:"source-available with a 2-year automatic MIT sunset; every benchmark number reproducible for $3.50." git 历史里的 MIT 版本永久存在,不遮掩。

**执行清单(拍板后一个 commit 完成)**:LICENSE 换 FSL-1.1-MIT 官方文本(copyright 行保持 Yiluo)→ `LICENSE-ANCHORS` 保持 CC0 → README §License、launch post、position paper 三处 "MIT" 字样同步 → MCP 卡/商标声明补一行("nautilus-compass™ 名字不受源码协议影响")。

**条款核实注**:本文按 FSL-1.1 要点撰写(竞争性使用例外 + 2 年自动 MIT + 内部使用明示允许);切换时直接采用 fsl.so 官方标准化文本,勿自拟条款。本次起草时 fsl.so 网络不可达,未逐字核对——执行前须拉原文比对(标注 ⚠)。

### 2.6 决策请求

三选一:**a. 保持 MIT**(传播速度优先,放弃 license 抓手)/ **b. 切 FSL**(推荐,保护+传播兼得)/ **c. 切 AGPL**(最强保护,牺牲部分企业采用)。无论选哪个,**商标/名字保护都建议做**(命名三连撞前科:CompassBench/ATLAS/CompassMem)。

## 3. 四路径细化

### A · open-core 托管(近期主推,漏斗顶端)

- **漏斗**:本地免费自托管(无限)→ hosted 免费层(单用户,基础 quota)→ Pro → Team。
- **定价(拟)**:免费层=单用户/限记忆条数;Pro **$15/人/月**(低于 Mem0/Zep 的 $20-25,配合 p95 0.34-0.80s 性能叙事);Team **$25/人/月**(SSO+审计日志+优先支持)。
- **已就绪**:signup/JWT/token 自助/四探针/MVP1-6(v0.9 安全矩阵已修)。
- **缺口→开工件**:①hosted 计量(记忆条数/API 调用)②支付通道(Stripe 或国内替代,出海/国内定位影响选型)③免费层与自托管的边界文案。

### B · 政企组织记忆底座(中期利润主力)

- **客户画像优先级(拟)**:①国内 AI 原生先行企业(多 agent 工作流已有痛点)②数据不出域刚需的政企单位(本地部署+零上云架构是天然合规卖点)③具身智能公司(方向锚协同:机器人编排 agent 的组织记忆底座)。
- **lighthouse 策略**:1-2 家免费/低价换首个可署名案例;销售物料=dogfood 实录(§1)+ 六层治理件(drift AUC 0.83/合约审计/merkle/scoped token)。
- **license 抓手(若 §2 拍 FSL)**:企业支持协议 + SLA + 合规审计包;集成商转售须商业授权。
- **缺口**:打包文档(产品化语言)、首个案例、销售渠道判断(直销 vs 生态伙伴)。

### C · 数据飞轮期权(长期持有,不当近期收入)

- **授权链路**:用户显式 opt-in → 无损原文轨迹 → PII 脱敏 → 训练/持续学习数据资产。
- **变现路径(远期)**:数据集授权;或持续学习上游真值供给(连 Ilya/SSI 窗口期卡位)。
- **近期动作**:只积累不变现。把 opt-in 开关做成 hosted 设置项(小工程量),写入端零改动(无损存储天然就是数据资产——这正是卖点)。
- **合规前提**:opt-in 机制 + PII 脱敏工具(仓库已有 guoshu_pii 线索可接)+ 数据授权法律意见(待咨询)。

### D · 第三方评测(轻量副业,权威反哺 A/B)

- **卖什么**:判分卫生学方法论(抓自己判官 5 次事故全套实录)+ 记忆系统对打评测服务。
- **品牌决策待拍板**:独立品牌(裁判不能是运动员,可信度隔离)vs compass 背书(流量互导)。**倾向独立**。
- **节奏**:10 月出第一篇第三方对打评测(方法是现成的,.mem0 对打协议直接复用)。
