## 单文

**单号**:b-crowd-v2-embodied-annotate-001
**任务**:对 20 张日常生活操作照片(开抽屉/拿杯子/拧瓶盖)做边界框标注,
框出"手部"与"操作对象",每图 1-3 框
**交付**:annotations.jsonl(每行 {image_id, boxes[[x1,y1,x2,y2]], note?})
+ _delivery_manifest.json(文件哈希+可选截图 URL)
**金额**:200 NAU(≈首验 USDC 兑换)|**死线**:接单后 72h|**工时估**:≤2h

## 三层判据(预注册冻结,接单快照哈希)

- **L1 机验(60%)**:jsonl 可解析/20 行/每行 image_id(str)+boxes(list,坐标
  0≤x1<x2≤图宽,整型)——程序:`ops/crowdsource/l1_machine_check.py`(已冒烟)
- **L2 对拍(30%)**:与 5 个样例锚比对(下节)
- **L3 陪审(≤10%)**:仅争议启用

## 质量样例锚(L2 判读锚,挂单即冻结)

合格×3:
✅ {"image_id":"img_001","boxes":[[112,340,398,512],[420,300,610,470]]}
   ——手部框完整含五指,对象框紧贴瓶身,不裁不溢
✅ 框住"手+物"交叠区允许重叠,note 留空或一句短注
✅ 多目标(双手)时 2-3 框,每框单一目标
不合格×2:
❌ 框整图/框半图(敷衍框)——不合格:对象边界必须可辨
❌ boxes 空数组且无 note(跳图)——不合格:每图至少 1 框或 note 说明遮挡

## 附:因果倒置的验收经济学(为什么这套判据分层让"AI 派人"成立)

传统众包平台(MTurk/Scale 类)的质检成本结构:人审或抽样人审为主,
质检本身占了交付价的 20-40%,且质量波动随标注员池波动——平台卖的是
"人力池+抽检",**验证是外挂的、事后的、按单付费的**。

因果倒置模式的差异:验证机构内嵌(Assay=组织自己的器官)——
1. **L1 机验零边际成本**:判据在挂单时就设计成可机验(60% 占比),
   质检前置进单的结构,而不是交付后补检;
2. **样例锚把 L2 的主观性压到判读对照**,不是自由心证——判官可替换
   (模型对拍),质量不随人力池漂移;
3. **判绩账双向**:错怪人可翻案且翻案记账——信任的边际成本随单量下降
   (传统平台随池子扩大上升)。

一句话:**传统平台用抽检对冲人力不可信;我们用判据结构消解不可信**——
这正是"验证即协议"在 C 端众包的同一论点(MTurk 是机构,我们是协议)。
