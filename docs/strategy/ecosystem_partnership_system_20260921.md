# 生态合作系统方案:三环模型与 MemTensor 首案(2026-09-21)

> 用户命题:对 MemTensor/MemOS 的合作「需要系统性的方案」。本档把单一合作对象
> 升维为产业架构:对 MemTensor 的方案=对 agent 记忆产业合作策略的第一份完整设计。

## 一 · 产业角色地图(验证机构的结构性位置)

```
agent 记忆产业链:
  记忆系统生产者 —— Mem0 / MemOS / Letta / Zep / cognee / NanoJev
  评测生产者 ———— LoCoMo / HaluMem / LME-V2 / RSI-Bench(常由生产者自建=自评)
  市场分发 —————— ClawHub / MCP Registry / Glama(装机入口)
  消费者(买方)—— 采购 agent/记忆能力的企业(尽调付费方,方向锚的具身数据买方)
  治理 —————————— EU Machinery Reg 2027-01-20 / 行业标准
  【验证机构(我们)】—— 产业链上唯一的独立裁判位;其余每个角色都有可验证声明
```

结构性事实:生产者自建评测(运动员兼裁判)不是缺陷是常态——**这正是验证机构
存在的原因**:产业越大,「不由利益方自己发的背书」越稀缺。

## 二 · 三环模型(系统方案骨架)

**内环·产品接入**(验证即基础设施):SDK/回执格式/验签门做成各环节的标准件,
不为任何一家定制——LE 剧本「无处不在」门槛的唯一正路。状态:SDK/协议/v0.3 已齐。

**中环·生态卡位**(每类角色一个样板):对产业链每类关键节点各做一个可复制
的验证模板——
| 角色样本 | 模板 | 状态 |
|---|---|---|
| 开源复刻者:NanoJev | 三层回执(声明/校准/权重重放)+verify_all PR | ✅ 已成 |
| 新范式厂商:TypeSafe | 校准声明验证层(判据+引擎+回执) | ✅ 弹药齐,函在途 |
| 中文圈 agent:iFlow | 逐 trial 复算(与 TB 同配方) | ✅ 已成 |
| 市场位:ClawHub | 徽章提案(显示层) | bot triage 在途 |
| **复合机构:MemTensor** | **本档首案——四可验证面×分层架构** | ↓ |
| 评测机构:榜单方(HaluMem/RSI-Bench) | 「评测的评测」(EoE) | 候选 |

**外环·标准与机构化**:协议 CC-BY→事实标准/RFC 轨;EU 2027 认证轨卡位;
L-2 验证者网络;月度信任报告(需求侧痛点制造)。

## 三 · MemTensor 首案:分层合作架构(L0-L3)

MemTensor 的四个可验证面=四类产业声明的模板集合:
① MemOS 的 LoCoMo 成绩(evaluation/ 全套在仓,可复算性佳)
② token savings 声明(README「35.24%」)
③ HaluMem 榜单(他们做评测——评测本身需要被验证=EoE 首个真实对象)
④ MemOS-Cloud-OpenClaw-Plugin(分发面——与我们的 ClawHub 徽章提案同一市场)

**分层架构(对机构的标准打法,可复制到 Mem0/Letta/Zep)**:

- **L0 免费回执**(创世,零条件):LoCoMo/token-savings Tier-1 复算
  (完整性+算术,零 API 成本)→回执登门。展示独立性,不谈任何合作——
  **顺序不可倒**:先有独立裁判的身份,再谈一切。
- **L1 协议采纳**(技术层):其 eval 输出接 VerifyPack 格式+回执签名
  =「MemOS verified results」——他们获得对自评偏差的第三方锚,我们获得
  协议在头部记忆系统的装机。互惠,仍免费。
- **L2 联合资产**(生态层):HaluMem 榜挂第三方回执(评测的评测样板);
  记忆条目 provenance 标准共建(「记忆营养标签」:来源/时间/哈希/签名)——
  与我们验签门/记忆门同构,可互锚。
- **L3 商业**(认证轨):他们发榜/发版前的独立验证=试金局认证轨 SKU;
  他们企业客户的尽调分包。**L0-L2 期间不收 MemTensor 一分钱**(验证独立
  红线);L3 才是商业关系,且永远对买方倾斜。
