# Let's Encrypt 剧本解剖 × AI 信任基础设施路线(2026-09-20)

> 用户命题:LE 有没有参考价值?我们如何成为 AI 时代的验证基础设施?
> 方法:逐件解剖 LE 真实历史(不是口号),映射到我们,**重点标注类比在哪里断裂**——
> 断裂处恰是 Jev 型创新的接口。

## 一 · LE 真正做对了什么(五件,常被讲错的三件先纠)

被讲错的:不是"免费"赢了,不是"慈善"赢了,不是"证书好"赢了。

1. **协议是产品,不是证书**。ACME(RFC 8555)把签发从 $100+/人工/年变成 $0/API/90 天——
   赢在**自动化**,免费只是自动化的副产品。
2. **浏览器造的痛,LE 只造了解药**。Chrome/Firefox 把 HTTP 标"Not Secure" +
   HTTP/2/SEO 都绑 TLS——**默认态反转是浏览器做的,不是 CA 做的**。LE 只是让
   合规变免费变自动。
3. **90 天有效期=强制自动化+持续验证**。续期循环让验证从一次性变成连续的,
   也把作废窗口压小。
4. **跨界签名自举**。借 DST Root CA X3 背书,让新 CA 的证书从第一天就被信任——
   基础设施冷启动靠**挂靠既有信任锚**。
5. **ISRG 非营利治理**。任何一家厂商不能独占——浏览器们才敢合力推它。
   **基础设施归治理结构,不归产权。**

## 二 · 逐件映射(✓=已具雏形,⏳=缺口,✗=断裂)

| LE 要件 | 我们的对应 | 状态 |
|---|---|---|
| ACME 协议 | Assay Protocol v0 + SDK(attest/verify) | ✓ CC-BY 已公开;⏳ 缺标准化轨迹(RFC 式)或事实采纳 |

| 浏览器"Not Secure" | 墙/记忆门打 self-reported/UNVERIFIABLE 标 | ✓ 我们已在打;✗ **没有"浏览器"帮我们显示** |
| 90 天续期 | **回执 TTL 挂主体指纹(T8)+续期=持续适航订阅** | 🔧 设计收敛点(见 §四) |
| 域名验证(控制权证明) | manifest/seal(字节控制权证明) | ✓ |

## 三 · 两处断裂(诚实)+ Jev 如何补上

**断裂一:证书验的是"控制权",我们验的是"陈述真伪"。**域名的机械验证一天可自动化;
"这个 agent 真有 91% 准确率"是语义的,LE 的路线在这里直接失效。**我们的解法从来
就是只验机械可复算子集**(三门=git apply+compile+pytest;轨迹重放=运动学+计数对账)。
**Jev 恰好扩大了这个子集**:决策头输出=固定空间的概率分布(非自由文本),校准
(Brier/ECE)是可重算的量——**业界每采用一分 Jev 式决策模型,我们的可自动验证
面就自动扩大一分**。Jev 范式不是我们的竞品,是我们验证面的扩张器。

**断裂二:LE 有一个浏览器垄断渠道,AI 声明验证没有。**HTTPS 保护单一通道;AI
声明是碎片需求(采购/保险/监管/榜单)。解法=**多渠道挂靠**(见 §五),其中离我们
最近的一个"浏览器"是**市场位**(ClawHub/Glama/MCP Registry——我们三个都已
在列!)。

**自举比 LE 更强的一点**:LE 证书仍需信任 CA 不滥发;我们的回执**持公钥即可验,
数学上不需要信我们**。跨界签名这个冷启动难题,被我们用密码学直接绕过了。

## 四 · 商业模式的 LE 完整映射(两档制)

LE 杀死了付费 DV 证书,但 Sectigo 们仍靠 **EV/组织验证**活着。对应:

1. **免费层(基础设施,永久免费)**:SDK 自证——任何项目用自己的密钥对
   attest,任何人 verify。**不需要我们参与**。目标:像 coverage 工具一样被
   框架默认集成。这层的胜利指标=装机/集成数,不是收入。
2. **付费层(我们的生意)**:独立第三方验证(验证者≠实现者,I3)+墙位+
   **持续验证**(回执 TTL 到期续验=LE 90 天续期↔我们持续适航订阅)——
   **LE 的续期循环和我们的订阅商业模式在结构上是同一件事**,这是本次分析
   最值钱的收敛:订阅不是"我们想收月费",是基础设施信任的天然形状(信任
   是连续量,不是一次性授予)。

## 五 · 成为基础设施的五道门槛(现状+动作)

| 门槛 | 现状 | 下一步 |
|---|---|---|
| 免费 | ✓ SDK 自证免费 | 永远免费(承诺写进协议) |
| 自动 | ✓ attest 一行 | 框架集成(coverage 式默认) |
| 无处不在 | ⏳ 三市场位在列,装机 0 | **创世十家+一个市场位显示徽章**(ClawHub 提案:卡片显示验证状态=他们的差异化,我们的"Not Secure") |
| 连续 | ⏳ 单次回执 | **回执 TTL(挂 T8 指纹)+续验=订阅**——VerifyPack v0.3 episode/TTL 一并设计 |
| 开放治理 | ⏳ 单运营者 | 创世验证者(外部重判我们)→ L-2 多验证者 → ISRG 式"登记运营者"终局(受益方供养,不按张收费) |

## 六 · Jev × 我们的产品架构终图

```
Jev 式决策模型普及
   ↓ (输出=分布,校准可算,轨迹可重放)
可机械验证面扩大 ──→ SDK 自证(免费层,无处不在)
   ↓                      ↓
轨迹回放判分器      记忆验签门/市场徽章(消费侧强制)
   ↓                      ↓
独立验证+墙        回执 TTL 续验(付费层=持续适航)
   └────── 判据库棘轮(法律层)─────┘
   ↓
L-2 验证者网络 → 我们=登记运营者(ISRG 终局)
```

我们自己的小判分器也长成 Jev 形(决策头+三态+校准门)——**吃自己的狗粮到
架构层:验证 AI 的验证器,本身就是被验证范式最好的示范。**
