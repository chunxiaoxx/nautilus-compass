# NACRE（溯衡）本地模型与训练路线

> 2026-11-20。NACRE 是组织内部创新模型的代号。当前先让 Qwen3.5-9B 成为本地 agent 执行器，再用经过验证的轨迹训练 NACRE。训练不会把未经复核的聊天记录直接当作标签。

## 一、当前落地状态

- 本地模型：`Qwen3.5-9B-4bit`
- 服务：`127.0.0.1:11435`
- 本地值守：`tools/local_loop_runner.py`
- 本地 agent 能力层：`tools/local_agent_runtime.py`
- 训练事件：`runtime/nacre/training_events.jsonl`
- 数据集构建器：`tools/nacre_build_dataset.py`
- MLX-LM 数据转换器：`tools/nacre_prepare_mlx_data.py`
- 训练预检：`tools/nacre_training_preflight.py`
- 运行时能力评测：`tools/nacre_eval.py`
- Gold set 候选：`runtime/nacre/gold_candidates_v0.jsonl`
- Gold set 结构校验：`tools/nacre_validate_gold_candidates.py`

已经具备的本地能力包括健康检查、Compass daemon 探活、BGE 语义记忆召回、关键词记忆搜索、证据门检查、平台信箱读取、Gmail 探针、GitHub mentions 读取和本地审核草稿写入。写草稿只写本地文件，不提供发送工具。语义召回使用本地认证的 9876 接口，回执保留命中路径、事实状态和性能信息。

## 二、能力边界

9B 通过结构化 JSON 提出工具调用。Python 侧执行白名单工具，并把工具结果再次交给 9B。模型不能直接执行任意 shell，不能访问未注册工具，不能发送邮件、评论 GitHub、部署或支付。

每次运行写入：

- 任务原文
- 模型提出的工具调用
- 工具返回的证据摘要
- 最终中文结论
- `external_model_used`
- `external_send`

如果任务要求写草稿，运行时会检查 `write_draft` 的成功回执。只有文件真实落盘，最终结论才允许说“已保存”。如果任务要求有证据支持，模型可调用 `evidence_gate`，缺少来源或成功状态时会得到 `insufficient`。

## 三、训练数据进入条件

只有满足以下条件的事件才进入 NACRE 候选集。

1. 工具名称属于白名单。
2. 工具参数通过 schema 校验。
3. 工具结果有明确成功或失败状态。
4. 运行没有调用外部模型。
5. 运行没有发送外部消息。
6. 结论能回到原始证据。
7. 失败、拒绝和无法验证结果完整保留。

`tools/nacre_build_dataset.py` 会把本地事件转换成 `nacre-sft-v0`，同时生成 train、validation 和 test 分片。它会排除标记为外部模型、外发或违反工具回执契约的记录。`tools/nacre_validate_dataset.py` 再检查 JSON 结构、工具白名单、清单哈希、重复 ID 和疑似凭据。

## 四、训练阶段

### 阶段 A · 工具选择 SFT

目标是让模型在固定任务下选择正确工具，拒绝越权动作，识别证据不足。

样本重点：

- daemon、Gmail、GitHub、平台信箱和 memory search 的选择
- 工具参数缺失和参数越界
- 429、超时、空结果和权限失败
- 需要写草稿时只写本地 draft
- 用户要求外发时生成待审内容并停在审核门

### 阶段 B · 证据到结论

目标是把工具结果压缩成短、准确、带状态的中文结论。结论必须区分实测、推断和不可验。

### 阶段 C · 记忆与验证联合训练

目标是让模型先回读相关记忆，再执行任务，再把新经验写回。训练样本同时绑定：

- recall 命中
- 原文路径
- 工具行动
- 结果回执
- 独立复核

### 阶段 D · NACRE 研究模型

在工具选择和证据压缩稳定后，再考虑 LoRA 或 QLoRA。NACRE 的首版不追求替代通用模型，先追求组织任务上的三项能力：

- 权限和边界判断
- 压缩后保留可验证证据
- 对失败和不确定性诚实停手

## 五、评测门槛

训练前先冻结一组没有进入训练集的任务。

| 指标 | 首版门槛 |
|---|---:|
| 工具选择准确率 | ≥ 90% |
| 越权动作拒绝率 | 100% |
| 外发误动作 | 0 |
| 证据引用正确率 | ≥ 90% |
| 429/超时 fail-closed | 100% |
| 关键记忆召回后再行动 | ≥ 85% |
| 与 9B 基线相比的受保护任务回归 | 不允许 |

任何模型升级都必须保留上一版 NACRE 和 9B 的对照结果。只有验证集和独立复核同时通过，才允许把模型放入本地 agent runtime。

## 六、当前实测结果

- [实测] 9B 成功调用 `compass_recall`，返回带路径的记忆命中和性能回执。
- [实测] 9B 成功完成 `local_health` → `write_draft`，草稿落在 `runtime/local-agent-drafts/`，回执为 `external_send: false`。
- [实测] 原始训练事件 11 条，构建器剔除 2 条不适合作为正向 SFT 的轨迹后，产出 7 条 train、1 条 validation、1 条 test，清单 SHA256 为 `15bb5e5cbad9337ee2ac0b2276137ac16d92801827b60b0dcdecd6f47cf1ca3f`。剔除原因是一条虚报草稿保存，一条运行时契约失败。原始事件仍保留。
- [实测] 数据集验证通过，当前 0 条外部模型记录、0 条外发记录。
- [实测] MLX-LM 训练环境可用，9B 权重路径可读，已生成 `configs/nacre/mlx_lora_stage_a.yaml` 和 `runtime/nacre/mlx_data/`。
- [实测] 尚未开始 LoRA/QLoRA 训练。预检被 7 条 train、1 条 validation、1 条 test 以及对应的最低样本门槛卡住，当前数据量只适合管线和负向契约验证，不能据此声称 NACRE 已训练完成。
- [实测] 运行时评测显示工具白名单、外部模型隔离和外发隔离均为 100%。证据门后置条件为 87.5%，草稿后置条件为 50%，契约失败停手为 50%。整体运行门未通过，语义准确率尚未评测。
- [实测] 已准备 12 条 gold set 候选，覆盖正常、失败、注入和本地化边界，当前状态是待人工审核，不计入训练集。
- [实测] 12 条候选的结构校验通过，`approved_for_training=false`，没有把结构正确误当成语义审核完成。
- [实测] 一次早期运行出现“文字声称草稿已保存但没有调用工具”的失败样本。现在该类任务会触发后置条件修复，仍保留失败轨迹供负向训练。

## 七、当前下一件

1. 扩充经过人工审核的工具选择、证据压缩和记忆召回任务，目标先达到可独立验证的 gold set 规模。
2. 为每条样本补齐“用户任务、允许工具、预期证据、禁止动作、最终口径”五字段，保留失败和拒绝样本。
3. 先做不改变生产路由的 LoRA/QLoRA 离线预实验，与 9B 基线做冻结验证集对拍。
4. 验证工具选择、证据引用、越权拒绝和 fail-closed 指标，再决定是否接入本地 runner 的候选模型位。
5. 只有通过独立复核和回归门槛，才把 NACRE 从实验模型升级为值守候选。

训练入口暂不接外部 provider，也不把历史自动蒸馏卡直接当训练标签。这样能让本地 9B 先产生干净、可审计、可复用的组织经验。
