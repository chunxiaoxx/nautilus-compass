## 〇 · 为什么之前的 loop 不 work(根因诊断)

| 根因 | 症状 | 本系统对策 |
|---|---|---|
| G1 状态无单一真值 | 各框各说各话,轮值报告互相矛盾 | 机制 1:LOOP_STATE 账本(git 单源) |
| G2 函件无闭环 | 「为何发函回函又不发挥作用」——ack≠做了,做了≠验收 | 机制 2:函件三段协议(trace+判据+验收态) |
| G3 角色无矩阵 | 同一件事两框都做或都没做;用户当人肉路由 | 机制 3:五框分工矩阵+任务认领 |
| G4 轮值脱离真值 | 漂亮报告,零中心环贡献(剧场) | 机制 4:M1 锚定+黄红牌硬停 |
| G5 用户被信息淹没 | 待办散在五框消息里,用户疲劳 | 机制 5:用户决策面板(每轮聚合顶部) |
| G6 节奏无分层 | 每轮都是浅同步,深问题没人管 | 机制 6:三层节拍(小时轮/深同步/周复盘) |

## 一 · 机制 1:LOOP_STATE 账本(单一真值)

- 位置:`docs/plans/LOOP_STATE.md`(assay 主仓,每轮 commit,git 历史=审计线)
- 结构:任务表(owner/判据/deadline/状态)+轮次日志(每轮 4 行)
- 各框同步方式:每轮开头 `git pull` 读账本;不能拉仓的框(flywheel/日报)
  由平台信箱轮次摘要函代理通知(摘要函=只读投影,真值在 git)
- 铁律:状态只许在本档改;聊天里的状态=草稿,不入账不算数

## 二 · 机制 2:函件三段协议(闭环)

每封跨框函=三段,缺一不算合规函:
1. **trace**:承前 id 链(回函必引原函 id)
2. **判据**:收函方做什么算完(可复算/可验收,不是"尽快")
3. **deadline**:时刻(无 deadline=默认 24h)

闭环状态机:`发函 → 对方 ack(计划+判据确认)→ 交付回函(判据证据)
→ 发函方验收(✅/❌)→ 关闭`。**ack ≠ 完成**。
每轮检查两列:我发出的函未验收列 / 我收到的函未关闭列——空列才准开新活。

## 三 · 机制 3:五框分工矩阵

| 框 | 组织角色 | 本 loop 期主责 |
|---|---|---|
| platform | 运营/门户/对账/发令 | 门户 T1→动工、经营日报钱箱节、跨框追办 |
| compass+assay | 验证产品/研究/基建 | BC1(9/27)、jev-trust 线、DCR 上墙技术侧、复算纪律 |
| v5 | 判定执行/RSI 长程 | RSI 三跳落地、密钥分发设计(#801)、W41 复测 |
| flywheel | 具身数据/燃料 | 数据域校准会话(域 3 延伸)、两函复算 |
| 日报 | 传播/中文圈 | D2 系列、BC1 发布中文稿、案例文 |

认领规则:任务进账本必须带 owner(单 owner,协作时主/辅);无主任务
=谁发现谁挂到 platform 追办,不默认自领。

## 四 · 机制 4:M1 锚定(反剧场硬门)

- 组织唯一计数器:**M1=首个外部复算/付费请求**
- 每轮收轮自问:「本轮 diff 对 M1 有直接/间接贡献吗?」在轮次日志记
  `M1:+1(直接)/ +0(基建)/ -1(无关新坑)`
- **连续 2 轮 +0/-1 = 黄牌**(下轮只准做 +1 项);**连续 3 轮 = 红牌**
  (全框停下,loop 降级为每日一次轻同步,等用户重设方向)

## 五 · 机制 5:用户决策面板(每轮报告顶部固定格式)

```
【等你拍板/操作】(N 项)
1. …(选项:…)
2. …(阻塞:…)
```
用户唯一角色=决策+解锁;loop 保证用户一次回复能批多项。
零待办时显示「无阻塞,下一里程碑 X 在 Y 日」。

## 六 · 机制 6:三层节拍

| 层 | 频率 | 内容 |
|---|---|---|
| 工作轮 | 用户消息驱动(或自轮 ≤60min) | 七步协议(下节),推进任务清单 |
| 深同步轮 | 每 5 轮或跨框依赖冲突时 | 全量对账:账本 vs 各框自述 vs 平台信箱三方核对;差异入 P 表 |
| 周复盘轮 | 每周日 | M1 仪表盘(曝光/询盘/付费漏斗)+黄红牌清账+下周任务重排;10/26 硬评审并入本层 |

## 七 · 轮值七步协议(每轮固定步序)

1. **账本**:git pull 读 LOOP_STATE;无冲突进 2,有冲突=本轮就是深同步轮
2. **信箱**:check 未读→逐封按三段协议处理(ack 带判据确认)
3. **两列检查**:我发未验收列/我收未关闭列,清完才开新活
4. **推进**:账本最高优先未完项(owner=我)——BC1 期即 L1-L3
5. **防跑偏**:compass drift_check;方向锚自检(具身数据+验证平台);
   任务跨轮描述一致性(防口径漂移)
6. **收轮**:轮次日志 4 行(进展/阻塞/对 M1 贡献/下轮第一件)+commit
7. **投影**:平台信箱发轮次摘要函(3 行版),供不能拉仓的框同步

## 八 · 与现有机制接线

- **compass 记忆**:每轮日志同时写 memory 一行(跨会话恢复点)
- **GOAL_SSOT/LOOP_STATE_SSOT(旧)**:已冻结不复活,新账本=本档机制 1
- **报数纪律**:BC1/任何对外数字照旧(预注册+非实现者复算),loop 不豁免
- **drift_check**:步 5 必跑;score 异常即停轮报告用户
