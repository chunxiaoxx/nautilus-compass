# 机制转向 · 从穆迪模式到 Let's Encrypt 模式(2026-09-19 · 用户拍板方向)

> 用户裁决:"真正把仲裁、AI 产出物真实性可溯源性低成本高效率解决,像区块链共识那样,
> 做无法拒绝的机制和产品。"——P0 销售包(私信/登门/示范复算)保留但不主位,
> **主位=机制产品**。

## 一 · 为什么销售式注定徒劳(承认)

三封信 0 回、博文 0 阅——不是执行不力,是模式错了:**B2B 审计每一单都要说服**,
而区块链从没说服过任何人。中本聪没有给十个人发私信。区别在:

| | 穆迪模式(我做的) | 机制模式(要做的) |
|---|---|---|
| 验证发生时 | 事后,需被测方主动提交 | **生产时,自动** |
| 谁付费 | 被测方(说服成本高) | 无人(公共品,成本趋零) |
| 不参与的后果 | 没有回执而已 | **数字显示为"自报/未验证"——默认态反转** |
| 历史同构 | 穆迪/四大会计师 | **Let's Encrypt/HTTPS/git** |

## 二 · 机制解三支柱(区块链结构的正确移植)

### 支柱一 · 产出即打包(attest-at-generation)
比特币交易签名是钱包**自动**做的,用户无感。对应物:**assay-sdk**——任何 agent
框架跑评测/产出声明时,一个函数调用自动产出 VerifyPack 格式证据包+签名。
生产者不需要理解协议(就像 git 用户不需要懂 merkle 树,commit 天生带哈希)。
**对框架是纯增益**:自动保存评测产物+自动生成可发布成绩页+免费第三方签名——
像 coverage 工具一样会被集成,这就是"先加入者先赚"的机制化。

### 支柱二 · 验证即消费前提(verify-on-consume)
比特币节点自动验证每笔收到的交易,不通过就拒收。对应物:**compass 记忆层是
A2H2A 的咽喉**——agent 消费信息必经记忆层。把验签+可复算性标记做进 ingest 的
默认步骤:带 receipt 的记忆自动验签打标 `verified`;不带的标 `self-reported`。
**这个结构位置只有我们有**(竞品记忆层没有判据库和验签器)。MCP 工具
`assay_verify` 同理:任何 MCP 客户端装了 compass 就能对任何产物验签——验证
能力经 MCP 分发,像 DNS 解析一样无感。

### 支柱三 · 激励内生(HTTPS 式默认态反转)
Let's Encrypt 没有说服任何网站买证书——它把证书成本降到零,然后**浏览器把
无 HTTPS 标记为"不安全"**,默认态反转,不参与的人开始需要解释。我们的对应:
SDK 免费+自动化(验证成本→零)→墙/记忆层/榜单把无回执数字标 self-reported/
UNVERIFIABLE(不验证的状态变得刺眼)→**不验证成为需要解释的选择**。
诚实者抢先(数字经得起复算的框架先获得 verified 标),不诚实者被默认标记——
激励自动分化,无需任何人执法。

## 三 · 与既有资产的对齐(不是推倒,是换主位)

- VerifyPack v0.2 = 证据包格式(已开源)= SDK 的内核
- verify_receipt.py 单文件零依赖 = SDK 验证函数(已存在,需包装分发)
- 判据库 14 条 = SDK 的"判断模板库"(随包分发,集成方开箱即用)
- 记忆层(compass 主产品)= 咽喉卡位(支柱二的宿主)
- 墙/考场 = 默认态标记的公开展示面(维持,但不再是销售面)
- 三张签名成绩单 = SDK 的演示用例(创世十家复算的产出物改用 SDK 生成,
  **SDK 即演示,演示即 SDK**)
- 穆迪 SKU($99-299)= 过渡现金流,保留但不主位

## 四 · 工程排期(机制产品线 P0 重定义)

1. **assay-sdk(pip 包,3 天)**:`pip install assay-verify`;
   - `attest(claims, artifacts_dir) → pack+sig`(生产端,一行)
   - `verify(target, sig, pubkey) → 三态`(消费端,一行,verify_receipt.py 包装)
   - 判据模板随包分发;README 三行代码接入
2. **记忆层内置验签(1 天)**:ingest_obs 写入时,若带 receipt 字段→自动验签
   →fact_status 打 `verified`;否则 `self-reported`。查询端透出标记。
3. **MCP 工具 assay_verify(半天)**:已列在 Registry server.json 的工具表补真身
4. **创世演示改造**:Aider 复算改用 SDK 流水产出,回执=SDK 的第一个第三方用例
5. 暖私信文案更新:卖的不是"我们的审计服务",是"三行代码让你的数字自动可信"
