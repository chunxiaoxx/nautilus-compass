# compass 架构审计 · 七算子框架与三修复方案

> 2026-09-07。审计来源：nautilusflywheel 仓《四系统底层算子对照·第一性原理分析》（SSI/Waddle/ICL/compass 四系统按七原子算子拆解），本文把该框架反过来对 compass 自身过秤。
> 审计判据先行：compass 最强算子是"选"（多层门控），最弱是"组合"与"合并"——弱的原因不是没引擎（Claude 即引擎），是**没触发器**。

## 1. 七算子审计表

| 算子 | 现状 | 缺口 |
|---|---|---|
| 写 | ●多路写入（session 提炼/feedback_log/hook 沉淀） | **无写入 gate**：错误记忆先入库、使用时才发现；"用前须验证"原则是缺前置门禁的代偿 |
| 读 | ◐BGE 召回 | **读写介质异构**：markdown 结构（frontmatter/链接/表格）在嵌入里被压平；top-k 固定与任务复杂度无关 |
| 选 | ●最强（时间戳+drift+锚点档案） | 门只挡"旧"不挡"错"：硬事实随时间被降权不合理；drift 测人格不测事实正误；无置信度分层 |
| 合并 | ◐session 结束提炼 | **无触发器**：同主题第 N 次出现不自动触发合并；单 SSOT 靠人工纪律非机制 |
| 忘 | ◐删文件/时间戳降权 | 无衰减：被验证 10 次的配方与零引用条目同权；MEMORY.md 全量索引无淘汰队列 |
| 组合 | ○最缺 | [[链接]]是装饰不是机制（召回不沿链走）；多记忆不能拼装为可执行清单 |
| 评估 | ◐drift_check+复核回执 | 讽刺缺口：给客户数据出效用报告，记忆系统自身零读数（召回率/采纳率/死记忆占比） |

## 2. 三修复方案（按杠杆排序）

### 修复一：fact_status 写入 gate（评估前移，最轻）

- 变更：memory frontmatter 增加字段 `fact_status: measured | inferred | heard`（实测过/推断/传闻）+可选 `verified_at`（上次实测日期）
- 纪律：写入方（Claude/用户）落条目时必填；recall 注入时随条目带出——高 stakes 决策（部署/对外/杀进程）只采信 measured 级
- 实施位置：记忆写入模板（全局 CLAUDE.md 记忆节+memory 文件约定）；daemon 侧注入格式（涉及 recall 输出模板，实施前先读 recall.py 确认注入拼装点）
- 验证：抽样 10 条新记忆检查字段存在+一次 high-stakes 提问只命中 measured

### 修复二：写入查重触发合并（给合并装触发器）

- 机制：新 memory 写入前先 BGE 查重（对既有条目集），cosine ≥0.9 命中→进入合并流程（升级覆盖原条目，保持单 SSOT）而非新建；0.75-0.9 灰区→提示人工裁决并回填 [[链接]]
- 实施位置：session_writer/记忆写入路径前置钩子（实施前核对 session_writer.py 与 daemon 的写入入口；仓内已有 cycle_consolidator.py/ssot_consistency.py，先读其既有职责避免重复造轮子——本仓反复教训）
- 验证：故意写一条与既有条目高度相似的记忆，确认走合并而非新增；MEMORY.md 索引行数不增

### 修复三：召回沿链一跳（组合的最小修复）

- 机制：recall 结果中每条 memory 的 [[name]] 引用自动展开一层（不递归，控制注入预算），把链接从装饰变机制；展开的二级条目降权标注"沿链展开"
- 实施位置：recall.py 召回后处理（实施前读 recall.py 的结果组装段与 token 预算逻辑）
- 验证：构造 A 链接 B 的两条记忆，查询命中 A 时 B 以沿链标注出现在结果里；无链查询不膨胀

## 3. 理论定位（与分层记忆计算机图景的接口）

三修复分别对应记忆计算机 MMU 的三种职责：修复一=磁盘层写入 gate（防污染写入）；修复二=内存层 compaction（碎片整理）；修复三=内存层内寻址（间接寻址一跳）。全部实施后，compass 的七算子短板从"组合/合并缺触发器"收敛为"评估读数缺自动化"——后者是下一阶段（记忆效用报告）的活。

## 4. 边界

- 本文为审计与方案，非已实施；三修复均需先读涉及源文件再动手（本文件未附源码核对，引用文件名为候选位置）
- 修复优先于新特性开发的原则下排序：一（纯纪律）→ 二（触发器）→ 三（召回改动）；单次改动独立 commit 可回滚
