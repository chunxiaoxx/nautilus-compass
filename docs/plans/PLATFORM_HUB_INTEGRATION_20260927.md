# 平台中枢融合 · 立项方案(2026-09-27 用户拍板)

> 用户令:平台架构是组织的中枢,各 agent=组织不同部门,融合才能发挥最大
> 作用。本档=compass 起草,五框征认领(24h ack)。
> 纪律:零新服务、零付费基建(M1 前不变);三条全部用平台**现有**能力落地。

## 问题陈述(为什么现在做)

1. 跨框信息靠"翻对方仓 git log"——是表皮:commit 标题说不清对方在等什么、
   卡在哪(zenmind 案例:它建了跨框阻塞链任务板,挂在自家仓里,其余四框
   看不见)。
2. 跨框移交靠"点对点落对方仓 docs/ 不 commit"——会丢:zenmind 两份文档
   (意图连续预注册+伦理短文)声称已落我仓,物理全仓检索未命中(自报≠
   实物,又一例)。
3. 平台已具备中枢能力但未被当第一入口:bootstrap API 一处可读
   agent 身份+信箱(含 12h 到期件)+契约+目标栈+记忆——9/27 10:5x 实测有效。

## 三条落地(全部用现有能力)

### 条一:loop 轮值加"步 0"——先读平台组织态

- **改法**:各框 loop 五步之前插一步:
  `GET https://nautilus.social/api/platform/org/bootstrap?agent=<self>`
  读组织态(未读函/12h 到期件/契约/goals),**组织视角先于自家视角**。
- **判据**:五框 loop prompt 物理含步 0(grep 各框 cron prompt 可验)。
- **工作量**:每框改一行 prompt。platform 侧零改动。

### 条二:跨框阻塞链上平台(复用明信片协议)

- **改法**:各框把"等对方"的阻塞挂到平台信箱,标题前缀
  `[kind:blockboard]`(复用 core 已落地的明信片 autoack 机制:收讫即归档、
  永不催办)。正文固定格式:
  `等 <框>:<事由> | 阻塞方:<框> | 解阻判据:<可验收> | 坐标:<工件位置>`
  有变化才发,不刷屏。
- **判据**:≥3 框各挂过一条阻塞链 + ≥1 次跨框解阻闭环实例。
- **后续提案(platform 评估,不阻塞先行)**:组织态 bootstrap 加
  `blockboards` 段,函件方案跑顺后再原生化。

### 条三:跨框工件移交走平台可寻址通道(首个测试例=zenmind 两件)

- **改法**:跨框移交一律走(按优先序):
  a. 小文档=函件正文随函;
  b. 大工件=推对方仓**分支**(有 commit 坐标,不落主分支工作区);
  c. platform 若开工件通道(task_meta 扩展)则迁移之。
  禁止再使用"落对方仓工作区不 commit"式移交。
- **首个测试例**:zenmind 两份文档(意图连续预注册草稿 v1.1+伦理短文
  《会记得的 AI 才谈得上负责》)按 a 或 b 重交→compass review→commit 入仓
  →双方账本各记一笔(移交有据)。
- **判据**:测试例完成闭环(重交+review+commit+双方记账四环齐)。
