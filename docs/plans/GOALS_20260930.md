## 五、loop 机制(20 分钟档 · v3 · 梳理驱动)

> v3 修正(用户批"无效 loop"):连续 16 轮安静空转=任务清单没有真正驱动行为。
> v3 核心改动:**每轮必须产出**——梳理是动词不是读一遍;安静轮≠不作为。

每轮六步:
0. **步 0 组织态**:curl bootstrap——信箱未读 ack/回函+bounty 六单+到期件
1. **梳理正档**(强制更新):
   - 任务表逐行盘状态:✅/🔄/🔴/新增/删减——状态没变化就是没梳理
   - 有完成→标✅+commit;有新增→入表;有卡住→标🔴+归因
   - 三层北极星读数(M1/V2/V1):有变化就记
2. **值守**(五框探查=每轮必做,不是可选):
   - 信箱/Discord 9224/gh issue
   - **五框 git log 快探**——涉我域的 commit 当轮处理
3. **执行队列**(每轮至少完成一件,做完才 commit):
   当前可做队列(按优先排):
   - F15 meta-judge 手工抽样(5%×三供应商,可开始)
   - Trust Report #2(TypeSafe 复算四轮+两簇,可编)
   - G4 中文圈层(伦理短文《会记得的 AI 才谈得上负责》可发)
   - 基线扩充(Zep/Letta/调参版≥3 家上墙)
   - D3 触达批次(外联手册第四节)
   - Jev 判定外置首例(裁判域高频三态→Jev API,可开始)
   - assay 靶向题(考试执行)
   - 新增:五框域细化跟进/权重自进化 flywheel 表态追/PMF 双验证
4. **体系动作**(每轮至少一个):
   - compass:三门判分/记忆写入/考官面 SLA 计时
   - assay:计量单/复算/考场
   - jev:至少一个判定走 Jev API(jev-trust/直接 API)
   - 三者任选一,但**必须有代码或工件产出**,不是口头提
5. **记账**:每轮 commit(有实质变化才 LOOP_STATE;任务表状态更新=实质变化)

纪律:
- 安静轮≠零产出:任务梳理+体系动作也产出
- 红灯先证伪自己;跨框先物理探查;发布类默认执行
- 20 分钟内做不完的拆到下轮,但本轮件必须做完至少一件
- 反剧场判据:每轮 commit 有 diff(gates/报告/代码/文档状态更新)
