# 校准货币立项(融合四向②号 · 2026-09-22 用户拍板)

> 命题来源:Compass×Assay×Jev 融合第②号(反常识:信任不是评分,是汇率)。
> 承 LE 收敛(90 天续期↔持续适航=同一结构)、DCR 月度重测(+40%)、
> VerifyPack v0.3 TTL。**本档定义信任的计价单位、汇率牌形态与市场化路径。**

## 一 · 核心命题

**信任不是静态徽章,是浮动汇率。** 一个 agent 在某个域的可信度,不是「已验证/
未验证」的二元,是一个随时间衰减、随表现浮动、可查可算的连续量。

```
校准货币(calibration credit)的定义:

  C(agent, domain, t) = 1 - ECE_t(agent, domain)

  其中 ECE_t = 最近一次独立复算的 ECE(带 TTL;过期=UNVERIFIABLE=C→0)
```

性质:
- **衰减性**:C 随时间单调下降(TTL 到期归零),除非续验
- **域特异性**:同一 agent 在不同域 C 不同(这是 DCR 的本质)
- **可计算性**:C 从公开工件可复算(不是我们说了算)
- **不对称性**:C 上升慢(需要验证),下降快(一次 challenge 失败→§5b track
  record 清零=硬着陆)

## 三 · 计价场景(商业闭环)

**场景 1:agent 采购的汇率牌**(买方 SKU 增强)
企业采购 agent 服务时看 C 值:「此 agent 在代码修复域 C=0.87(3 天前更新)」
vs「此 agent C=UNVERIFIED」——**数字一样,汇率不同,采购价差合理化**。
DCR $99-499 就是「查汇率」的报告费。

**场景 2:管线内的信任路由**(SKU-B 验收嵌入)
agent 管线运行时,C<0.50 的域自动降级(人工复核/降速/拒答);C≥0.80 的域
自动通过。**校准货币即风控参数**——不需要人工判断「信不信」,查牌即可。

**场景 3:多 agent 协作的清结算**
Agent A 请求 Agent B 完成任务:B 的 C=0.72 → A 给 B 的任务加 28% 人工抽检率。
多 agent 生态的信任摩擦从「互相不信任→全检」变成「查汇率→按 C 值定价」。

**场景 4:挑战与贬值**(§5b 的货币化)
challenge 成功→C 硬着陆到 0(做市方清算)+挑战者获赔偿。**这是唯一的
通缩机制**——没有牙齿的货币会通胀(所有人都声称自己 100%)。

## 六 · 红线

1. **C 值不可自报**——只有做市方(独立验证者)可发布;agent 自报 C=无效
2. **C 值不是「好坏」**——是「经过独立复算的可信度快照」;UNVERIFIED 不是
   差评,是「还没验」
3. **自家产品同尺照登**——NautilusMem C=UNVERIFIED 在牌上,直到我们自己付钱
   请 L-2 验证者验(或明示 self-audited)
4. **不代币化**——C 是度量不是加密货币;「货币」是比喻(汇率/贬值/清算),
   不是 ICO
