## 0. 核心理论(一句话)

**记忆的价值在检索时兑现,不在写入时下注。**
智能应该出现在"信息完整 + 意图已知"的时刻(读取时),
而不是"信息完整 + 意图未知"的时刻(写入时)。

### 写时压缩必输的三个不变量

1. **未来查询分布不可知** —— 重要性只在被问到的时刻显影。
   实证:同一份记忆,utterance 分型路由按题型选检索粒度,P@1 0.20→1.00
   (单会话用户型,held-out runs)——检索什么粒度取决于被问什么,写入时无人知道。
2. **原文是唯一可重新索引的表示** —— 提炼物被冻结在当初那个 LLM 的认知水平;
   无损原文明天可换更好嵌入/更好读法/可作训练燃料(数据飞轮)。
   写时压缩不只丢信息,它把记忆锁死在技术现状里。
3. **成本曲线方向反了** —— 存储趋零、LLM 调用恒贵;把便宜的(原文)换成昂贵的
   (提炼物)是逆成本曲线。写入免费 + 读侧 p95 0.34-0.80s(对照 LLM controller
   26.9s,~80×)是把智能放在正确时刻的自然结果,不是优化奇迹。

### 第三方背书(ICLR 2025 基准论文,arXiv 2410.10813)

- §5.2:用 LLM 提炼的摘要/facts 替代原文 → 因信息丢失损害 QA
- Appendix B 人肉研究:ChatGPT 随对话压缩历史时覆写关键信息;Coze 漏记间接提及
- 长上下文直读 LongMemEval-S 掉 30-60%(裸读是死路,记忆层必要性由基准作者论证)

## 1. 六层架构总图

```
┌─ 进化层 📊  记忆胶囊 GEP:W1 验证写回 → W2 继承召回 → tier 晋升/PoI/report 回流/可逆衰减
│            (compass_fleet_memory.py · docs/plans/2026-06-21-memory-capsule-evolution-design.md)
├─ 治理层 ✅  drift 检测(AUC 0.83 p95<50ms)· 跨 agent 合约审计 · scoped token 三层隔离
│            · 判分卫生学(PROTOCOL.md · 5 次 judge 事故全录)· merkle 链/数字声明验证
├─ 组装层 ✅  摘要卡按题型路由(ms/ssa/tr)· 日期时间线排序 · utterance 窗口组装
├─ 召回层 ✅  六型分型路由 → BM25+dense RRF 融合 · 日期锚定 · 分型粒度选择(turn/session/摘要卡)
├─ 存储层 ✅  原文 verbatim 存储(md+frontmatter)· 本地 BGE-m3 嵌入 · 日期元数据 · 零 LLM 零上云
└─ 格式层 ✅  OKF(Google 开放知识格式)天然兼容:任何 OKF 工具可读我们的记忆 bundle
```

数据流:

```
写入:对话/文档 → verbatim 存储 → 本地嵌入+日期元数据 → 索引(零 LLM,免费,无损)
读取:问题 → 分型路由(6 型)→ 混合检索(分型粒度)→ 组装层(摘要卡/时间线)→ reader LLM → 答案
进化:解题 reward≥1.0 → W1 写回胶囊 → 他 agent W2 召回继承 → report 回流 → 质量晋升
```

## 2. 写入端(反传统的核心)

| 决策 | 内容 | 理由 |
|---|---|---|
| 存什么 | **原文 verbatim**(md+frontmatter+`[[链接]]`) | 不变量 2:唯一可重新索引的表示 |
| 怎么索引 | 本地 BGE-m3 嵌入 + BM25 词面 + 日期元数据 | 双路互补:词面扛精确标识符,日期扛时序 |
| 不做什么 | **写入时零 LLM**:不提炼 facts、不建图谱、不生成摘要、不上云 | 不变量 1+3:意图未知时不做有损决策;写入免费 |
| 质量门 | 胶囊写回需 `MIN_WRITE_REWARD=1.0`(验证过的经验才入库) | 防退化:错经验不入库,不被跨 agent 复利成毒 |

## 3. 读取侧(智能集中地)

1. **六型分型路由** — 问题先分类(ssu/ssp/ssa/ms/ku/tr),每型不同检索单元:
   用户陈述型问题检 turn 级块(滑动窗 2),跨会话型路由到摘要卡。
   单型实测:ssu P@1 0.20→1.00;ssa 0.250→0.839;tr 0.158→0.624(A 臂重判口径)。
2. **混合检索** — BM25 + dense(bge-m3)RRF 融合(k=60);dense 单路掉时序/多会话查询。
3. **日期锚定** — session 日期前缀注入 chunk 文本,before/after 类查询有时序把手。
4. **组装层(摘要卡)** — 跨会话题型路由到逐会话摘要卡+日期时间线:
   e2e 500 题 42.6%→75.4%(81.6% 剔除断连口径),三弱型 2 倍超预注册门;
   零检索改动、零模型训练,纯 context 工程 +32.8pt。
5. **实测证伪过的读侧选项**(同样公开):cross-encoder rerank 有害(-2pt)、
   K=50 无深度收益、小嵌入模型无效——排序质量是主因,复杂度不做加法做减法。

## 4. 治理层 = 组织记忆的可信度(独有件)

- **drift 检测**:动作前对照失败模式锚点,AUC 0.83,p95<50ms
- **跨 agent 合约审计**:多 agent 共享文件时追踪隐式义务
- **多租户隔离**:scoped token(user/设备/agent 三层),四探针公网验证,撤销即时
- **判分卫生学**:预注册锚/judge 函数调用级冒烟/双口径强制披露/Wilson CI/重判工具随栈
  ——我们抓了自己判官 5 次事故(401/断连/预算被 reasoning 吃满等),全部是配置层,
  断连曾把 14.2% 题记成错题(5.4pt 失真)。测量可信度先于分数。

## 7. 为何业界普遍做反了(长文灵魂章素材)

1. **路径依赖**:记忆系统从对话摘要演化而来,写时提炼"顺手"——没人把记忆当存储问题而非理解问题
2. **商业激励错位**:写时 LLM = 按 token 收租的理由 + "智能记忆管理"叙事;简单架构没故事——不是想不到,是不愿意
3. **评测盲区**:没有严格基准就量不出压缩丢了什么;上游 2024 年才造出尺子(LME),我们是第一波量出写侧路线败绩的
4. **直觉错觉**:LLM 时代直觉是"聪明模型处理一切";反直觉认知是聪明模型应在最需要的时刻出现一次
5. **出身红利**:自用 dogfood,隐私/本地/成本是硬约束——约束逼出正确架构,一人开发者从劣势变方法论优势
