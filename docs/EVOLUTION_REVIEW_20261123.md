## 四、NACRE 定性(供拍板,[子研] 为主)

**它是什么**:10/6 定名的组织创新模型代号。三版定义并存——

| 版本 | 定义 |
|---|---|
| 10/6 白皮书 v1.0 | 判分原生判分模型:agent 产出工件 → PASS/FAIL/UNVERIFIABLE 三态+证据分层;判例/勘误 → 增量 LoRA → REG-100 零翻转门 |
| 10/6 夜 v1.5 | 压缩×验证×因果倒置 + 原生动态权重/RSI/记忆/JEV/专家技能(目标态原生,现状多为系统级编排) |
| 11/20 本地模型计划 | 本地 agent 执行器训练路线:本地 9B 先当值守执行器,用验证过的轨迹训 NACRE,四阶段 |

**走过的路**:9/26–30 判官 LoRA 88.51%(官方真值集,现役)→ 10/7 E-NACRE-1 域路由 −36.6pp → 10/13 8B 触发 +1.0pp 不到门、1.7B-v2 −2.0pp → 10/14 强模型重判 65% 不过 → 10/19 自举线定谳无效,燃料路径 A(冻结等外部题)/B(小而净 8B 对照)候拍 → **至今无裁决记录**。

**11/15 之后做了什么**:11/19–20 在 Token Plan 断供期搭了本地 9B 降级值守 loop 和 NACRE 本地训练管线(规格 2 份、脚本 8 个、LoRA 配置、运行数据)。跑了 114 轮,训练未启动——数量门 32/8/8(需 ≥48 条)而数据集停在 20 条;14 条金标候选未批;语义准确率未评。**该 loop 即 11/22 审计席按用户授权换回全能力版的那一个,轨迹源随之停止**(原始事件已有 117 条)。

**必须由你裁的四件事**:
- **N1 定义对账**:三版并存,后一版未引用前一版,未说明与 E-NACRE-1 的关系;中文名"溯衡"10/6 被你否过,11/20 规格又用上了。
- **N2 边界**:新路线的训练目标是"9B 自己写的总结",源是值守轮自己的运行事件。10/19 定谳是"自产工作记录自始不构成判例",主线文档写"模型不能给自己发教材"。11/20 规格用七条准入加独立金标划界,但**没有任何文档正面回答它是否触线**。
- **N3 去留**:燃料路径 A/B 自 10/19 候拍未决;数据源已停;若续,需恢复一个受控数据源并完成金标审批。
- **N4 保存**:上述工作在 Mac 上全部是未跟踪文件,origin 上没有。

## 五、进化方向(建议,[建议] 非结论)

把 §一 的 15 条需求与 §三 的 8 个缺口收敛成四条主线:

**E1 先用 assay 验自己,再验别人。** 判官金标自检(对已知样本对照,全同向即报警——本评审刚给机审器装了一条,应做成 assay 的通用件)· 探针有效性分级(故障注入验"能不能报红")· 处方→执行→回执闭环台账 · 公开墙入库字节验签进 CI 门("新克隆一命令验证"从口号变成每次提交都被测的断言)。消化 G2、G4、G5 与 C1、C2、C5、C9。

**E2 记忆层从"存得多"转向"信得过"。** 清理 1196 张噪声卡 · fact_status 从贴标签改为拦截 · 召回候选纯度指标进巡检 · 记忆使用可追溯(召回了什么、agent 有没有照做)——重犯率才量得出来,也才配得上"Verified Memory"这个写在一页纸上的产品。消化 G3。

**E3 进化环换燃料来源。** 自举线已证伪,剩下的只有三类外部真值:外部评测题(hindsight 评测已有先例:40.8% vs 56.6%)· 真实外部委托(判读免费,换判例)· NACRE 本地执行器线(前提是 N2 裁定不触线并以独立金标为门)。消化 G1、G6。

**E4 对外的最小可信面。** 重签 3 张坏签 · README/HF 卡与勘误对齐并补适用域 · 修 502 · 提交部署鉴权修复 · 发版 · 然后才谈专稿。消化 G2、G7。
